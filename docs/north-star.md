# north star — mnemora が目指しているもの

**この文書は正典である。**
**正典と実装が食い違ったら、バグなのは実装のほうである。**
実装の都合でこの文書を書き換えないこと。方向そのものを変えるときだけ、書き換える。

---

## 目的

**mnemora は、LLM アプリケーションに「思い出す」を与えようとしている。「保存する」ではなく。**

保存はすでに解けている。解けていないのは、**大量に貯めたものの中から、いま必要な分だけを引き当てること**である。

> **「大量の会話ログを LLM へ毎回全部渡す」ことではありません。**
> **必要な記憶だけを、意味、構造、時間、重要度、利用頻度、関連性から思い出せること**です。
> そしてその記憶から新しい知識を統合し、**使われない記憶は自然に想起されにくくなり、
> 必要な場合だけ過去の記憶を再び呼び戻せる。**
>
> — オーナーの仕様 §48「最重要要件」（逐語）

---

## 目指す姿

**機能の名前ではなく、外から見てどう現れるかで書く。**

- **言ったことを、次の日も覚えている。**
- **使う側が有効にすれば、聞かれていないことを、自分から思い出す。**——有効にするのは使う側だが、何を思い出すかは mnemora が決める。
- **なぜそれを思い出したのかを、後から説明できる。**
- **使われない記憶が、静かに遠ざかる。**——消えるのではなく、遠ざかる。
- **間違いを正すと、古いほうが先に出てこなくなる。**
- **知らないことを、知らないと言える。**——「見つからなかった」と「探していない」を、同じ顔で返さない。
- **どれだけ載せるかを、使う側が決められる。**

この一覧に「永続化」「ベクトル検索」「バックグラウンド処理」といった語が無いのは、意図的である。
**それらは手段であって、目指す姿ではない。**手段は差し替わる。

---

## 物差し

**近づいたかどうかは、これ一つで測る。**

> **使う側が、会話ログを全部プロンプトへ積むのをやめられたか。**

**記憶の件数でも、機能の数でも、recall の平均スコアでもない。**
mnemora を入れたのに呼び出し側が結局「全部渡す」を続けているなら、
どれだけ機能が増えていても、目的には一歩も近づいていない。

## 迷ったときの問い

**上ほど強い。**上の問いと下の問いが衝突したら、上を採る。
**この問いは、実際に設計案を落とすためにある。**どの案も落とせない問いは、書き直すか捨てる。

### 1. これは、毎回渡す量を減らす方向に働くか。増やすなら、その分だけ想起が良くなると言えるか。
オーナーの仕様 §48 から。**目的は想起であって保管ではない。**
「念のため全部載せる」は、この問いで落ちる。

### 2. これを無効にしたとき、Memory Framework として成立するか。
オーナーの設計原則 §42-6 から（逐語: *Background Cognition を無効にしても Memory Framework として成立する*）。
**「これが無いと動かない」を増やさない。**

### 3. この記憶が選ばれた理由を、後から説明できるか。
オーナーの仕様 §30 から。オーナーはこれを**第一級の機能**と書いている。
**説明できない賢さは採らない。**

### 4. AI の推論と、ユーザーが言った事実を、区別しているか。
オーナーの設計原則 §42-7 から（逐語: *AI の推論とユーザーが言った事実を区別する*）。
**混ぜた瞬間に、記憶は信用を失う。**

### 5. これは、LLM を呼ばずに済ませられないか。
オーナーの仕様 §34 から。
**列と索引で解けるものを、モデルに問わない。**

## この問いが、実際に案を落とすことの確認

**問いは、書いた時点では飾りと区別が付かない。**
だから、手元にあった設計判断に実際に当ててみた記録を残す。

| 問い | 実際に落ちた案 | 判定 |
|---|---|---|
| 1 | 「Observation の全文を毎回 recall に含める」「digest を持たず本文だけ保存する」 | **落とせた** |
| 2 | 「Scheduler / BullMQ を必須にする」「抽出を常に非同期にする」 | **落とせた**（`InlineScheduler` が既定になり、`extract: 'sync'` が残った） |
| 3 | 「Phase 1 に LLM reranker を入れる」「`omitted` をログにだけ出す」 | **落とせた** |
| 4 | 「consolidate したら元の Memory を捨てる」 | **落とせた**（統合物は `basis` を解決できなければならない） |
| 5 | 「矛盾を recall のたびに LLM に判定させる」「目次帯を LLM に要約させる」 | **落とせた**（`status` 列と集約クエリで解ける） |

**問い1については、最初の草案から書き直している。**
草案は「記憶を『思い出しやすく』するのか『保存しやすく』するのか」という形だった。
これを実際に当てたところ、**監査ログと provenance が落ちてしまった**——
どちらも単独では想起を良くしないが、両方とも必要なものである。
**落としすぎる問いは、落とせない問いと同じくらい役に立たない。**
そこで「毎回渡す量」を軸に置き直した。この形なら、
プロンプトに載らない監査ログは通り、「念のため全部載せる」は落ちる。

**問い3が over-fetch を落とさなかったことも記録しておく。**
落とさなかったが、**条件を付けた**——「取りこぼしの可能性を必ず結果に出す」。
**問いは案を落とすだけでなく、案の形を変えることもある。**
