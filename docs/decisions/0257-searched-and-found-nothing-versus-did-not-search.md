## 文脈

**[ADR 0223](./0223-cross-cutting-disciplines-extracted-from-the-adr-corpus.md) は、ADR 211本の母集合から「繰り返し採られているのに入口の文書に書かれていない規律」を10本抽出した。**その決定10 がこれである【現物・逐語】:

> **一般形**: **「無い」「見つからなかった」と書く前に、探した場所（コマンドと対象）を列挙する。** ⟹ **列挙できないなら「当たった範囲での結果であり、断定ではない」と書く。**

**⛔ そして ADR 0223 は、成文化の場所を自分では決めなかった**【現物・逐語、「⛔ 成文化の場所 —— **未決のまま残す**」節】:

> **どこへ置くかで読者が変わる。**`AGENTS.md` は人もエージェントも読む。`docs/autonomy.md` は「オーナーに逐一確認せずに進める担い手」向けだと自ら宣言している。

その未決を [Issue #505](https://github.com/takecchi/mnemora/issues/505) が引き取り、6つの決定（2/3/5/6/9/10）を1本ずつ判断することにした。**決定9 は [ADR 0234](./0234-bake-no-numbers-into-tools-and-artifacts.md)（[PR #520](https://github.com/takecchi/mnemora/pull/520)）、決定2 は [ADR 0250](./0250-machines-detect-humans-confirm-and-write.md)（[PR #553](https://github.com/takecchi/mnemora/pull/553)）が既に答えている。この ADR は、残る決定10 だけに答える。**

⚠ **【受】この ADR の判断そのものは、Issue #505 のコメントに先に置かれている**（逐語「## 5. 決定10 — ✅ **yes。⭐ ただし「向きが逆」であることを明記して書く**」、[issuecomment-5714613359](https://github.com/takecchi/mnemora/issues/505#issuecomment-5714613359)）。⛔ **そのコメントは「クローン miku（自動化された担い手）による判定である。オーナー本人の判定ではない」と自ら名乗っている**（同コメント冒頭「**クローン miku（自動化された担い手）による判定である。** ⛔ **オーナー本人の判定ではない。**」）。**この ADR が足すのは、その判断を記録の形にすることと、下の「測ったこと」で現物に自分で当て直した裏づけである。**

## ⭐ なぜ入口へ置くのか —— **向きが逆であることが、足す前提になる**

**【現物】入口に在るのは、この規律の向きが逆の版である。**

| 在る版 | 宛先 |
|---|---|
| [docs/north-star.md](../north-star.md)「目指す姿」——逐語「**知らないことを、知らないと言える。**——「見つからなかった」と「探していない」を、同じ顔で返さない。」 | **`mnemora`（製品）が使う側に対して満たすべき姿** |

🔴 **同じ規律を *書き手・担い手が自分の調査手続きに* 当て直した版は、入口のどこにも書かれていない**【実測、下記】。

⟹ ⭐⭐ **だから「正典に在るから足さなくてよい」ではない。** 製品の振る舞い（`mnemora` が呼び出し側に「見つからなかった」と「探していない」を区別して返す）と、書き手の手続き（担い手が ADR・issue・報告で「無かった」と書くときの手続き）は**別の宛先**である。**同じ言葉が別の宛先にも効くことを、明示的に書く必要がある。**

**この向きが逆であることの裏づけは、north-star が指す製品仕様がすでに実装側で使われている実例からも取れる**【現物】。[ADR 0089](./0089-runtime-consolidate-shape.md) は `ConsolidateOutcome` の `nothing_to_consolidate`（見た上で束ねるものが無かった）と `not_examined`（そもそも見ていない）を区別する理由として、north-star の同じ逐語をそのまま引いている——

> 🔴 **`nothing_to_consolidate` と `not_examined` を束ねない。**どちらも「何も起きなかった」だが、前者は「探して無かった」、後者は「そもそも探していない」であり、**`docs/north-star.md`「目指す姿」が名指しで区別を要求している**（「知らないことを、知らないと言える。——『見つからなかった』と『探していない』を、同じ顔で返さない。」）。

⟹ **この引用は製品の出力形（`ConsolidateOutcome` という API の型）に対して行われている。**⛔ **書き手が ADR・issue 本文・報告で「無かった」と書くときの手続きには、まだ当て直されていない。**この ADR が足すのはそちらである。

## 決めたこと

### 決定1. `AGENTS.md`「作業のときの決まり」に「⚠ 「無かった」と書く前に、探した場所を列挙する」を新設する

**書くのは3つ**: (1) 一般形（「無い」「見つからなかった」と書く前に探した場所を列挙する。列挙できないなら「当たった範囲での結果であり断定ではない」と書く） (2) **向きが逆であることの明記**（正典の版と、この版は宛先が違う） (3) **例外**（列挙は網羅を示さない）。

⭐ **ADR 0223 決定10 が挙げる ADR の一覧は `AGENTS.md` へ写さない。ADR 0223 を指すだけにする**（ADR 0234 決定1 / ADR 0250 決定1 と同じ理由——一覧は ADR が増えれば動く。この ADR 自身が「⚠ 数を、道具と生成物に焼き込まない」節を自己適用する形でもある）。

### 決定2. ⭐ **向きが逆であることを、一般形と同じ重みで書く**

**⛔ 「正典に在るから足さなくてよい」と読まれると、この決定10 が丸ごと不要判定されてしまう。**

北極星は `mnemora`（製品）が使う側に返す姿を定めている。**担い手が ADR・issue・報告に「無かった」と書く手続きは、別の宛先である。** ADR 0089 が north-star の同じ逐語を製品の型（`ConsolidateOutcome`）に当てているのは、まさに**正しい向き**の適用例であり、**その適用がまだ書き手自身の手続きには及んでいない**ことの対照になる（上記「なぜ入口へ置くのか」）。

### 決定3. ⚠ **例外を一般形と同時に書く** —— **列挙は網羅を示さない**

**「探した場所を書け」は「網羅を証明せよ」ではない。**書かないと、探索の報告が無限に重くなる。

**【現物】[ADR 0140](./0140-contested-write-side-companion-required.md) が、この例外を自分の失敗で認めている。**同 ADR は `packages/postgres/src/__tests__/` を横断した `grep` で「対向無し `contested` 生成の全箇所」を洗い出したと書いたが、その洗い出し自体が一度見落としを起こしていた——見落とした箇所（`recall-gate-index.test.ts` の `insertManyMemories`）は、**手元の `grep` では見つけられず、CI の DB ジョブが実際に落ちて初めて見つかった**【現物・逐語、同 ADR】:

> `grep` は「`status: "contested"` という字面」までは見つけられるが、それが `contestedWithId` を伴わずに `store.createMemory` へ渡っているかは、関数呼び出しの組み立てを追わないと分からず、今回は `grep` でも見落とした。

同 ADR は再実行後も「確かめていないこと」節で念を押している【現物・逐語】:

> **`packages/postgres/src/__tests__/` を横断した `grep` が、対向無し `contested` 生成の全箇所を本当に洗い出せているという保証。** `grep` と目視で「見つからなかった」ことを確認したに留まり、DB を伴う全テストを実際に実行して確認したものではない——…**同種の見落としが他にも残っている可能性を否定できない。**

⟹ **列挙した探し先が網羅であることは、列挙しただけでは示せない。**「探した範囲を書け」という決定10 の要求は、「その範囲が全部だと証明せよ」までは含まない——含めると、決定10 自身が ADR 0140 と同じ形で自壊する。

## 現物へ当て直した独立の採用例

**この形を独立に採った ADR の一覧は [ADR 0223](./0223-cross-cutting-disciplines-extracted-from-the-adr-corpus.md) 決定10 に在る**（`AGENTS.md` へは写さない。ここは ADR 本文なので、書き手が自分で当て直した確認として残す）。

- **[ADR 0065](./0065-vector-store-space-separation-conformance.md)**【現物・逐語】: 「⚠ **「意図的にこの歯を作らなかった」という決定は見つからなかった——ただし、これは「無かった」という断定ではなく、当たった範囲での結果である。**当たったのは…」と、当たった範囲（ADR 64本・`git log` 16コミット・PR番号付き74コミット）を具体的に列挙してから断定を避けている。

- **[ADR 0089](./0089-runtime-consolidate-shape.md)**: 上記「なぜ入口へ置くのか」の根拠。north-star の同じ逐語を製品の型へ**正しい向き**で適用している実例。

| 案 | ⛔ 落とした理由 |
|---|---|
| **`docs/autonomy.md` §5「報告に必ず書くこと」へ置く** | ⚠ **マネージャーの指示どおり、ADR 0234/0250 が使った「宛先が狭い」という理由がそのまま当たるかを自分で確かめた。** 結論: **狭さの中身は違うが、狭さそのものは同じ形で当たる。** §5 は「PR 本文に分けて書く」形で、**宛先が「オーナーに逐一確認せずに進める担い手が書く PR 報告」に閉じている**【現物、`docs/autonomy.md:3`「この文書は、オーナーに逐一確認せずに作業を進めるエージェントのためのものである」】。だが決定10 が要る場面は PR 報告に限らない——ADR の「確かめていないこと」節（0065/0074/0218 の実例）、issue 本文（#505 自身）、code review コメントなど、**確認しながら進める人間・エージェントが書く場面にも同じだけ当たる。**⟹ **狭いのは「PR 報告という成果物」と「確認せず進める担い手という書き手」の両方であり、`AGENTS.md`（人もエージェントも読む・成果物を限定しない）のほうが実際の適用面と一致する。** |

## ⭐ 歯を足すか —— ⛔ 足さない

**決定10 の一般形**（「無かった」と書く前に探した場所を列挙する）**を機械で縛ることを検討した。**

⛔ **足さない。理由は2つ。**

1. **偽陽性率に上限を置けるとは言えない**（[ADR 0223](./0223-cross-cutting-disciplines-extracted-from-the-adr-corpus.md) 決定3「⛔ 偽陽性率に上限を置けない検査は、門にしない」への自己適用）。「探した場所を列挙しているか」は構文の形では判定できない——「見つからなかった」という文字列の近くに列挙が在るかを機械で見分けるには、その列挙が本当に対応する探索なのか（ADR 0065 のように後から表で列挙する形もあれば、ADR 0074 のように直後に置く形もある）を意味で読む必要がある。
2. **個別インスタンスの ISSUE がまだ無い**。`gh search issues --repo takecchi/mnemora "探した場所" "見つからなかった 断定"` を実行したが、決定10 に反する具体的な文書を指す ISSUE は見つからなかった（Issue #505 自身がヒットするのみ）。⟹ **成文化だけを済ませ、歯は個別の事例が出たときの別の判断とする。**

⚠ **この検索は網羅ではない**（下の「確かめていないこと」）。

## 引き受けた負債

- **残る2つ（[ADR 0223](./0223-cross-cutting-disciplines-extracted-from-the-adr-corpus.md) 決定3 / 6）の宛先は、まだ決まっていない。**⟹ この ADR は決定10 の1本だけを動かしており、**[Issue #505](https://github.com/takecchi/mnemora/issues/505) は閉じない。**

## これが覆るとしたら
