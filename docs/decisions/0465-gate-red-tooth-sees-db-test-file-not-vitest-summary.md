# ADR 0465: 門が赤くなる歯は、「DB テストが本当に走って落ちた」を vitest の集計の行ではなく、落ちた DB テストのファイルの名前で見る

- **状態**: 採用 (2026-10)
- **日付**: 2026-10-01

クローン miku の委譲先（マネージャー mgr-3a4ae979）が書いた。直し方の線（テストが vitest の集計の文言に依存しない形にする・歯の強さは落とさない）はクローン miku が決めた。オーナーの判断ではない（[ADR 0220](./0220-issue-comment-author-does-not-distinguish-owner-from-agent.md)）。
**オーナーが覆せる点は「これが覆るとしたら」にまとめてある。**
出所の区別: 【現物】は読んだコード・CI のログ、【実測】は手元で走らせた結果、【判断】は担い手の判断。

- **文脈**:

  1. **【現物】** main `e4e27fd`（#1568 のマージ後、run `36844330037`、job `typecheck / lint / test / build`）で、
     `scripts/__tests__/run-db-tests.test.mjs` の「DATABASE_URL が在って DB テストが落ちるとき: 門が赤くなる」が落ちた。
     門の中の `@mnemora/postgres` の `vitest run --bail=1` は期待どおり落ちていた（`Tests  1 failed | 128 passed (278)`、
     門は `✗ DB テストが落ちました（@mnemora/postgres）。` を出し、終了コードも 0 でなかった）。ところが集計の行が
     `Test Files   (296)` だけで落ちた数を出さず、歯の `/Test Files\s+\d+ failed/` に合わなかった。
     `--bail=1` で打ち切る時機によって、落ちたファイルが集計に数えられないことがある、と読む（【判断】。vitest の内部は追っていない）。
  2. **【現物】** この `expect` が守っていたのは、コメントのとおり「DB テスト（`vitest run`）が本当に走って落ちたこと——門が自分の文言だけを出す形では通らない」。
     門の終了コードと門の文言（`DB テストを実行します`・`DB テストが落ちました`）は、別の `expect` で既に縛っている。
     ⟹ 門の終了コードや門の文言に置き換えるだけでは、「本当に走った」の強さが落ちる。

- **決めたこと**:

  1. **印を、落ちた DB テストのファイルの名前（`src/__tests__/<名前>.test.ts`）にした。** 門は `test:db` を `stdio: "inherit"` で起動するので、
     子の vitest が落ちたテストを報告する行（`FAIL … src/__tests__/….test.ts > …`）とスタックが、歯の捕まえる出力に届く。
     門が自分で出すのはパッケージ名と `test:db` だけで、ファイルの名前は出さない。vitest の集計の行の形にはよらない。
  2. **`ECONNREFUSED 127.0.0.1:1` は印にしなかった。** 最初はこれにしたが、門の接続先の告知（`接続先: （版を取得できませんでした: connect ECONNREFUSED 127.0.0.1:1）`）が
     同じ文字列を出すので、門が DB テストを起動しなくても通った（下の変異 M1・M2 で緑のままだった）。
  3. **`.postgres.test.ts` にも絞らなかった。** DB テストのファイルがすべてこの名前で終わるわけではない（【実測】手元で最初に落ちたのは `src/__tests__/contested-with-index.test.ts`）。
  4. **門（`scripts/run-db-tests.mjs`）は変えていない。** 変えたのは歯の `expect` 1つとコメントだけ。CHANGELOG は、利用者に見える変更が無いので足していない。

- **測ったこと**（【実測】。手元の器、`node scripts/run-db-tests.mjs --bail=1` を歯から子プロセスで起動する本物の形。変異は `cp` で退避・復元）:

  | 門 | 古い歯（`Test Files … failed`） | 印を `ECONNREFUSED 127.0.0.1:1` にした歯 | 新しい歯（`src/__tests__/….test.ts`） |
  |---|---|---|---|
  | 元のまま | 緑 | 緑 | 緑（3回） |
  | M1: `test:db` を起動せず `{ status: 1 }` で「落ちた」とだけ言う | 赤 | **緑**（門の告知に同じ文字列） | **赤** |
  | M2: `test:db` の代わりに `node -e "process.exit(1)"` を起動する | 赤 | **緑** | **赤** |

  - CI で揺れたときに歯が捕まえた出力（ログの `AssertionError` に出ている部分）に正規表現を当てると、古い印は合わず、新しい印は合った。
  - ファイル全体（8本）は緑。

- **採らなかった案**:
  - **集計の行の正規表現を緩める**（`Tests\s+\d+ failed` も許す等）。vitest の集計の文言に依存したままで、別の打ち切り方でまた揺れうる。
  - **pnpm の `ERR_PNPM_RECURSIVE_RUN_FIRST_FAIL … test:db` と `Exit status 1` を印にする**。子を起動して非 0 で終わったことは分かるが、
     DB テストが走ったこと（M2 のように別の子でも出る）までは言えない。
  - **門の文言・終了コードだけにする**。既に別の `expect` が縛っており、「本当に走った」を測れなくなる。

- **引き受けた負債**:
  - 印は vitest が落ちたテストを報告するときにファイルの相対パスを出すことに依る。集計の行よりは安定と判断したが、vitest の報告の形が変われば、この歯がまた揺れる（赤い側に倒れるので、黙って弱くはならない）。
  - `--bail=1` のとき集計の行が落ちた数を出さない理由（vitest 5.0.0 の内部）は追っていない。

- **これが覆るとしたら**:
  - 門が自分でテストのファイルの名前を出すようになったとき（この印では「本当に走った」を測れなくなる）。そのときは印を選び直す。
  - 直したあとも同じ歯が CI で落ちたとき。ログから切り分け直す。
