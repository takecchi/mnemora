## 問い

**[Issue #403](https://github.com/takecchi/mnemora/issues/403) が報告した形**【現物】:

`examples/chat/compare-baseline.json` の `omitted` 欄が `main` 上で陳腐化しており、
`example-chat` ジョブの Job Summary には**相違が出続けるのに、CI は緑のままである。**

⛔ **これは見落としではなく、設計どおりである**——⭐門（`scripts/compare-summary-lib.mjs` の
`GATE_FIELDS`）は `mnemoraShareOfNaiveChars` と `factStatementSurvived` の2欄しか見ない
（[ADR 0133](./0133-compare-baseline-and-gate.md)）。`omitted` は `DIFF_FIELDS` に在るので
**Job Summary には出る。**

⟹ 🔴 **`omitted` は「誰も見ていない欄」ではなく、「出ているが、誰も直す義務を負わない欄」である。**
⟹ **誰も直す義務を負わないので、腐る。**

## 決定 —— **落とす門にはしない。「申告を強制する門」として置く**

**`omitted` の `kind` と `stage` の組の*集合*が基準値から動いたら、その PR 本文に
「意図した仕様変更である」という*申告*を1行要求する。申告が在れば通し、無ければ落とす。**

申告の形（`scripts/compare-omitted-stage-declaration-lib.mjs` の `DECLARATION_PATTERN` が正本。
**ここに正規表現を写さない**——[AGENTS.md](../../AGENTS.md)「⚠ 数を、道具と生成物に焼き込まない」と同じ線）:

```
Compare-Omitted-Stage: <なぜ動いたのか。意図した仕様変更なら、その出所（ADR 番号など）>
```

⛔ **印だけ置いて理由が空の行は、申告として数えない。**

### 何を見て、何を見ないか

| | |
|---|---|
| ⭕ 見る | 各行の `omitted` の **`kind`+`stage` の組の集合**（重複は潰す） |
| ⛔ 見ない | **`count` / `countKind` の値**。件数は run ごとに揺れうる側であり、#403 の測定もそこは「揺れなかった」以上を主張していない【受: #403 のコメント（2026-09-21）】 |
| ⛔ 見ない | **申告の中身が本当か。**「理由が空でない」ことしか見ない |
| ⚠ 判定しない | **PR 本文が無いとき**（`main` への push）。⟹ `skipped` を出して緑で通る。⛔ **「動いていない」ではない**——CLI がそう名乗る |
| 🔴 判定不能 | **実測と基準値の `turnCount` 集合が食い違うとき** ⟹ **exit 2**。⛔ 申告が在っても黙らせられない（[Issue #477](https://github.com/takecchi/mnemora/issues/477) が `compare-summary` に入れたのと同じ線） |

## なぜこの形か

- ⛔ **`stage` 集合の一致を `GATE_FIELDS` に足す（＝落とす門にする）のは採らない。**
  `AGENTS.md`「⚠ **偽陽性率に上限を置けない検査は門にしない**」に正面から当たる
  ——`stage` 集合が動く理由には「退行」と「意図した仕様変更」の両方が在り、
  **機械にはその2つを区別できない。**
  ⚠ ADR 0133 自身が「全欄の厳密一致を門にする案」を、同じ理由で既に却下している【現物】。
- ⛔ **かといって「見ない」も採らない。**#403 が報告したのは、**その空白期間が実在した**ことである。
- ⟹ ⭐ **偽陽性の代償を「PR が赤になる」から「一行書く」へ落とす。**
  ⟹ **偽陽性率に上限を置けなくても、門にできる。**
- ⭐ これは `AGENTS.md`「⚠ **機械には「検出」まで — 確定と書き込みは人に残す**」の適用でもある
  ——**機械は検出して赤くするところまでで止まり、基準値を1バイトも書き換えない。**
  ⟹ 同 AGENTS.md の線（repo の中／GitHub 側の取り消しにくい面）でいえば、
  この門は**何も書き込まない**側に留まっている。

  ⚠ **fixture の値は歯が持つ**——`main` の基準値ファイルから読んでいない。
  読むと `main` が動くたびに歯の意味が変わる

## 検討して採らなかった案

1. **(A) `omitted` を `GATE_FIELDS` に足して落とす門にする。**⛔ 却下——上記「なぜこの形か」1番。
   ⚠ **#403 のコメントが「A′（`stage` 集合だけを門に加え、`count` は加えない）」として測っており、
   過去の意図した変更で 5/12 行が赤くなると出ている**【受: #403 のコメント（2026-09-21）】
   ⟹ **偽陽性の実在が示されている。**
2. **(B) 基準値ファイルから `omitted` 欄ごと落とす。**⛔ 却下——`stage: "association"` のような
   「連想枠が何件捨てたか」の記録が基準値から消える ⟹ 次に同種の穴が開いたとき、
   基準値からは検知できなくなる（#403 本文が挙げた代償）。
3. **(C) いま基準値を更新するだけ。**⛔ 却下——**また腐る。**判定に使わない欄は、次に形が変わったときも
   誰も直す義務を負わない ⟹ **同じ ISSUE がもう一度立つ。**
4. **機械が基準値を自動更新する。**⛔ 却下——`AGENTS.md`「機械には検出まで」に反する。
   「意図した変更か退行か」を機械が判定できない以上、自動更新は**退行を黙って飲み込む。**
5. **`count` も申告の対象にする。**⛔ 却下——件数は run ごとに揺れうる側であり、
   申告を要求する回数が増えて**申告そのものが儀式化する。**

## 引き受けた負債

1. 🔴 **この門は、この CI 実行を起こした push の時点の PR 本文しか見ない。**
   ⟹ **最後の push の「後」に `gh pr edit` で申告を足しても効かない**
   （`ci.yml` の `pull_request` トリガーに `edited` を足していない）。
   ⚠ **`scripts/check-pr-adr-reference.mjs` が同じ穴を持ち、同じ断りを書いている**【現物】
   ——**この ADR は穴を塞いでおらず、既存の作法（申告を書いてから push する）に乗っているだけである。**
   ⚠ **この順序を逆にして赤を1回増やした実例が在る**【実測 2026-09-23、[PR #620](https://github.com/takecchi/mnemora/pull/620)】。
2. **`omitted` の陳腐化そのものは、この PR では直していない。**この門は「**次から腐らない**」を作るだけである。
   ⟹ **いま基準値に載っている古い `omitted` は、古いままである。**
   ⛔ **更新は CI artifact からのみ行う**（[ADR 0121](./0121-bench-baselines-from-ci-artifacts.md) /
   [ADR 0231](./0231-compare-baseline-omitted-measured-update-and-freshness.md)）。この作業環境には `DATABASE_URL` が無く、
   **`compare` ベンチを一度も走らせていない**【実測】。
3. **申告の中身の妥当性は、誰も検査しない。**「一行書けば通る」形である
   ⟹ **申告が儀式になる可能性が在る。**⚠ そうなったかどうかは、この ADR では測れない。
4. **`example-chat` ジョブの中に置いた**（新しい required context を作っていない）
   ⟹ **`compare` が走らない状況ではこの門も走らない。**

## これが覆るとしたら何が起きたとき

- **申告が儀式化したとき**（内容の無い申告が積み重なる）⟹ 申告の形を強める、または (A) を採り直す。
- **`stage` 集合が「意図した仕様変更」以外の理由で頻繁に動くと分かったとき**
  ⟹ この門は偽陽性の山になる ⟹ 見る対象を狭めるか、撤回する。
- **`omitted` の構造そのものが変わったとき**（`kind`/`stage` 以外の軸が増える）
  ⟹ `omittedEntryKey` の定義を見直す必要が出る。
- **`ci.yml` の `pull_request` トリガーに `edited` が足されたとき** ⟹ 負債1 が解消する。

## 確かめていないこと

1. **`compare` ベンチを一度も走らせていない**——この作業環境に `DATABASE_URL` が無い。
   ⟹ **この門が本物の `compare.json` に対してどう振る舞うかは、CI で初めて分かる。**
2. **#403 のコメントが測った数値（n=10 の run 間一致、5条件の順序・件数実験、A′ の 5/12）を
   再導出していない**【受】。この ADR が使ったのは、その**結論の形**だけである。
3. **申告の正規表現が、実在の PR 本文の書き方すべてに耐えるかは測っていない。**
   歯で固定したのは「理由あり／理由なし／引用・箇条書きの装飾つき／本文が文字列でない」の4形だけである。
4. **オーナー本人の確認は取っていない**（冒頭のとおり）。
