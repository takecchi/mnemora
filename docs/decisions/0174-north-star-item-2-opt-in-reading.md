## 文脈: なぜ改めたか

### 監査の判定

2026-09-16 の7項目最終監査（`docs/roadmap.md` §7.4、PR #346 で着地）が、北極星「目指す姿」
項目2「聞かれていないことを、自分から思い出す。」を**「半分」**と判定した
（`docs/roadmap.md:538`）。

### 判定の根拠になった現物

**【現物】`packages/core` の既定は off のまま。**`packages/core/src/recall.ts:1104` の

```ts
association?: RecallAssociationQuery;
```

は optional で、既定値の代入が無い。同じファイル `:1100` の doc コメントは逐語で

> **省略時は連想を一切走らせない**（既定 off）

と明記している。off の実体は `packages/core/src/recall-runtime.ts:988` の

```ts

```

である。**⟹ npm から `@mnemora/core` を入れた利用者に届く既定の振る舞いは
「聞かれたことしか返さない」。**

**【現物】on にしている唯一の呼び手 `examples/chat` は出荷されない。**
`examples/chat/package.json:4` は `"private": true`。`scripts/publish-targets.mjs` の
`PUBLISH_TARGETS` は `@mnemora/core` / `testkit` / `openai` / `postgres` / `anthropic` /
`local-embedding` の6件で、同ファイル冒頭のコメントが「対象は固定リストである
（動的に発見しない）。publish 対象と非対象（ルートの `mnemora` /
`@mnemora/example-chat`）を分ける機械的な目印は無い」と `@mnemora/example-chat` を
publish 非対象として名指ししている。**⟹ `examples/chat/src/mnemora-path.ts:22` の**

```ts
export const DEFAULT_MNEMORA_PATH_ASSOCIATION: RecallAssociationQuery = { maxCount: 10 };
```

**は利用者に1バイトも届かない。**

### 食い違っていたのは正典と実装ではなく、正典どうしである

AGENTS.md は「正典と実装が食い違ったら、バグなのは実装のほうである」と定める。
しかし `docs/roadmap.md` §7.4 が指摘した通り、**ここで食い違っていたのは項目2 自身と
北極星「迷ったときの問い」の問い1（毎回渡す量を減らす方向に働くか）である**——
[ADR 0151](./0151-recall-association-unprompted.md) が既定 on を落としたのは
まさにこの問い1であり、連想枠は載る量を*増やす*機能である。**⟹ AGENTS.md の
「正典と実装が食い違ったらバグなのは実装のほう」という規律は、この形には当たらない。**
どちらの実装も、それぞれの正典の要求（項目2 の「自分から」／問い1 の「量を減らす」）を
律儀に満たそうとした結果、正典の内部で衝突していた。

## 何を変えたか

**変更前**（`docs/north-star.md` 29行目）:

```
- **聞かれていないことを、自分から思い出す。**
```

**変更後**:

```
- **使う側が有効にすれば、聞かれていないことを、自分から思い出す。**——有効にするのは使う側だが、何を思い出すかは mnemora が決める。
```

### 「自分から」を残した理由

**オプトインは「誰が機構を有効にするか」の話であり、「誰が思い出すか」の話ではない。**
使う側は「連想を有効にする」と言うだけで、何を思い出すかは指定しない——アンカーの近傍を
選ぶのは mnemora の側である（`packages/core/src/recall-runtime.ts` 段3.5、
`retrievedVia: 'association'` / `associationOf` として結果に印字される）。後半の
「——有効にするのは使う側だが、何を思い出すかは mnemora が決める。」は、**この区別を
文言として固定するために置いた。**

**⚠ ここが曖昧になると、この一行が守っていたもの（mnemora の側が能動的に想起すること）が
消える。**「使う側が有効にすれば」だけを読んで「使う側が何を思い出すか決める」と読み違えると、
項目2 は項目7（「どれだけ載せるかを、使う側が決められる」）と区別が付かなくなる。

### 項目7 との違い

項目7「どれだけ載せるかを、使う側が決められる」は、オプトインがそのまま充足である
——「載せる／載せない」を使う側が決めることが項目そのものだからである。

項目2 は「自分から」なので、字義通りに読めば呼び手のオプトインは充足の否定に近い
（`docs/roadmap.md` §7.4 の「⛔ 項目2 を『在る』と数えなかった理由」1番が指摘した通り）。
**⟹ 本 ADR は、オプトインを充足の側に数えるという読みを、正典の側で明示的に確定させた。**
これは新しい設計判断ではなく、オーナーが選んだ道 (ろ) をそのまま文言に落としたものである。

- **連想枠を既定 on にしたわけではない。**`packages/core` の既定は off のままであり、
  `recall.ts:1104` も `recall-runtime.ts:988` も本 PR は1バイトも変えていない。
  **本 PR は `packages/` と `examples/` を一切触っていない**（`docs/` のみの変更）。
- **[Issue #337](https://github.com/takecchi/mnemora/issues/337) の「10万行級で測ってから
  判断」は生きている。**既定 on の判断はこの ADR で先取りしていない。オーナーの逐語
  （`docs/roadmap.md` §7.4 が引用、【受】）——「**10万行級で測ってから既定 on をやるか
  判断してほしいです。**」——は変わらず未達のままである。
- **[ADR 0151](./0151-recall-association-unprompted.md) の判断（既定 on を落とした理由 =
  問い1）は揺らがない。**本 ADR は問い1を当て直していない。
- **項目6（[Issue #329](https://github.com/takecchi/mnemora/issues/329)）については
  何も言っていない。**項目6「知らないことを、知らないと言える」が「半分」である理由

- **`docs/roadmap.md` §7.4 の ⚠2（連想枠が忘却ゲートと `validAt` ゲートを両方すり抜ける）は
  塞がっていない。**項目2 の読みが確定しても、`recall-runtime.ts:1049-1064` の連想用
  `vectorStore.search()` の filter が `decayFloorAtAfter` / `decayFloorSeqAfter` /
  `validAt` を渡していないという実装のバグは、そのまま残る。

## 北極星の5つの問いに当てる

1. **これは、毎回渡す量を減らす方向に働くか。増やすなら、その分だけ想起が良くなると
   言えるか。** ⟹ **働かない。**この ADR は文書の1行を書き換えるだけであり、
   `packages/core` の既定は off のままである。量が増えるのは、呼び手が明示的に
   `association` を渡す（＝オプトインする）ときだけであり、それは元から呼び手の選択
   だった。**連想枠は予算の内側で最初に落ちる**（`recall-runtime.ts:1163`
   `const allUnits = [...units, ...associationUnits];` が予算の切り詰めで最初に
   削られる順で連結している）——予算を絞れば量は増えない。
2. **これを無効にしたとき、Memory Framework として成立するか。** ⟹ **落ちる案なし。**
   本 ADR は文書変更であり、連想枠を無効にする（`association` を渡さない）という
   既存の経路には触れていない。
3. **この記憶が選ばれた理由を、後から説明できるか。** ⟹ **落ちる案なし。**本 ADR は
   `explain`（`getRecall`）の経路に触れていない。
4. **AI の推論と、ユーザーが言った事実を、区別しているか。** ⟹ **落ちる案なし。**
   本 ADR は API の記述であり、記憶の内容の推論/事実の区別には関与しない。
5. **これは、LLM を呼ばずに済ませられないか。** ⟹ **落ちる案なし。**本 ADR は
   文書変更であり、LLM 呼び出しの要否を左右しない。

**⟹ 5問中、実際に判断を導いたのは問い1だけである。**残り4問は「飾りで当てはめない」
という AGENTS.md の指示に従い、素直に「落ちる案なし」と書く。

## 引き受けた負債

1. **正典の1行が「使う側が有効にすれば」という前置きを持つことで、文が長くなり、
   読み手が後半の「——有効にするのは使う側だが、何を思い出すかは mnemora が決める」まで
   読まないと、項目2 と項目7 の違いが伝わらない。**元の一文「聞かれていないことを、
   自分から思い出す。」が持っていた短さ・強さは失われた。
2. **道 (ろ) を選んだことで、項目2 の充足は `examples/chat` という非公開パッケージの
   挙動に依存したままである。**`packages/core` 単体を npm から入れた利用者にとって、
   項目2 は依然として off の挙動しか届かない。この ADR は「外から見て満たされる」の
   「外」を `examples/chat` を含む形で確定させたが、**`@mnemora/core` だけを見る利用者
   にとっての体感は変わっていない。**
