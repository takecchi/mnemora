# ADR 0156: 「§5 級の判断」と「公開 API の破壊的変更」の事前承認待ちを、担い手へ委譲する（`docs/autonomy.md` §3 の改定）

- **状態**: 採用 (2026-09)
- **日付**: 2026-09-16

**⚠ 各主張の出所を分ける**（[ADR 0118](./0118-pr-merge-delegated-when-ci-green.md) / [ADR 0151](./0151-recall-association-unprompted.md) の体裁を踏む）。

- **【現物】** — この repo のコード・文書を、この ADR の書き手が自分の手で読んで確かめた。
- **【伝】** — オーナーの決定として、書き手へ伝達された。逐語を引く。

---

## 決定

**`docs/autonomy.md` §3 の ⛔ 表から、次の2行を外す。**

1. **`§5 級の判断`を自分で決めること**
2. **公開 API の破壊的変更**（`0.x` なので semver 上は許されるが、従来は「提起までにする。ADR を書き、実装は別 PR にして、承認を待つ」と定めていた行）

**根拠 【伝】**: 2026-09-15、オーナーが**クローンへ直接**（マネージャーを介さず）回答した。逐語:

> Aでお願いします。北極星を目指し貴方が進めてください。

> 破壊的変更であっても構わず実装してください。

（承認 id `f6d9c3ea`）

**⚠ 出所について**: この逐語を受け取ったのはクローンであり、この ADR の書き手（担い手）は
オーナー本人とやり取りしていない。書き手はマネージャー経由の指示としてこの逐語を受け取り、
本 ADR に転記した。**この前提が誤りだった場合、この ADR は無効であり、`docs/autonomy.md` は
本 ADR の変更前の状態へ戻すべきである**（ADR 0118 が同じ形の伝聞に対して取った態度をそのまま踏む）。

**⚠ 同じ逐語が既に別の目的で使われている 【現物】**: `git grep` で確認したところ、
「Aでお願いします。北極星を目指し貴方が進めてください。」は
[ADR 0152](./0152-consolidate-seed-neighborhood.md)・[ADR 0153](./0153-recall-decay-floor-gate.md)・
[ADR 0154](./0154-reflect-seed-neighborhood.md)・`docs/roadmap.md:352` に、
**それぞれ個別の `docs/roadmap.md` §5 項目（§5.7 等）を解決する根拠として**既に引かれている。
本 ADR はこの同じ逐語を、**個別の §5 項目1つに対してではなく、「§5 級の判断を自分で決めてよい」
という一般的な許可として**引く。⟹ **この解釈の広さ自体が、本 ADR が新しく主張する部分である**
（下の「採らなかった案」・「確かめていないこと」参照）。

**副次的な決定**: `docs/autonomy.md` §3.1 の手順（技術的に決められるなら決めて ADR に書く／
製品・事業・安全性の判断なら `docs/roadmap.md` §5 に項目を足して止まる）はそのまま残す。
本 ADR が変えるのは「§5 級の判断を**自分で決めることそのものが ⛔ だった**」という前提であり、
§3.1 の「迷ったら §5 へ足して止まる」という既定動作自体は削らない
——**許可が増えても、「迷ったら止まる」という規律は残す**（ADR 0118 が「積極的にマージを」を
「何でもマージしてよい」と読まなかったのと同じ考え方）。

## 誰が受け取った許可か

**クローンが受け取った。マネージャーではない。**
この点は ADR 0118（マネージャー経由の伝聞としてクローンが最終的に自律作業へ反映した先例）と
出所の層が違う——ADR 0118 は「マネージャーがオーナーの許可を伝えた」という伝聞だったのに対し、
本 ADR の根拠はオーナーからクローンへの直接の回答である。**ただし本 ADR の書き手（担い手）自身は
このやり取りに同席していない**——上の「出所について」に書いたとおり、書き手にとってはこれも
また伝聞の1段である。

## ⛔ のまま残るもの

`docs/autonomy.md` §3 の ⛔ 表を自分で全行読み直し、本 ADR が変えない行を数え上げた 【現物】。
本 ADR の変更後、表に残るのは次の**5行**である:

1. **npm への publish・Release の作成・npm 側の設定**
2. **`package.json` の `version` を上げる**
3. **`docs/north-star.md` の書き換え**
4. **`docs/north-star.md` の「やらないこと」への追記**
5. **ライセンス・パッケージ名・依存の追加方針の変更**

**これらは本 ADR の後もそのまま ⛔ である。**本 ADR が変えるのは「§5 級の判断」と
「公開 API の破壊的変更」の2行だけである。

## 採らなかった案

| 案 | 却下の理由 |
|---|---|
| **オーナーの逐語を、これまでどおり個別の §5 項目1つずつの解決にしか使わない**（一般的な委譲だとは解釈しない） | ADR 0152/0153/0154 は既にこの逐語を「オーナーの一般的な意思表示」として扱っており（各 ADR が「v0.x の破壊的変更を許諾した」という形で引いている）、本 ADR だけ狭く読む理由が無い。むしろ**同じ逐語をこれ以上個別の場面ごとに引き直し続けるほうが、`docs/autonomy.md` の正典と運用の乖離を積み増す**——ADR 0118 が Issue #203 で指摘したのと同じ形の問題を、§5 級の判断・破壊的変更の2点で繰り返すことになる |
| **§3.1 の「迷ったら §5 へ足して止まる」手順ごと削除する** | オーナーの逐語には「迷ったときにどうするか」の粒度の指示が含まれていない。ADR 0118 の「採らなかった案」と同じ理由——**推測で線を引くと、オーナーが言っていない制約を勝手に足すか、勝手に緩めるかのどちらかになる。**⟹ 許可は広げるが、既定の「迷ったら止まる」動作は維持し、必要になったらそのとき ADR で決める |
| **「公開 API の破壊的変更」の事前承認待ちだけを外し、「§5 級の判断」は残す**（逆も同様） | オーナーの2つの逐語はいずれも「北極星を目指し貴方が進めてください」という同じ回答に対になっており、**分けて扱う根拠が無い**。実測でも（下の「測ったこと」）実際に3件の `!:` 破壊的変更が承認待ちなしで着地しており、この慣行を追認する形で両方を一度に扱うほうが実態に合う |

## 引き受けた負債

- **オーナーの逐語が、既に4箇所（ADR 0152/0153/0154・`docs/roadmap.md`）で個別の §5 項目の
  根拠として引かれており、本 ADR がその同じ逐語を一般化して引いている。**
  もしオーナーが「あれは個別の項目に対する回答であって、§5 級の判断全般を委譲したつもりはない」
  と後で言った場合、本 ADR だけでなく、この逐語を引いた既存の ADR 群の位置づけも見直しが要る。
- **書き手はオーナーとのやり取りに同席しておらず、伝聞をそのまま記録している。**
  上の「出所について」に書いたとおり、この前提が崩れれば本 ADR は無効になる。
- **「§5 級の判断を自分で決めてよい」の範囲が、依然として担い手の主観に委ねられている。**
  §3.1 の見分け方（「どちらを選んでも技術的には成立するが、選び方が製品の性格を決める」なら
  §5 行き）はそのまま残るが、**その判断自体を今後は担い手が下してよい**、という1段委譲が増えた
  ——これは「判断の質」ではなく「誰が最終的に決めてよいか」の変更であり、誤った判断が続けば
  委譲を狭める ADR が必要になる。

## 測ったこと

**`git log origin/main --format='%h %s' | grep '!:'` を実行して確認した 【現物】**——
`0.x` の段階で、実際に承認待ちなしに着地している破壊的変更が複数件在る:

```
1e65592 feat(core)!: recall の段1に忘却ゲート（decay_floor_at）を既定で通す（Issue #196 / ADR 0153） (#286)
21ecce2 feat(core,postgres,testkit)!: 「聞かれていないことを、自分から思い出す」を recall の連想枠として実装する（Issue #200 / ADR 0151） (#290)
937d507 feat(core,postgres,testkit)!: contested を active|superseded へ解決する経路を作り、段3の発火を変異試験で測る（Issue #197 / ADR 0150） (#283)
73233aa feat(core)!: 型に在って一度も生成されない4値を union から落とす（Issue #206 / ADR 0117 分類3 / ADR 0144） (#271)
```

依頼で名指しされたのは `1e65592`・`21ecce2`・`73233aa` の3件だったが、実際に `git grep` すると
`937d507`（ADR 0150）も同じ形で該当した。**⟹ 実測は4件であり、依頼時点の列挙（3件）より
1件多かった**——依頼側の列挙は写しであり、現物のほうを採る。

**⟹ この ADR は「これから許可する」のではなく、「既に実態として起きている慣行を、
正典側に追いつかせる」性質を持つ。**ADR 0118 が PR マージについて行ったのと同じ構図
（Issue #203 の問題——正典が実際のオーナーの意向・実際の運用を反映していない——を、
§5 級の判断・破壊的変更の2点についても解く）。

## これが覆るとしたら

1. **オーナーが直接（伝聞を介さず）この委譲を撤回したとき。**
2. **オーナーが「あの逐語は個別の §5 項目への回答であって、§5 級の判断全般や
   破壊的変更全般を委譲したつもりはなかった」と言ったとき**——本 ADR は無効になり、
   `docs/autonomy.md` §3 の該当2行を元に戻す。ADR 0152/0153/0154 が同じ逐語を引いて
   下した個別の決定は、本 ADR とは独立に、それぞれの ADR 自身の「これが覆るとしたら」で扱う。
3. **委譲によって実害（取り消せない失敗——例えば破壊的変更が外部の利用者を実際に壊し、
   それが問題化した等）が起きたとき**——そのときは委譲を狭めるか、事前レビューを条件に足す
   ADR が必要になる（ADR 0118 と同じ基準）。
4. **書き手が受け取った伝聞（マネージャー経由）が、実際のオーナーの発言と異なっていたと
   判明したとき**——上の「引き受けた負債」参照。

---

## 確かめていないこと

- **この委譲がいつまで有効かは、オーナーが期限を切っていない。**恒常的な運用方針として
  扱ってよいのか、それとも当時の文脈（v1.0 に向けた特定の作業）に限った許可だったのかは、
  逐語だけからは判別できない。ADR 0118 も同じ形の逐語（「積極的にマージをお願いします」）を
  恒常的な方針として扱っており、本 ADR もそれに倣ったが、**この解釈をオーナー自身に確認していない。**
- **オーナーの逐語を、書き手は直接受け取っていない。**マネージャー経由の伝達をそのまま記録した
  ——上の「出所について」「誰が受け取った許可か」に書いたとおり。
- **「§5 級の判断」という語がオーナー自身の語彙であるかは確認していない。**
  `docs/autonomy.md` §3.1 に既に在る表現をそのまま使ったが、オーナーが逐語でこの語を
  使ったわけではない。
- **既存の4件の破壊的変更（`1e65592`・`21ecce2`・`937d507`・`73233aa`）それぞれについて、
  着地時点でオーナーの個別承認が本当に無かったか（口頭・非公開のやり取りで承認されていた
  可能性）は確認していない。**確認したのは「`docs/decisions/` に事前承認待ちの記録が残っていない」
  という現物だけである。
