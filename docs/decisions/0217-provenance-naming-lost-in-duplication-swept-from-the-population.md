## 文脈

この repo は出所を全角ブラケットで名乗る規律を持つ（`docs/` 配下で **【実測】657 / 【現物】474 / 【受】224** 回
【実測 2026-09-17、`main` = `8cb43bc`、`grep -rho '【[^】]*】' docs | sort | uniq -c`】）。
**しかし規律が在ることと、守られていることは別である。**

**【受】**として次の報告を受け取った: 「4つの文書がほぼ同じ文で『一過性の corepack `ECONNRESET` で、
再実行すれば緑に戻る性質のものではあった』と書いており、出所の ADR だけが【受】と名乗っている」。

🔴 **問題は個々の文ではない。** 同じ文が複数の文書に在ると、**読む人には「よく知られた事実」に見える。**
名乗りは1箇所にしか残っていないのに、**複製の数だけ信憑性が増して見える。**
⟹ **v1.0.0 当日、`main` が赤かったときに「再実行すれば通る」へ頼る経路がここから生える。**

⛔ **「同じ形が他にも在る」を「探す」形では答えられない。** 見つかった件数だけを出すと、
**どれだけの中から出た件数かが分からない。** ⟹ **母集合を取り、そこから落として残りを出す形にした。**

## 見つかったもの

### 1. corepack `ECONNRESET` — **【受】は1箇所にしか残っていなかった**

⚠ **受け取った報告は「4文書」だったが、【現物】当て直したところ主張としては3文書である。**
4本目として挙がっていた ADR 0104 は `corepack` の `ECONNRESET` に触れるが、
主張は「**頻度は直近40 run 中1件**」であり、**自前の【現物】実測を持っている。⟹ 複製ではない。**

| 文書 | 名乗り |
|---|---|
| ADR 0191 | ⭐ **在る。**「issue 本文からの【受】であり、このセッションでは自分の `gh` 呼び出しで再導出していない」と「確かめていないこと」に明記 |
| ADR 0132 | 🔴 **落ちている。**しかも段落全体が「**PR #283 で【実測】として次を踏んだ**」で始まる |
| `docs/autonomy.md` §2.1.1 | 🔴 **落ちている。**名乗りが1つも無い |

🔴 **【現物】3文書とも同じ commit `6fc2afa`（PR #385）で入っている。**
⟹ **「後から複製されて名乗りが落ちた」のではない。1回の執筆で3箇所に書き、1箇所にしか名乗らなかった。**
⭐ **これは複製の事故ではなく、執筆の事故である。防ぎ方が変わる**（下の決定3）。

⛔ **赤くなった事実**と、**その赤が「一過性で、再実行すれば戻る性質」だったという原因の性質判定**は
**別の主張である。** ADR 0132 の【実測】は前者にはかかるが、後者にはかからない。

## 決定

### 1. 元の記述は消さず、**名乗りを戻す追記**で直す

⛔ **「再実行すれば緑に戻る」を削除しない。**⭐ **「それは【受】である」「実測は無い」と添える。**
⛔ **「だから再実行するな」とも書かない。**⭐ **測っていない、と書くだけである。**
ADR の本文は書き換えず、**冒頭に追記の節を足す**（ADR 0074 / 0128 の前例に倣う）。

### 2. 同じ主張が複数箇所に在るときは、**1箇所を正規の置き場にして、他はそこを指す**

pgvector の件は逐語と上流の実測を `docs/memory-model.md` にまとめ、
ADR 0002 と `docs/roadmap.md` §4 からはそこを指した。
⟹ **次に上流が動いたとき、直す場所が1つで済む。**

### 3. **数字を直すのではなく、鮮度と出所を名乗らせる**

⛔ pgvector の推奨下限を `>= 0.8.6` へ書き換えない。**数字を直してもまた腐る。**
⭐ **「2026-09-17 時点では古い。引くときに上流の `CHANGELOG.md` を見ること」と書く。**

  依存している。⟹ **意訳・要約で複製された主張は、この掃きをすり抜ける。**

  ⭐ **母集合（220 / 92 / 255 / 12 / 7,710）は【現物】であり、揃っている。**
