## 文脈

**Issue #263**: [ADR 0022](./0022-fake-provider-compare-does-not-claim-recall-quality.md) の
決定2（`compare` は擬似 provider で走るため、想起の質についての主張をここに載せない）は、
「`compare` は擬似 provider である」という前提の上に立っている。**その前提は
[ADR 0133](./0133-compare-baseline-and-gate.md)（2026-09-15）で崩れた**——【実測】
`compare.json` の `llmMode`/`embeddingMode` はどちらも `"deterministic"` ではなく
`"recorded"`（記録した実 API 応答の再生。[ADR 0051](./0051-recorded-provider-cassette.md)）
だった。

⚠ **ADR 0133 自身は ADR 0022 に一度も言及していない。**⟹ 前提が崩れたことは記録されたが、
その上に立っていた決定は見直されないまま残っていた。[examples/chat/README.md](../../examples/chat/README.md)
の Issue #248 対応の追記（2026-09-15）も同じ崩れを認めつつ、「この ADR 0022 の決定自体を
書き換えるべきかは、本追記の範囲では判断していない」と3箇所で明示的に判断を保留していた。
**この ADR が、その保留に答える。**

Issue #263 は3案を挙げている:

- **(A) 決定2 を維持し、理由を差し替える。**⚠ ADR 0088 が `retrieval-quality` を
  `recorded` で走らせることに意味を与えているため、**同じ層(`recorded`)で
  片方(`retrieval`)は質を主張してよく片方(`compare`)はいけない、という線引きを
  書けなければ (A) は成立しない**、と issue 自身が釘を刺している。
- **(B) 決定2 を撤回する**（`recorded` の `compare` から想起の質を主張してよいとする）。
  北極星の物差しに直接効く——製品の性格を決めうる。
- **(C) 決定2 の射程を分ける**（削減率は主張してよい／想起の質は主張しない、等）。

## 検討: 北極星の5つの問いに当てる

**(B)（決定2 を撤回し、`recorded` の `compare` から想起の質を主張してよいとする）を、
[docs/north-star.md](../north-star.md) の「迷ったときの問い」に実際に当てた。**

| 問い | (B) を当てた結果 |
|---|---|
| 1. 毎回渡す量を減らす方向に働くか | 中立に近い。(B) 自体は量を動かさない——「北極星の物差しの後半（削っても目的の記憶が落ちない）への主張の根拠が1本増える」だけであり、積む量そのものは変わらない。**この問いだけでは落とせない。** |
| 2. 無効にしたとき Memory Framework として成立するか | 無関係。`compare` は計測用の bench であり、`Runtime` の挙動そのものではない。**この問いは適用外。** |
| 3. **この記憶が選ばれた理由を、後から説明できるか** | **⟹ ここで落ちる。** `compare` の `buildConversation`（`scenario.ts`）は12種類の filler の巡回と単一の `FACT_STATEMENT` の有無しか判定しない——**正解集合(ground truth)を持たない。** 「この記憶が選ばれた/落ちた理由」を、`MRR`・`hit@k` のような**順位に基づく説明**として言おうとしても、比較対象になる正解の順位が定義されていないため、**主張の根拠を説明できない。** 問い3 は「記憶が選ばれた理由の説明」だけでなく、**その説明（主張）自体の根拠を持てるか**にも及ぶ——ここで (B) は明確に落ちる。 |
| 4. AI の推論とユーザーが言った事実を区別しているか | 無関係。`FACT_STATEMENT` はユーザー発話そのものであり、この問いに (B) は影響しない。 |
| 5. LLM を呼ばずに済ませられないか | 無関係。`compare` は既に LLM 呼び出し（抽出）を伴う実測であり、(B) の採否とは独立。 |

**⟹ 問い3 が (B) を落とす主因である。**量を測ることと質を測ることは別の要件であり、
`compare` の器は前者のためだけに作られている。

## 決めたこと

### 決定1: ADR 0022 決定2 の結論は維持する。理由を差し替える

**線は provider の層（`deterministic`/`recorded`/`openai`/`local`）には引かない。
測定器（bench）が正解集合を持つかどうかに引く。**

| bench | 何を回すか | 正解集合 | 測れるもの |
|---|---|---|---|
| `compare`（`examples/chat/src/compare.ts`） | `scenario.ts` の `buildConversation`（12種類の filler の巡回）+ 単一の `FACT_STATEMENT` | **無し** | `FACT_STATEMENT` が残ったか（真偽1点）と、積んだ量の比だけ |
| `retrieval`（`examples/chat/src/retrieval-quality.ts`） | `probe-set.ts`（7 probe × haystack、probe ごとに gold/distractor を定義） | **有り** | `goldRank`/`distractorRank`/`hit@1`/`hit@10`/MRR |

**`compare` には比較対象になる「正解の順位」が無いので、`MRR` も `hit@k` も定義できない。**
`factStatementSurvived` は「見つかったか/見つからなかったか」の1点しか持たず、
**「良い順位で見つかったか」を測れない。** ⟹ **`compare` が質を主張してはいけないのは、
`recorded` という層に居るからではなく、正解集合を持たない器だからである。** この線なら、
同じ `recorded` 層で `retrieval` が質を主張し `compare` が主張しない、という非対称は
矛盾しない——**両者は同じ層の別の器であり、片方だけが正解集合を持つ。**

**⟹ (A) は成立する。**上記の線引きが、issue が求めていた「ADR 0088 との整合」に答える。

### 決定2: 旧理由（「擬似だから」）は、いまは主たる理由として使わない。ただし当時の記述は書き換えない

**ADR 0022 が書かれた時点の測定は否定しない。**当時（2026-09-05/06 頃）、`compare` は
実際に `DeterministicEmbeddingProvider`/`DeterministicLLMProvider`（意味を持たない stub）で
走っていた——カセット（`examples/chat/cassettes/compare.json`）を入れたのは
[ADR 0052](./0052-compare-cassette-and-provenance-survival.md) であり、これは
**ADR 0022 より後**である。**⟹ ADR 0022 の「擬似 provider」という記述は、書かれた時点の
事実として正しく、書き換えない**（このリポジトリの「履歴を書き換えない」規律。`AGENTS.md`
「名前について」節が同じ扱いを `mnemo` の記述にしている）。

**いま現在形として成立しないのは、「今の `compare` も擬似 provider である」という主張の
ほうである。**この ADR は ADR 0022 の本文を書き換えず、追記でこの区別を明示する
（下記「決定3」）。

### 決定3: ADR 0022 に「追記 (2026-09-16)」を足す

既存の「追記 (2026-09-10)」と同じ体裁で、決定2 の理由が本 ADR に差し替わったことを記す。
**決定2 の結論そのものは書き換えない。**

### 決定4: `recorded` にも割り引きは要る。ただしこれは第二の・従の理由である

**⚠ ここが issue の核心である。**`AGENTS.md` 逐語:

> 割り引くのは、擬似物だからではなく、**記録した時点のものだからである。**

これは事実だが、**`compare` に固有の理由ではない**——`retrieval` のカセット
（`retrieval.json`）も「記録した時点のもの」であり、同じ割引きが掛かる
（[ADR 0088](./0088-retrieval-quality-measured-in-ci.md) 引き受けた負債4「カセットは
2026-09-06 に録ったものである」）。**⟹ この理由**単独**を `compare` の新しい理由に
すると、`retrieval` にも同じ理由が掛かるのに片方だけ質を主張できないことになり、
ADR 0088 との線が引けなくなる**——issue が警告していたまさにその失敗形である。

**⟹ 理由は主従の2本立てである。**

1. **（主）`compare` は正解集合を持たない器である。** これが決定2 を今後も支える理由。
2. **（従）カセットは記録した時点のものである。** `retrieval` にも同様に掛かる、
   `compare` だけを縛る理由にはならない一般的な注意点。**ただし `retrieval` が質を
   主張してよいことと矛盾しない**——`retrieval` は正解集合を持つ分、記録の陳腐化を
   `verify`（[ADR 0051](./0051-recorded-provider-cassette.md)）で検出する余地がある。
   `compare` にはそもそも「正しかったか」を測る軸(1) が無いため、(2) を測っても
   質の主張には繋がらない。

### 決定5: (C)（射程を分ける）は新しい決定を必要としない — ADR 0022 決定1 が既に果たしている

Issue #263 の (C) 案（削減率は主張してよい／想起の質は主張しない、という射程の分割）は、
**[ADR 0022](./0022-fake-provider-compare-does-not-claim-recall-quality.md) の決定1・決定2
そのものである**（決定1「擬似 provider の `compare` は『量の削減』を測る道具として使う」・
決定2「擬似 provider の `compare` は『想起の質』の主張をここに載せない」）。**⟹ (C) を
別の決定として採る必要はない**——維持している決定1・決定2 の組み合わせが、既に (C) の
形をしている。この ADR はこのことを明記するに留め、決定1 には手を入れない。

## 何を落としたか（⭐ 芯）

**(B)（決定2 を撤回し、`recorded` の `compare` から想起の質を主張してよいとする）を落とした。**

**(B) を採れば、北極星の物差し「使う側が会話ログを全部積むのをやめられたか」への主張の
根拠が1本増えたはずである。**`compare` は12種類の会話長（`DEFAULT_COMPARE_SEQUENCE`）で
実際に `recall()` を撃っており、322・642ターンのような大きい会話でも
`factStatementSurvived: true`（[ADR 0133](./0133-compare-baseline-and-gate.md) の
`compare-baseline.json` 実測）——これを「削っても答えが残った」の一事例として
積み上げられれば、`retrieval`（probe 7件）だけでは足りない標本を補えたはずだった。

**それでも落とした。理由は「正解集合を持たない」。**物差しの後半（**削っても目的の記憶が
落ちない**）は、「見つかったか」の1点(真偽値)だけでは測れない——本当に測るべきは
「正しい記憶が、正しい順位で選ばれたか」であり、それには比較対象になる正解の集合が
要る。`compare` の器はそれを持たない。1つの `FACT_STATEMENT` が残ったかどうかだけでは、
仮に無関係な記憶に埋もれてギリギリ`limit`に滑り込んだだけでも「✅」と出てしまい、
**なぜそれが選ばれたと言えるのか(問い3)を説明できない。**

## 採らなかった案

- **⛔ (B) 決定2 を撤回する。** 上記「何を落としたか」の通り却下。正解集合を持たない器で
  「想起の質」を主張すると、問い3（主張の根拠を説明できるか）が答えられない。
- **⛔ 理由を「記録した時点のものだから」だけに差し替える。** 却下（決定4）。この理由
  単独では `retrieval` にも等しく掛かり、ADR 0088 との線が引けなくなる——issue が
  名指しした失敗形そのものである。
- **⛔ (C) を新しい決定として書き足す。** 却下（決定5）。ADR 0022 決定1・決定2 が
  既にその形をしている。同じ内容を重ねて書くと、どちらが正典か曖昧になる。
- **⛔ ADR 0022 の本文（文脈・決定）を直接書き換える。** 却下。このリポジトリは履歴を
  書き換えない規律を持つ（`AGENTS.md`）。当時「擬似 provider だった」ことは当時の事実
  であり、追記で現在との差分を明示する形（ADR 0064/0072/0022 自身の先例）に倣う。
- **⛔ `compare` に正解集合を持たせる bench を今回作り、(B) をこの PR で採る。**
  却下（今回は）。範囲が ADR の理由差し替えを超え、`scenario.ts`/`compare.ts` の
  新規実装を要する——製品として何を測る bench にするかの設計判断が別途要り、
  `docs/autonomy.md` §2「1つの PR は1つの ADR とその実装」を超える。**「これが覆るとしたら」
  に道を残す。**

## 引き受ける負債

1. **`compare` は今後も想起の質の回帰を検知できない。** 検知するのは引き続き `retrieval`
   （probe 7件、[ADR 0088](./0088-retrieval-quality-measured-in-ci.md)）だけである。
   `compare` が12会話長で実際に `recall()` を撃っているという事実（標本の広さ）は、
   正解集合が無い限り活かせない。
2. **「正解集合を持つかどうか」という線引きは、この ADR が初めて明文化したものであり、
   他の bench（将来増えるかもしれない `examples/chat` のサブコマンド）に自動的には
   適用されない。** 新しい bench を足す側が、この ADR を読んで判断する必要がある。
3. **決定4 の(2)（カセットは記録した時点のもの）の割引きの大きさを、`compare` について
   定量化していない。** `verify`（[ADR 0051](./0051-recorded-provider-cassette.md)）は
   `retrieval` 用のカセット (`retrieval.json`) の乖離を測る仕組みであり、`compare` 用の
   カセット (`compare.json`) に対して `verify` を走らせて乖離を測ったことはない
   （このリポジトリの `verify` コマンドの対象を確認した限り。下記「確かめていないこと」）。

## これが覆るとしたら

- **`compare` の器（`scenario.ts`/`compare.ts`）に正解集合を持たせたとき。**
  たとえば `buildConversation` が複数の事実を埋め込み、それぞれに期待される順位を
  持たせれば、`MRR`/`hit@k` を `compare` 側でも定義できる——**そのとき (B) が復活しうる。**
  ただしそれは「`compare` を `retrieval` に似た器へ作り替える」ことであり、この ADR の
  線引き（正解集合の有無）自体は変わらない。線の**位置**（どちらの器が正解集合を持つか）
  が動くだけである。
- **`retrieval` の probe が数十件規模に増えたとき**（[ADR 0088](./0088-retrieval-quality-measured-in-ci.md)
  「これを閉じるのは、この ADR ではない」節が指す将来）。そのとき `compare` に正解集合を
  持たせる動機（標本を補う）自体が薄れる可能性がある——`retrieval` だけで十分な標本に
  なるかもしれない。
- **`compare` のカセット (`compare.json`) が実 API から大きく乖離していると分かったとき**
  （`verify` に `compare` 用のカセットも対象化して測る、など）。そのとき決定4 の(2)が
  実害になり、`compare` の量の削減率の主張（決定1、これは今回変えていない）にも
  再検討が要る可能性がある。

## 確かめていないこと

- **`examples/chat` の `verify` コマンドが `compare.json` を対象にしているか**は、
  この ADR の作業では検証していない。`retrieval.json` を対象にしていることは
  [ADR 0051](./0051-recorded-provider-cassette.md) が実測しているが、`compare.json`
  側を同様に検証したという記録はこの ADR の作業範囲では見つけていない。
- **この判断（決定2 の結論を維持し理由だけ差し替える。(B) を落とす）は、マネージャーから
  委譲文の形で受け取った結論である。** 北極星5問への当てはめ・正解集合の有無という線・
  主従2本立ての理由構成は委譲文に明示されており、この ADR の作業者はそれを ADR の形式
  （文脈・決定・採らなかった案・引き受ける負債・これが覆るとしたら）に落とし込んだ。
  **技術的な事実確認（`compare`/`retrieval` が何を回しているか・`compare.json` の
  `llmMode`/`embeddingMode`・`factStatementSurvived` の定義）はこの ADR の作業者が
  `examples/chat/src/compare.ts`・`scenario.ts`・`retrieval-quality.ts`・`probe-set.ts`
  を実際に読んで検算した【現物】。**
- **他に ADR 0022 決定2 を前提にしている記述**は `docs/`/`examples/`/`packages/`/`.github/`
  を横断した（`grep -rn "0022"`）。`examples/chat/README.md` に3箇所、`.github/workflows/ci.yml`
  に1箇所（`retrieval-quality` ジョブの説明。現在形の「擬似だから」主張ではなく、ADR 0022 の
  歴史的な記述の引用であり訂正不要と判断した）見つけた。README の3箇所は本 PR で
  追記して更新した（PR 本文参照）。他のファイルに現在形で「`compare` は擬似 provider
  だから質を主張しない」と書いている箇所は見つからなかった。
