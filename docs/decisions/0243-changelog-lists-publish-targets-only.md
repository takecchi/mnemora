## 問い

**`CHANGELOG.md` の「利用者に見える変更だけを載せる」の「利用者」とは誰か。**

【現物】同ファイルの「何を載せるか」節は、**載せない**ものを4つ挙げている（docs のみ・
内部スクリプト・ADR 索引の再生成・テスト追加のみ）。⛔ **だが「どのパッケージを対象とするか」は
一度も書いていない。**

🔴 **その空白が、実際に食い違いを生んでいた。**【現物】`[0.2.0]` 節の `### Added` は
`examples/chat` の項目を2つ持っている（`memory_usage` 報告の実践 / 想起経路が連想枠を
既定で使うようになった）。⟹ **`examples/chat` は「利用者に見える」側に数えられていた。**

【現物】ところが `examples/chat/package.json` は `private: true` であり、
`scripts/publish-targets.mjs` の `PUBLISH_TARGETS` にも入っていない。
**同ファイルの冒頭コメント自身が「publish 対象と非対象（ルートの `mnemora` /
`@mnemora/example-chat`）を分ける機械的な目印は無い」と書いている。**

🔴 **そして repo の別の場所は、逆の線を引いている。**【現物】`docs/roadmap.md` は
北極星 項目5 について「**出荷物の既定が反対を向いている**」という行を持ち、逐語でこう書いている:

> `@mnemora/core` を入れた利用者が `markContested` を自分で呼ばない限り、`contested` は
> 永久に立たない。既定の振る舞いは「訂正しても古いほうが出続ける」

【現物】同文書の項目5 の行は、**その口を実際に駆動しているのが `examples/chat` の
`correction-demo.ts` であることを経路ごと辿って示している。**
⟹ ⭐ **同じ文書が「`examples/chat` が動かしているだけでは、出荷物の既定は変わらない」と
読んでいる。**⚠ **そこで引かれているのは「出荷面の内か外か」の線そのものである。**

⟹ ⛔ **同じ repo の中に、`examples/chat` について2本の線が立っている。**

## 🔴 決定

1. ⭐ **`CHANGELOG.md` が載せるのは、publish 対象パッケージの変更だけとする。**
   ⟹ **`examples/chat` の変更は載せない。**
2. **線の出所は `scripts/publish-targets.mjs` の `PUBLISH_TARGETS` とする。**
   ⛔ **本数もパッケージ名も `CHANGELOG.md` へ写さない**（`AGENTS.md`「⚠ 数を、道具と
   生成物に焼き込まない」/ [ADR 0234](./0234-bake-no-numbers-into-tools-and-artifacts.md)）。
3. **この決定の射程は `[0.3.0]` 節以降とする。**
   ⛔ **`[0.2.0]` 節の既存2項目は書き換えない**——当時の記録である（`AGENTS.md`）。
4. 🔴 **形が途中で変わったことを、`CHANGELOG.md` 自身に名乗らせる。**
   ⟹ **読む人が「載っていないのは書き漏れか方針か」を、文書の中だけで判断できるようにする。**
   ⛔ **黙って変えないこと**——それがこの決定でいちばん重い部分である。

## 根拠

**1. 同じ repo に2本の線を立てない。**

北極星 項目5 の判定が「`private` は出荷面の外」で通っている以上、`CHANGELOG` だけが
`examples/chat` を「利用者に見える」側に置くと、**同じ問い（`examples/chat` は出荷面の内か外か）に
repo が2つの答えを持つ。**⟹ **どちらが正しいかを、読む人に判断させる形になる。**

**2. 前例の重みは、規律の着地時刻で決まる。**

`[0.2.0]` の2項目は **2026-09-16 に書かれた**【実測】（`git log -1 --format=%ci v0.2.0` =
`2026-09-16`）。**v1.0.0 のスコープ判定（`private` は出荷面の外）より前である。**
⟹ **「前例が在る」ことは、その前例が現在の線と整合することを意味しない。**

**3. 書式は発明していない。**

⭕ **変えたのは「載せる対象の範囲」1つだけである。**見出し構成・項目の粒度
（1〜2行の要約＋ADR/Issue へのリンク）は `[0.2.0]` のまま据え置いた。

**4. 主観で決まる境界を1本にする。**

⚠ **この決定は、`@mnemora/testkit` の内部向けに見える追加も載せる側に倒す。**
【実測】`CassetteRecorder.lookupLLM` / `lookupEmbedding`（PR #514）・
`OutboxStoreConformanceOptions.supportsRealConcurrency`（PR #450）はどちらも
「評価ハーネスの補助」だが、**`@mnemora/testkit` は publish 対象である。**
⟹ **載せる。**「利用者への訴求が薄い」を理由に落とすと、**載るかどうかが書き手の主観で
決まることになる。**

## 採らなかった案

**(A) `[0.2.0]` の前例に揃え、`examples/chat` も載せ続ける。**
⛔ **却下。**上の根拠1（線が2本になる）。⚠ **この案は「前例に揃える」という点では強い**
——却下の理由は前例が弱いことではなく、**前例が現在の線と食い違うこと**である。

**(B) `examples/chat` を「参照実装」の別見出しで載せる。**
⛔ **却下。**⭐ **新しい見出しの発明であり、Issue #536 が逐語で禁じている**
（「⛔ 新しい書式を発明しないこと」）。⚠ **かつ、載せるかどうかの判断を1本の線から
2本へ増やす**——この ADR が消そうとしているものそのものである。

**(C) `[0.2.0]` の2項目も遡って外し、全節で線を揃える。**
⛔ **却下。**`AGENTS.md` が「当時の記録は書き換えない」と定めている。
⟹ **揃えるために記録を消すのは、順序が逆である。**

## 引き受けた負債

🔴 **1. 訂正の実演が `CHANGELOG` から辿れなくなる。**
【実測】PR #522（訂正の相手を人が明示指名する経路を本番コードから立てる）と
PR #525（訂正の根拠を `memory_events.meta.note` と `RecallResult.explain` の両方から辿れる
ようにする）は、どちらも `examples/chat/src` に実の振る舞い変更を持つが、**この決定により
`[1.0.0]` 節に載らない。**⟹ **北極星 項目5 の進捗を `CHANGELOG` だけから追うことはできない。**
⭐ **辿る先は `examples/chat` の README と ADR 0235 / 0238 である。**

⚠ **2. 「publish 対象か」は機械では判定できない。**
【現物】`scripts/publish-targets.mjs` の冒頭コメント自身が「機械的な目印は無い」と書いており、
`PUBLISH_TARGETS` は手で保守された一覧である。⟹ ⛔ **この線は歯になっていない。**
新しいパッケージが増えたとき、`CHANGELOG` の書き手はその一覧を自分で引く必要がある。

⚠ **3. `[0.2.0]` と `[0.3.0]` 以降で、同じファイルが2つの範囲を持つ。**
⟹ **決定4（名乗らせる）はこの負債を消さない。読む人に見えるようにするだけである。**

## これが覆るとしたら

- **`examples/chat` が publish されるようになったとき。**⟹ 線はそのままで、
  `PUBLISH_TARGETS` が変わるだけである。**この ADR を書き換える必要は無い。**
- **オーナーが「`CHANGELOG` は repo の変更全体を追う文書である」と決めたとき。**
  ⟹ 🔴 **それは方向そのものの変更であり、クローンの判断では覆せない**（冒頭のバナー）。
- **北極星 項目5 の判定が「`private` でも出荷面の内」へ変わったとき。**
  ⟹ 根拠1 が消えるので、この ADR も見直す。

## 確かめていないこと

- ⛔ **`examples/chat` の変更が `CHANGELOG` から消えることで、実際に誰が困るかは測っていない。**
  上の「引き受けた負債1」は構造からの推論であって、実際の読み手の観測ではない。
- ⛔ **`[0.2.0]` の2項目が当時の判断としてどこまで意識的だったかは確かめていない。**
  根拠2 は **時刻の前後**だけを根拠にしており、書いた人の意図は読んでいない。
- ⛔ **`markContested` の呼び出し箇所を、この作業では自分で走査していない。**
  上の【現物】は `docs/roadmap.md` の記述を読んだものであって、**ソースに当て直してはいない**
  （同文書は `rg` の結果を根拠として載せているが、それを再導出していない）。
