# ADR 0700: `recall()` の `timeWeighting` の既定を `eventAwareFreshness` にする——ADR 0300 §7 のオーナー判断（Issue #2106）

- **状態**: 採用 (2026-11)
- **日付**: 2026-11-10

**既定を変えるのはオーナーの判断である。** 2026-11-10、対話セッションで担い手（Claude Code）が「既定を変えるほうがいい」と推奨し、利用者が逐語で「変える。でお願いします」と答えた。回答者は、同じセッションで PR #2105 を `takecchi`（オーナー）のアカウントでマージした本人である。ただし、オーナー本人かどうかをセッションの中から確かめる手段は無い（[ADR 0220](./0220-issue-comment-author-does-not-distinguish-owner-from-agent.md)）。⟹ **オーナー本人でなかったと分かったら、この ADR は根拠を失う。**
出所の区別: 【現物】は読んだコード・文書、【実測】は手元で走らせた結果、【判断】は担い手の判断。

**⚠ この ADR の番号は仮である。** マージの直前に `node scripts/adr-renumber.mjs` が確定する（[ADR 0179](./0179-adr-number-assigned-at-merge.md)）。

## 文脈

[ADR 0300](./0300-time-weighting-policy-opt-in.md) は `RecallQuery.timeWeighting` を足したが、既定は `"legacy"` のままにした。§7 は、既定を新方針へ倒すかどうかを**オーナー判断として開いたまま**残した。挙げた理由の1つが「本 ADR が実測したのは『動くこと』であって『良くなること』ではない」で、「実 embedding・実運用規模のベンチが要る」としていた。【現物】

[ADR 0699](./0699-long-horizon-recall-bench.md) の `long-horizon` ベンチ（180日の時間軸。雑談 2,700件と事実 22件）が、その材料の一部になった。【実測】

## 何を決めたか

1. **`DEFAULT_TIME_WEIGHTING_POLICY` を `"eventAwareFreshness"` にする。** `timeWeighting` を渡さない `recall()` は、`occurredAt` を持たない記憶の `freshness` を 1 に固定する。`occurredAt` を持つ記憶の式は変わらない。
2. **`"legacy"` は残す。** 明示すれば、既定を変える前の省略時と1バイトも変わらない結果になる。戻す口は既に在る（ADR 0300）。
3. **🟡（後方互換だが挙動が変わりうるもの）に数える。** 型・シグネチャは変わらず、新しく断る入力も無い。変わるのは `timeWeighting` を渡さない呼び出しの順位と、閾値を割る記憶の集合である。ADR 0300 の「これが覆るとしたら」が、この変更を `docs/migration-v1.md` の 🟡 節に足すと書いていた。⚠ ADR 0300 §7 は「`v2.0.0` 側で検討する変更の候補」とも書いていた。**版を決めるのはオーナーである。**この ADR は版を決めない。
4. **既定を縛る歯の向きを逆にする。** 「省略時は legacy と1バイトも変わらない（既定不変の歯）」は、「省略時は `eventAwareFreshness` と1バイトも変わらない」と、陰性対照「省略時は `legacy` と一致しない」に変えた。`recordedAt` へのフォールバックそのものを見る歯（ADR 0036 の頭打ちなど）は、`timeWeighting: "legacy"` を明示して、何を見ているかを変えない。
5. **`examples/chat` の測定の前提を縛る歯2本も、新しい既定の形に向け直す。**
   - `retrieval-quality.postgres.test.ts` の ADR 0109 の歯: 以前の前提は「既定では `decay === freshness` が全行で厳密に等しい（`total = similarity × decay²`）」だった。いまは「`occurredAt` を持たない記憶の `freshness` が全行で 1（`total = similarity × decay`）」である。「時間項が順位を動かさない」という歯の目的は変わらない。
   - `time-term.postgres.test.ts` の対照 probe `absent`（両方とも `occurredAt` が無い）: `freshness ≈ decay` を見ていたものを、`freshness === 1` に変えた。
   - どちらも、既定を `"legacy"` に戻す変異で赤くなり、戻すと緑に戻ることを実測した。

## 判断の材料【実測】

`long-horizon` を埋め込みだけ OpenAI（`text-embedding-3-small`、実 API）に替えて、手元で1回走らせた（2026-11-10、534秒）。記憶は抽出 LLM を通さず直接書く（ADR 0699 と同じ）。常用の事実8件が、既定の `recall()` に返った件数:

| 条件 | 7日 | 30日 | 45日 | 60日 | 90日〜180日 |
|---|---|---|---|---|---|
| A legacy・使用報告なし | 8/8 | 2/8 | 0/8 | 0/8 | 0/8 |
| B legacy・使用報告あり | 8/8 | 5/8 | 3/8 | 1/8 | 0/8 |
| C eventAware・使用報告なし | 8/8 | 6/8 | 3/8 | 1/8 | 0/8 |
| D eventAware・使用報告あり | 8/8 | 8/8 | 8/8 | 8/8 | 8/8 |

- **legacy は、使用報告を配線しても90日までに全部が返らなくなった。** 落ちる理由は、まず順位（30日目）、次に閾値（45日目。既定値からの見立ては34〜46日）、150日目からは忘却ゲートである。
- **180日もったのは D だけ**（全時点で診断順位1位）。`eventAwareFreshness` だけでは足りず、使用報告と組み合わせて初めて効いた。
- 一度も話題に出ない事実は、D でも90日目に 0/8 だった（下の「引き受けた負債」）。
- 埋め込みが `local`（ADR 0699 の CI の値）だと、7日目から gold が順位で負けるため、使用報告が一度も送られず、条件の差が出なかった。⟹ 判断には OpenAI 埋め込みの結果を使った。

⚠ 合成データで、標本は種類ごとに6〜8件である。成功率は主張しない。測っているのは出典への到達で、回答の正しさではない。

## 引き受ける取り引き

**`eventAwareFreshness` は、`occurredAt`・`validFrom`・`validUntil` のどれも持たない記憶を、一律に「恒常的な事実」として扱う。**抽出が日付や期限を構造化できなかった古い予定まで、`freshness` を 1 に固定して持ち上げる。ADR 0300 §6.4 の実 API 評価では、そういう古い予定が `recall()` の最上位に来た。回答が誤るかどうかは、回答のプロンプトが `occurredAt` の有無をどう見せるかで変わった。【現物】

【判断】それでも既定を倒す。legacy の誤り（使われ続けている恒常的な事実が、1〜2か月で既定の `recall()` から消える）のほうが、北極星の物差し「会話ログを全部積むのをやめられたか」を直接損なうからである。古い予定を持ち上げる誤りは、期限（`validUntil`）を構造化できれば validity ゲートが落とす。これは `timeWeighting` に関係なく効く（ADR 0300 §8 変異(c)）。

## 採らなかった案

- **既定を legacy のまま、README で `eventAwareFreshness` を勧める。** 入れたままの利用者が、1〜2か月で記憶を失う。担い手はこの案を推奨せず、オーナーが既定を変えると決めた。
- **テナント設定にする（ADR 0300 §4.1(B)）。** 恒久設定の口が増える。テナントごとに選ぶ理由が今は無い。
- **`recall()` が返した記憶を自動で使用報告する。** D の効果を既定で得られる。だが「返した」と「実際に使った」を区別しなくなり、`memory_usage` の意味が変わる。採らない。

## 引き受けた負債

- **一度も話題に出ない事実は、`eventAwareFreshness` でも約90日で返らなくなる。** アレルギーのように「めったに話題に出ないが忘れてはいけない」記憶は、`decay`（使用の新しさ）で沈む。半減期の既定（720時間）と、減衰させない記憶の扱いは、この ADR では変えない。
- **`default_half_life_hours` を設定する公開の口が無い。** 利用者が半減期を延ばす手段が無い。
- **測定ジョブの基準値。** 既定に依る測定の数字が動いたら、CI の artifact から採り直す（ADR 0121）。少なくとも `time-term` の基準値（`examples/chat/time-term-baseline.json`）の `absent` probe は、`freshness` が約0.999999997から1へ動く。門ではないので、この PR では採り直していない。
- **ADR 0109 の見出し（`total` は `similarity × decay²` に一致する）は、既定では成り立たなくなった。** ADR 0109 は当時の記録なので書き換えない。

## 確かめていないこと

- OpenAI 埋め込みの `long-horizon` を CI で走らせていない（手元の1回だけ）。
- 抽出 LLM を通した E2E（段階2）の結果は、この ADR を書いた時点ではまだ出ていない。
- 実運用の記憶の分布で、`occurredAt`・validity 列を欠く記憶がどれだけあるか（ADR 0300 §9 と同じ）。

## これが覆るとしたら

- 回答者がオーナー本人でなかったと分かったとき。
- 実運用規模の測定で、`eventAwareFreshness` が古い予定を持ち上げる誤りのほうが、legacy の埋没より重いと分かったとき。
- 抽出が `occurredAt` を恒常的な事実にも埋めるようになったとき（ADR 0300 の「これが覆るとしたら」の2つ目と同じ）。
