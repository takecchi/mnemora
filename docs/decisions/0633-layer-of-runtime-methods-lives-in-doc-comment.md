# ADR 0633: `Runtime` のメソッドの層の正本を doc コメントの `層:` 行にし、3文書からメソッド名の列挙を外す（Issue #605）

## 文脈

- 【現物】README.md・docs/vision.md・docs/architecture.md の「中核を守る3つの層」の節は、`Runtime` の
  メソッド名を層ごとに列挙し、そのうえで「`findCorrectionCandidates` と `applyCorrection` はどの層にも
  置かれていない」と書き、判断の置き場として [Issue #605](https://github.com/takecchi/mnemora/issues/605)
  を3文書それぞれ2箇所で指していた（ADR 0268 が #518 から #605 へ付け替えた）。
- 【実測】`gh issue view 605` は `state: CLOSED`・`stateReason: COMPLETED`（2026-09-26T11:27:26Z）。
  **3文書は閉じた Issue を判断先として指していた。**
- 【現物】ADR 0244 の決定1は、3文書が中核以外の全メソッド名を `` `name` `` の形で並べていることを歯
  （`runtime-method-doc-correspondence.test.mjs` の it4）で縛った。ADR 0268 は3文書のポインタが一致していること
  を歯（`living-doc-judgment-pointer-consistency.test.mjs`）で縛った。
- 【現物】名前の列挙は、メソッドが増えるたびに3文書3箇所を直す作業を生み、その分類は ADR 0171 の時点のまま
  腐ってきた（ADR 0244 の経緯、#605 本文）。

## 決定

1. **層の正本を、`packages/core/src/runtime.ts` の `export interface Runtime` の各メソッドの直前の JSDoc の
   `層: <値>` の1行にする。**値は `中核` / `保守操作` / `是正・取り消し` / `説明` / `未分類` の5種。
   公開の型・シグネチャは変えない（コメントの追加だけ。実装 `createRuntime` 側には足さない）。
2. **歯 `scripts/__tests__/runtime-method-layer-line.test.mjs` を足す。**各メソッドの直前の JSDoc に、
   `^\s*\*\s層: (中核|保守操作|是正・取り消し|説明|未分類)\s*$` に当たる行がちょうど1行あること。
   加えて、`層` + 半角/全角コロンで始まるのにこの形に当たらない行が1行でもあれば赤（正しい行が隣に在っても赤）。
   判定は純関数 `checkLayerLines` で、fixture による陽性対照・陰性対照を置く（別メソッドの層の行・全角コロン・
   `不明`・`中核 です`・JSDoc 外の `// 層: 中核`）。**層の値が意味として正しいかは見ない。**
3. **3文書から、メソッド名の列挙と #605 への言及を外し**、層の定義（保守操作・是正取り消し・説明の性格）だけを
   残す。代わりに「正本は各メソッドの doc コメントの `層:` 行」「`未分類` は判断が割れているもので1本ずつ決める」
   「この ADR」へのリンクを書く。個数は書かない。中核5動詞の名前は docs/vision.md に残す（ADR 0244 の it1 が見ている）。
4. **ADR 0244 の決定1を一部覆す。**3文書がメソッド名を並べることは求めない。it4 は外し、「メソッドが文書のどこにも
   出ない穴」の役目は新しい歯が引き継ぐ（新しい口は層の行が無ければ赤）。it1・抽出の it・陽性対照・
   「3文書が空でない」は残す。ADR 0244 の決定2〜7は覆さない。
5. **ADR 0268 のポインタ歯は削除する。**3文書が #605（や他の Issue）を判断先として指さなくなり、歯は取れる番号が
   無く空回りする（空回り防止の it が落ちる）。対象が無くなったことを確かめる形には変えなかった——閉じた
   Issue を再び指すことを禁じる検査は、判断先を「Issue」から「コメントの行」へ移した後は、検査する値打ちのある
   不変条件を持たないと判断した。ADR 0268 の本文は触らず、末尾に追記だけを足す。

### 5本の `未分類`

`未分類` = `tick` / `reextract` / `restoreSuperseded` / `applyCorrection` / `findCorrectionCandidates`。

- 【現物】`tick` / `reextract` / `restoreSuperseded` / `applyCorrection` の4本は、#605 のコメント
  （2026-09-23）が「両論あり」として挙げたもの。⚠ 同じ再検算を書いた ADR 0275（状態「提案」）は `tick` と
  `reextract` を「一致」と判定しており、#605 のコメントとは読みが違う——その食い違い自体が、判断が割れている
  ことの現れとして `未分類` に入れた。`applyCorrection` は3文書も未配置としていた。
- 【現物】`findCorrectionCandidates` は、3文書が「どの層にも置かれていない」と書いていたもの（書き込まない口なので
  「是正・取り消し」ではない、とだけ言っていた）。
- ⟹ 5本は「#605 コメントの4本」と「3文書が未配置としていた `findCorrectionCandidates`」の和である
  （`applyCorrection` は3文書でも未配置とされていたが、#605 の4本に入っているので重ねて数えない）。割り振りは担い手の暫定で、**あとで1本ずつ決める**。
  それ以外の15本は、3文書が既に書いていた層をそのまま写した（中核5・保守操作2・是正・取り消し7・説明1。
  3文書の旧「保守操作」の列挙から `tick` と `reextract` を `未分類` へ、「是正・取り消し」から
  `restoreSuperseded` を `未分類` へ移した）。
- 【現物】歯は値が5種のどれかであることしか見ないので、`未分類` を他の値へ書き換えても歯は緑のはずである
  （歯の正規表現を読んだ判断であり、書き換えて走らせてはいない）。決め直しは1行の編集で済む。

## 採らなかった案

- **層ごとに interface を分割する案**（`Runtime` を中核・保守・是正・説明の interface に分けて合成する）。層が型に
  現れるが、**公開型の変更**であり `pnpm api:check` に差分が出る。層の判断が割れているもの（5本）を置く先が無い。
- **現状維持（3文書の列挙と #605 のポインタを保つ）**。閉じた Issue を指し続け、メソッド追加のたびに3文書を直す。
- **層の値を歯で縛る（メソッド名→層の表を歯に持つ）**。名前と層の写しが歯と doc コメントの二重になり、
  AGENTS.md の「複製した瞬間から腐る」に当たる。意味の判定は機械に決まらない（ADR 0244 決定5）。
- **ポインタ歯を「#605 を指していないこと」の検査に変えて残す**。上の決定5のとおり。

## 引き受けた負債

- 層の値が意味として正しいかを見る歯は無い（誤配置は緑）。レビューに残る。
- 3文書を読むだけでは、どのメソッドがどの層かが分からない。`runtime.ts` を開く必要がある。
- `未分類` の5本は決めていない。放置すれば `未分類` が定着する（歯は `未分類` を許す）。
- 歯は interface のメソッド宣言が行頭2スペース・直前の行が `*/` で終わる形であることに依存する。
  宣言の書式が変わると、層の行が在っても「直前に JSDoc が無い」で赤になる（偽陽性側。直す手がかりは失敗メッセージに出る）。
- ADR 0244 の it4 が見ていた「3文書にメソッド名が出ている」は、3文書が列挙を持たなくなったので見ていない。
- 3文書の相対リンク `ADR 0633` は `doc-reference` の歯が届くことを見る。

## これが覆るとしたら

- 層の値が `未分類` 以外で割れ続け、意味の判定を機械側へ寄せたくなったとき（歯で値を縛る案を再検討）。
- `Runtime` の層ごとの分割を公開型の変更として受け入れる判断がされたとき（その interface が正本になる）。
- doc コメントの書式（宣言行・JSDoc の形）が変わり、歯の抽出規則を保てなくなったとき。

## 測ったこと / 確かめていないこと

**測ったこと**【実測】:
- 歯だけを足した commit では、20本すべてが「層の行が無い」で赤。層の行を足した後は緑。
- 変異試験（PR #1736 の本文の表）: 1本の層の行を消す・全角コロン・値を `不明`・同じメソッドに2行、は本体の it が赤。
  判定を「interface 全体に `層:` が1つでもあれば通す」に緩めると陰性対照 (a) などが赤、正規表現を `層[:：]\s*\S+` 相当に
  緩めると陰性対照 (b) が赤。崩れた形の行の検査を外すと陰性対照 (b) が赤、`getRecall` の正しい行の隣に
  `層：保守操作` を足すと本体の it が赤。各々 `cp` で戻して緑に戻ることを確認。
- `pnpm api:check` の差分0（コメントのみの変更）。

**確かめていないこと**:
- 5種の値を割り振った意味の正しさ（旧3文書の分類を写しただけで、再検算していない）。
- 各 package の README など、3文書以外に同じ列挙・#605 ポインタがあるかは `grep -rn '605' --include=*.md . | grep -v docs/decisions` の当たった範囲のみ（`docs/release-v1.md` の sha 内の文字列を除き、当たりは3文書だけだった）。
