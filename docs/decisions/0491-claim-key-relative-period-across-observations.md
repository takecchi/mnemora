## 草稿の要点（器の入れ替えで文脈が失われても引き継げるように、先に書く）

- **Issue #1436 が開いている理由**【現物】: 本文「決める人」は「方針はクローン miku が決める。既定の経路の抽出プロンプトを変える場合は、カセットの録り直しになる（実 API の鍵は 2026-09-29 に返した。録り直すなら改めて借りる）」。コメントは 0 件。
- **症状**: 「去年は札幌で働いていた」「今年は福岡で働いている」のように、相対的な期間だけが違う正しい 2 主張が、**別々の `observe()`（別々の observation）**で届くと、claim key が揃って contested になりうる。ADR 0324 決定4 の有効期間の重なり判定は `validFrom`/`validUntil` を見るが、「去年」「今年」はどちらの抽出でもこの欄に入らず、どちらも null（＝重なる）なので弾けない。同じ observation の兄弟どうしは PR #1424（ADR 0377）が塞いだ。別 observation は対象外のまま。
- **選択肢**（Issue #835 のコメント〔2026-09-27〕の U2 の表）:

  | 案 | 中身 | 既定の経路 | カセットの録り直し | 取りこぼし・副作用 |
  |---|---|---|---|---|
  | (a) | 抽出で、相対的な時期（去年・今年）を `validFrom`/`validUntil` に入れる | 変わる（抽出プロンプト） | 要る（抽出を含むカセット全般、実 API） | 相対時期の解釈は観測日時に依存し、誤った期間が入ると本物の訂正が期間違いで弾かれうる。北極星の物差しが動きうる |
  | (b) | 既定の claim key のプロンプトに「時期の違う主張は別の predicate にする」を足す | 変わる（claim key プロンプトの既定の文言） | 要る | 「言い換えを統合する」指示と衝突し、訂正（`negation-moved-job` など否定を伴うもの）を取りこぼす恐れ。v1・案A で観測済みの失敗の形 |
  | (c) | 何もしない | 変わらない | 要らない | 誤検出は残る |

- **振り分け**【判断】: (a)(b) は既定の経路の抽出・claim key プロンプトの文言を変える**既定値の変更**で、カセットの録り直しと実 API の鍵（オーナー）が要る → **オーナーの領分**。(c) を選ぶなら内側。ただし**この限界が `detectContested` の TSDoc に書かれていない**。
- **TSDoc の現状**【現物】: `packages/core/src/claim-key.ts` の `detectContested`（384〜405 行付近）は、同じ observation の兄弟の「去年は札幌…今年は福岡…」を ADR 0377 の修正として書き、末尾に「**別の observation（別ターン）どうしの対（訂正の典型形）は今までどおり contested になる**」と書く。つまり別 observation どうしが contested になること自体は書いてあるが、**訂正の典型形という良い向き**にしか書かれていない。「期間だけが違う正しい 2 主張が別ターンに分かれると contested になる（相対的な期間が `validFrom`/`validUntil` に入らないため）」という限界は書かれていない。
- **内側の直し**: (1) `detectContested` の TSDoc に、その限界を今の振る舞いとして足す（(a)(b) はオーナーの判断待ち、Issue #1436）。(2) 歯: 別々の observation から「去年は札幌」「今年は福岡」に当たる 2 件（同じ鍵、有効期間がどちらも null）を作り、contested になることを縛る。陽性対照は、同じ observation の兄弟では contested にならない既存の歯（`claim-key-same-observation-not-contested.test.ts`）。作れなければ、ADR 0324 決定4 の今の振る舞い（有効期間が両方 null の 2 件は重なりとみなされる）として縛る。実装・プロンプトは変えない。
- **Issue は閉じない**: 直し方 (a)(b) の選択はオーナーの判断待ち。
