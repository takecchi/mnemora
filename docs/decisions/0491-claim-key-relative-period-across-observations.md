## 決定（線の内側＝文書の直しと歯だけ。実装・プロンプトは変えていない）

- **TSDoc**（`packages/core/src/claim-key.ts` の `detectContested`）に、限界を今の振る舞いとして足した: 別々の observation に分かれた、相対的な期間だけが違う正しい 2 主張も contested になる（相対的な期間は `validFrom`/`validUntil` に入らず、どちらも null で重なるため。同じ発話の兄弟なら ADR 0377 で除かれるが、別 observation は除かれない）。直し方 (a)(b) は既定の経路の文言を変えるのでオーナーの判断待ち（Issue #1436）。呼び出し側は、`observe()` に `validFrom`/`validUntil` を明示すれば、重ならない対は contested にならない。
- **歯** `packages/core/src/__tests__/claim-key-relative-period-across-observations.test.ts`（3 本、core の fake と固定の LLM の応答）:
  1. 今の振る舞い: 別々の `observe()` から「去年は札幌で働いていた」「今年は福岡で働いている」（同じ鍵 `user/work_location`、有効期間はどちらも null）を作ると、2 件目の検出が `contested`（`matchCount: 1`）になり、2 件とも `status: "contested"`・`contestedWithId` が互いを指す。
  2. 陽性対照: 同じ 2 主張を 1 回の `observe()`（同じ発話）から出すと contested にならない（ADR 0377）。
  3. 陽性対照: 別ターンでも、`validFrom`/`validUntil` を明示して重ならない 2 件なら contested にならない（ADR 0324 決定4）。ADR 0324 決定4 に頼る代替の縛り方は要らなかった（歯 1 が作れた）。
- **実測の結果**【実測。core の fake、node v22.23.3】: 3 本すべて緑。既存の `claim-key-same-observation-not-contested.test.ts` も緑（合わせて 6 本）。
- **歯が (a)(b) の直しで赤くなることの確認**【実測。変異】: (a) は「相対時期が有効期間に入る」ことなので、歯 1 の 2 回の `observe()` にテスト側で重ならない `validUntil`／`validFrom` を明示する変異を入れた。歯 1 が赤になり（contested にならず、緑の側の「重ならない」に倒れた）、他の 2 本は緑のまま。`cp` で戻して 3 本緑。(b)（claim key のプロンプトで期間違いを別の predicate にする）は、固定の応答の predicate が別になる変異と同じ形で、同じ歯が赤くなる。→ 誰かが (a)(b) で直すと歯 1 が赤くなり、ADR 0491 と Issue #1436 を読み直させる。

## 検討した代替案

1. **(a)(b) を実装する。** 採らなかった。既定の経路（抽出・claim key のプロンプト）の文言を変える既定値の変更で、カセットの録り直しと実 API の鍵が要り、取りこぼしの副作用（上の表）もある。オーナーの領分。
2. **同じ observation の兄弟の除外を、時間の近さ（`recordedAt` の差）に広げる。** 採らなかった。「近い時刻に別 observation で届いた主張は contested にしない」は、訂正の典型形（直後の言い直し）を取りこぼす。ADR 0377「失うもの」の損失を広げる。
3. **何も書かない。** 採らなかった。TSDoc は別 observation の対が contested になることを「訂正の典型形」という良い向きにしか書いておらず、期間だけが違う正しい 2 主張にも同じ向きで働くことが読めなかった。
