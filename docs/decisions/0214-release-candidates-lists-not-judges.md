# ADR 0214: リリース当日に「載せるべき候補」をその場で出す道具 — ⛔ 判定ではなく一覧である

- **状態**: 採用 (2026-09)
- **日付**: 2026-09-17

**⚠ 各主張の出所を分ける。**「私が実行して確かめた」と「受け取った前提」を混ぜない。

---

## 文脈

**リリースの当日、人が数える仕事が1つ残っている。**

`CHANGELOG.md` は冒頭で逐語こう宣言している:

> このファイルは [Keep a Changelog](https://keepachangelog.com/) の形式に倣う。**手で書く**（tag や commit ログからの自動生成ではない）。

理由は [ADR 0169](./0169-changelog-hand-curated.md) に在る。⟹ **自動生成は採らない。**

そして `[1.0.0]` 節は、自分が腐ることを自覚して書かれている（逐語）:

> ⭐ **数えた基準を明記する。**この節の数字は `v0.2.0` … **`4b92134`** の範囲を数えたものである。⟹ 🔴 **`origin/main` がこれより進んでいたら、この節は腐っている可能性がある**——読む人が `git log --oneline 4b92134..origin/main` で自分で判定できる。

⟹ **手順は文章で書いてある。道具が無いだけである。**

**そして腐りは実際に起きている**【実測】2026-09-17、`origin/main` = `a7b7ff1` の時点:

- `git rev-list --count 4b92134..HEAD` = **34**
- `git rev-list --count v0.2.0..HEAD` = **70**
- 🔴 **`b84f120`（`feat(local-embedding)!: LocalEmbeddingPipeline を必須 interface にする`）は確定的な破壊的変更だが、`CHANGELOG.md` に未収録である**（`grep -c "LocalEmbeddingPipeline" CHANGELOG.md` = **0**）

## 🔴 測ったこと: この repo は、破壊的変更を機械的に見分けられない

**着手前に、`v0.2.0..origin/main`（70 commit）の確定的な破壊的変更を全部数え、それぞれがどの信号に掛かるかを1件ずつ当てた**【実測】:

| sha | `!` | 本文に「破壊的」/BREAKING | 公開 API snapshot | 出所 |
|---|---|---|---|---|
| `c4a3dc7` | ✗ | ✗ | ✗ | `CHANGELOG.md` の「変更（破壊的）」節に載っている |
| `2097a72` | ✗ | ✓ | ✗ | 本文が逐語「## 🔴 破壊的変更」 |
| `855286a` | ✗ | ✓ | ✓ | 本文が逐語「## 破壊的変更について」 |
| `b84f120` | ✓ | ✗ | ✓ | subject に `!` |

- 🔴 **`!` だけを見る道具は、4件中3件を取りこぼす。**
- 🔴 **`BREAKING CHANGE:` / `BREAKING-CHANGE:` フッタは、repo 全履歴（315 commit）で1件も使われていない。**⟹ conventional commits の標準どおりに実装しても、この repo では何も拾えない。
- 🔴 **`c4a3dc7` は、上の3つの印をどれも持たない。**

⚠ **明文の commit 規約は見つからなかった。**`AGENTS.md` にも `docs/` にも「conventional commits を使う」という記述は無く、`.github/` に PR テンプレートも `CONTRIBUTING.md` も無い。[ADR 0070](./0070-version-comes-from-the-release-tag.md) が「これが覆るとしたら」で逐語「**Changesets か conventional commits の規約が要る**」と将来条件として書いており、**これは「採用した」ではなく「採用していない」ことの裏付けである。**`feat(scope)!:` の書式は**実践上の慣習であって、明文の規約ではない。**

## 決定1: 作る。ただし **⛔ 判定ではなく「候補の一覧」として作る**

`node scripts/release-candidates.mjs [--since <tag>] [--json]`。

**上の実測が、この形を強制している。**どの信号の組み合わせを採っても取りこぼしはゼロにならない ⟹ **「これが破壊的変更の全部です」と名乗れる道具は作れない。**名乗れないものを名乗ると、**次の人がそれを信頼する。**

⭐ **だから出力の末尾に、取りこぼした実例そのものを名指しで出す**（下の決定3）。

## 決定2: **母集合を出す。候補だけを出さない**

範囲内の commit を**全部**出し、信号が付いたもの（`bang` / `body-breaking` / `public-api` / `src`）と付かなかったものの**両方**を表示する。

**理由は `c4a3dc7` である。**⛔ **「探す」形にすると、印を持たない破壊的変更は構造的に見えない。**⟹ **母集合を落としてから印を当てる**形にした。

信号は**読む順番**であって**判定**ではない。⟹ 純関数側に、**信号が1つも立たない commit が分類結果から落ちないこと**を検査する歯を置いた（`scripts/__tests__/release-candidates-lib.test.mjs`）。**この歯の doc コメントに `c4a3dc7` を根拠として書いてある**——なぜこの歯が要るかが、歯だけを読んで分かるようにするため。

## 決定3: **信号の外し方を、両方向とも出力に焼く**

末尾の警告は、**取りこぼす側と余計に拾う側の実例を、sha 付きで名指しする**【実測】:

- **取りこぼす側（高い）**: `c4a3dc7` は `CHANGELOG.md` の「変更（破壊的）」節に載っているが、`!` も本文の「破壊的」も公開 API snapshot の変更も持たない——**粗い `src`（出荷される `packages/*/src` を触ったか）にしか掛からない。**⟹ ⛔ **信号が `src` だけの commit を「印が無いから安全」と読まないこと。**
- **余計に拾う側（安い）**: `e1c0793` は本文が逐語で「**（任意フィールドなので破壊的変更ではない。）**」と書いているのに `body-breaking` が立つ——**語を見ているだけで、否定文を読み分けない。**

⚠ **当初この警告は「`c4a3dc7` はどの信号にも掛からない」と書こうとしていた。⛔ それは誤りである**——4つ目の信号 `src` には掛かる。**実装を実際に走らせて分かった**（実装を担当した個体が指摘した）。⟹ **根拠が結論を支えていない警告を出荷しかけた。**この節はその訂正の記録でもある。

## 決定4: **数字も tag も repo 名も焼き込まない**

起点は `gh release view --json tagName` でその場で取り、失敗したら `git describe --tags --abbrev=0` へ落ちて、**落ちたことを出力に明記する。**repo 名も `gh repo view` / `git remote get-url origin` から導く。

**理由**: [ADR 0070](./0070-version-comes-from-the-release-tag.md) が「版は Release の tag が決める」と定めており、**道具側に版や tag を持たせると二重の真実になる。**そして**焼き込んだ数字は腐る**——この ADR の文脈そのものが、腐った数字の実例（`4b92134`）から始まっている。

## 決定5: **`CHANGELOG.md` を書き換えない。鮮度を名乗らせる**

道具は `CHANGELOG.md` から基準 sha を読み取り、`git rev-list --count <sha>..HEAD` を出して「**CHANGELOG はここまで数えている／HEAD はそこから N commit 先**」と表示する。⛔ **書き換えない。**

**理由**: ADR 0169 が「手で書く」と決めている。**数字を直しても、次の commit でまた腐る。⭐ 腐らないのは「どこまで数えたか」の宣言のほうである。**⟹ 道具の役目は、**その宣言と現在地の差を毎回言わせる**ことに留める。

読み取れなければ「読み取れなかった」と出す（例外にしない）。

## 決定6: **CI に配線しない。終了コードは常に 0**

**これは歯ではなく道具である。**当日、人が打つ。⟹ `.github/workflows/` に一切触っていない。候補が在っても `0` で終わる——**非0 で落とすと門になり、門になった瞬間「これが全部だ」と主張したことになる**（決定1 で名乗れないと決めたことである）。

⚠ **`scripts/__tests__/` に純関数の歯は置いた。**これはルートの `test` から走る。⛔ **「道具を CI が実行する」ことと「純関数に歯を置く」ことは別である**——後者は `scripts/` の全 `-lib.mjs` が従っている作法であり、こちらだけ外す理由が無い。

## 検討して採らなかった案

1. **CHANGELOG を生成する。** 却下。ADR 0169 が「手で書く」と決めている。**規律と正面から衝突する。**
2. **conventional commits の規約を明文化し、`!` / `BREAKING CHANGE:` を必須にする。**却下（この ADR では）。⭐ **筋は悪くない**——それが在れば道具は判定になれる。**しかし既に着地した70 commit は遡って直せない**ので、当日の問題は解けない。そして規約の新設は製品の運用の判断であり、**この ADR の射程を超える。**⟹ `docs/roadmap.md` §5 級の提起としては残しうる。
3. **公開 API snapshot の差分だけを見る。**却下。`check-public-api-surface.mjs` の doc コメントが逐語で「⛔ **『変わった』ことだけを検出する。『壊れているか』（semver 的に安全かどうか）は判定しない**」と書いており（ADR 0178）、**`c4a3dc7` は snapshot を1バイトも動かしていない。**
4. **当日の手順書に `git log` のコマンドを1行書くだけにする。**却下。⭐ **既にそうなっている**（`CHANGELOG.md` が `git log --oneline 4b92134..origin/main` と書いている）**のに、`b84f120` は落ちた。**⟹ 生の `git log` は70行を人に渡すだけで、**どれを見るべきかを何も言わない。**
5. **`--json` を持たせない。**却下。当日の出力を別の道具や報告へ回す余地を残した。⚠ **その先の使われ方は検証していない**（下記）。

## 引き受けた負債

1. 🔴 **取りこぼしはゼロにならない。**決定1 のとおり、これは設計の制約であって実装の不足ではない。**印を持たない破壊的変更は、人が読むしかない。**
2. **`body-breaking` は否定文を読み分けない**（`e1c0793`）。⟹ false positive が出る。**安い側の誤りなので直していない**が、件数が増えれば信号として役に立たなくなる。
3. **`src` は粗すぎる。**`packages/*/src` の doc コメントだけを直した commit にも立つ【実測】`e51e48f`（`docs(local-embedding)`）。⟹ **`src` は「出荷物に触った」以上のことを言っていない。**
4. **`gh release view` が失敗したときの分岐は、実地で発火させていない**（`try/catch` の形とコードレビューで確認したのみ）。
5. **`--json` の出力が、実際のリリースノート作成の流れで使えるかは検証していない。**
6. **`docs/release-v1.md` から参照させていない。**同ファイルは複数の担い手が同時に触っており、この PR では触らないと決めた。⟹ **当日この道具に辿り着けるかは、まだ手順書に繋がっていない。**

## これが覆るとしたら

- **conventional commits の規約が明文化されたら**（採らなかった案2）。そのときこの道具は「候補の一覧」から「判定」へ格上げしうる。⛔ **ただし格上げは、遡れない過去の commit をどう扱うか決めてからである。**
- **`CHANGELOG.md` の書き方が変わったら**（基準 sha を明記しなくなったら）、決定5 の読み取りは成立しなくなる。**そのときは「読み取れなかった」と出て、道具は静かには壊れない。**
- **信号の false positive が増えて、`withSignals` が母集合とほぼ同じになったら**、決定2 の「2群に分ける」ことに意味が無くなる。**そのときは信号の定義を見直す。**

## 確かめていないこと

- **`v0.2.0..HEAD` の破壊的変更が本当に4件で全部かは、確かめていない。**4件は「`CHANGELOG.md` に載っている」「本文が自己申告している」「`!` が付いている」のいずれかで**見つけられたもの**である。⟹ 🔴 **この ADR の表そのものが、決定1 が言っている取りこぼしの対象である。**
- **他のリポジトリ（[alteroid](https://github.com/takecchi/alteroid) 等）でこの形が通るかは見ていない。**射程は mnemora のみ。
