## 🔴 決定

1. **`CHANGELOG.md` に `[0.4.0]` 節を起こす。**中身は `[1.0.0]` に置かれていたものを移す
   ——**新しく書き起こしたのではなく、置き場所が間違っていた分である。**
2. **`[1.0.0]` の pin を `v0.4.0` … `420e0f4` へ進める。**
   ⚠ **pin は `scripts/release-candidates.mjs` の入力でもある**（[ADR 0214](./0214-release-candidates-lists-not-judges.md) 決定5）
   ——**ずれたままにすると、道具の鮮度申告まで誤る。**⛔ 道具のほうは書き換えていない。
3. **`docs/migration-v1.md` の世代を4つにする。**`v0.3.0` → `v0.4.0`（**出荷済み・6件**）を閉じ、
   `v0.4.0` → `v1.0.0`（未リリース）を起こす。項目 **12**〜**17** と `0018` の「未出荷」を訂正する。
4. **件数は、両端が tag で閉じた世代にだけ書く。**既存の規律（[ADR 0234](./0234-bake-no-numbers-into-tools-and-artifacts.md) /
   [ADR 0241](./0241-migration-guide-is-a-live-doc-not-an-adr.md)）をそのまま当てた
   ⟹ **12〜17 は「6件」と書き、`v0.4.0` → `v1.0.0` には件数を書かない。**
5. **直し方は文書の種類で分ける。**`docs/migration-v1.md` は**生きた文書**なので本文を直す
   （[ADR 0241](./0241-migration-guide-is-a-live-doc-not-an-adr.md)）。
   **`CHANGELOG.md` の過去の節（`[0.3.0]` / `[0.2.0]`）は当時の記録なので1バイトも書き換えない。**
   **`docs/migration-v1.md` の「訂正の履歴」の 2026-09-18 の記述も書き換えず、2026-09-19 の分を足した。**
6. ⛔ **3回目を防ぐ仕掛け（CI の歯・リリース手順の変更）は、この ADR では決めない。**
   ⟹ **本 ADR は現象と経緯を記録するところまでで止め、仕掛けの採否はオーナーの判断に委ねる**
   ——**リリース週に必須 CI の形を変える判断は、担い手のものではない。**

   ⚠ **隣で一度、同じ手段が却下されている。**【現物】[Issue #433](https://github.com/takecchi/mnemora/issues/433)（OPEN）は
   **別の失敗形**——「未リリース節が*数字*を焼き込んでいて、`main` が動くだけで腐る」——を扱っており、
   2026-09-17 のコメントが逐語で「**(い) 現状維持。着地済みの ADR 0214 決定6 を追認する。⛔ CI の歯は作らない**」と
   結論している（⚠ **クローンの判断であり、オーナー本人の決定ではない**と同コメント自身が名乗っている）。
   却下の芯は [ADR 0214](./0214-release-candidates-lists-not-judges.md) 決定1 の
   「**門になった瞬間、『これが全部だ』と主張したことになる**」である。
   ⟹ 🔴 **ただし #433 が却下したのは「commit ごとの内容ヒューリスティック」という述語であって、
   「出た tag に対応する節が在るか」という述語ではない。**⛔ **却下をそのまま転用しないこと。**
   ⟹ ⭐ **仕掛けを採るなら、「なぜ #433 の却下がこの述語には当たらないか」を先に書く必要がある。**

## 根拠

### なぜ「注記を足すだけ」で済まさないか

**pin は人が読む文字列であると同時に、道具が読む入力である。**
⟹ **`[1.0.0]` の pin を `434e663` のままにして「実は出荷済み」と注記だけ足すと、
`scripts/release-candidates.mjs` は引き続き「ここまで数えた」を誤って申告する。**
**文書の正しさと道具の正しさが、同じ1つの sha に乗っている。**

### なぜ世代を1つ増やすのか（＝「12 以降」を `v1.0.0` 側に残さないのか）

**利用者が読む範囲は「どの版から上げるか」で決まる。**
`v0.4.0` を使っている人にとって 12〜17 は**もう効いている**——**上げる前に直すものではない。**
⟹ **`v1.0.0` の世代に残したままだと、`v0.4.0` の利用者が「これから壊れる」と読む。**

### なぜ件数の扱いを変えないのか

**`v0.3.0` と `v0.4.0` は両端が tag で閉じており、`main` が動いてもこの6件は変わらない。**
⟹ **ADR 0234 の「焼き込むな」は当たらない**——**当たるのは、動く側（未リリース世代）だけである。**

## 採らなかった案

| 案 | なぜ採らなかったか |
|---|---|
| **`[1.0.0]` をそのままにし、「実は `v0.4.0` で出荷済み」という注記だけ足す** | 上の「根拠」のとおり、**pin が道具の入力である。**注記は道具に届かない |
| **`docs/migration-v1.md` の世代表を消し、「番号付き一覧だけを見ろ」にする** | **上げ元の版で読む範囲が変わる。**世代の区切りを消すと、利用者が「自分がどれを読むべきか」を決められない |
| **3回目を防ぐ歯を、この PR で一緒に入れる** | ⛔ **1 PR = 1 主張を破る。**そして**リリース週に必須 CI の形を変える判断**は、担い手が握ってよいものではない（決定6） |
| **`[0.4.0]` の中身を、GitHub の自動生成 Release 本文から起こす** | あれは **27 commit を無差別に並べたもの**である【実測】。⟹ **分類も、docs のみ・テストのみの除外も与えない**——`[0.3.0]` 節が同じ理由でそう書いている |

## 引き受けた負債

1. 🔴 **構造は直していない。**世代表は依然として番号付き一覧の**写し**であり、
   **3回目の腐りは、いまも起こりうる。**⟹ 決定6 のとおり、仕掛けは別途。
2. ⚠ **`[0.4.0]` 節は、出荷の後から書かれたものである。**
   ⟹ **「出荷時点でそう判断した」という記録ではない。**⭐ **その事実を節自身に名乗らせた。**
3. ⚠ **「`v0.4.0` で出荷済み」の根拠は git の祖先関係である。**
   ⛔ **公開された tarball の `dist/*.d.ts` を開いて照合してはいない**（下の「確かめていないこと」）。
4. ⚠ **`v0.4.0` の Release 本文は自動生成のままである。**⛔ **この PR では触っていない**
   ——`docs/release-notes-v1.0.0.md` は別の担い手が持っている。

## これが覆るとしたら

- **`v0.4.0` が unpublish / yank されたとき。**⟹ 「出荷済み」の判定そのものが崩れる。
  ⚠ **npm の unpublish には 72 時間の窓がある**【受】——この書き手は確かめていない。
- **「リリースが出たのに正本が追随していない」を機械が止める仕掛けが入ったとき。**
  ⟹ **本 ADR の手作業の部分は要らなくなる**（記録としては残る）。
- **件数の規律（両端が tag で閉じた世代にだけ書く）が変わったとき。**

## 確かめていないこと

- ⛔ **公開された tarball の `dist/*.d.ts` を開いていない。**「`v0.4.0` で出荷済み」は
  **git の祖先関係 + npm の版一覧 + publish run の成功**の3点から言っている。
  ⚠ **`docs/migration-v1.md` 自身が薦めている `npm pack` での照合はしていない。**
- ⛔ **テストを1本も走らせていない。**この PR は文書だけを変えており、コードに触れていない。
- ⛔ **`0018` を実際の Postgres へ適用していない**（この器に `DATABASE_URL` が無い）。
- ⛔ **項目 1〜11 は数え直していない。**触ったのは 12〜17 と `0018` の**世代の欄**だけである。
- ⛔ **`v0.4.0` を誰が・なぜ切ったのかは調べていない。**本 ADR が扱うのは「出た後に文書が追随していない」という事実だけである。
