## 文脈

**[ADR 0223](./0223-cross-cutting-disciplines-extracted-from-the-adr-corpus.md) は、ADR 211本の母集合から「繰り返し採られているのに入口の文書に書かれていない規律」を10本抽出した。**その決定2 がこれである【現物・逐語】:

> **一般形**: **歯（機械検査）の担当は「検出」までである。「確定」と「書き込み」は人に残す。そして機械が判定できなかったときは、従来どおりに倒さず赤／保留で止める。**

**⛔ そして ADR 0223 は、成文化の場所を自分では決めなかった**【現物・逐語、「⛔ 成文化の場所 —— **未決のまま残す**」節】:

> **どこへ置くかで読者が変わる。**`AGENTS.md` は人もエージェントも読む。`docs/autonomy.md` は「オーナーに逐一確認せずに進める担い手」向けだと自ら宣言している。⟹ **決定2・3・5・9 は *道具を作る側* への規律であり、そのどちらの宛先とも一致しない。**⭐ **3本目の宛先が要るのかどうかも、この ADR は決めない。**

**その未決を [Issue #505](https://github.com/takecchi/mnemora/issues/505) が引き取り、6つの決定（2/3/5/6/9/10）を1本ずつ判断することにした。**うち決定9 は既に [ADR 0234](./0234-bake-no-numbers-into-tools-and-artifacts.md)（[PR #520](https://github.com/takecchi/mnemora/pull/520)）が答えている。**この ADR は、残る5つのうち決定2 だけに答える。**

⚠ **【受】この ADR の判断そのものは、Issue #505 のコメントに先に置かれている**（逐語「## 1. 決定2 — ✅ **yes。ただし線は「repo の中か、GitHub 側の取り消しにくい面か」**」、[issuecomment-5714613359](https://github.com/takecchi/mnemora/issues/505#issuecomment-5714613359)）。⛔ **そのコメントは「クローン miku（自動化された担い手）による判定である。オーナー本人の判定ではない」と自ら名乗っている**（同コメント冒頭「**クローン miku（自動化された担い手）による判定である。** ⛔ **オーナー本人の判定ではない。**」）。**この ADR が足すのは、その判断を記録の形にすることと、下の「測ったこと」である。**

## ⭐ なぜ入口へ置くのか — 決定2 は「担い手の手の書き方」であって「道具の設計」ではない

**【現物】`AGENTS.md` / `docs/autonomy.md` には、近い版が既に1つ在る。⛔ ただし宛先が違う。**

| 在る版 | 対象 |
|---|---|
| [docs/autonomy.md](../autonomy.md) §4.1「静かに失敗する道具」の対処表——「⭐ **副作用のある手（`gh issue close`・`gh pr merge`・`git push`）を、判定と同じ行に繋がない。`if` で明示する**」 | **担い手が打つコマンドの書き方** |

⟹ 🔴 **「この repo で新しく作る道具（script・CI job）自体を、どこまで自動化してよいか」という *設計* の規律は、どちらにも無い。**ADR 0223 決定2 が「独立に採った」として挙げる7本（0199 / 0169 / 0200 / 0211 / 0215 / 0216 / 0178）は、**まさにそちら側である**【現物】——たとえば ADR 0199 は「**歯が縛ってよいのは実体から機械的に数え直せる件数・群数だけであり、性能の解釈は人間の読み物（README のプローズ）に残す**」、ADR 0211 は「**機械が直接 `gh pr edit` を打つ」案（ADR 0200 の案3…）ではなく**」「⟹ **安全側は赤。**」と、道具そのものの設計として書いている。

## 決めたこと

### 決定1. `AGENTS.md`「作業のときの決まり」に「⚠ 機械には「検出」まで — 確定と書き込みは人に残す」を新設する

**書くのは2つ**: (1) 一般形（機械の担当は検出まで。確定と書き込みは人に残す。判定できないときは赤／保留で止める） (2) **線**。

⭐ **ADR 0223 決定2 が挙げる7本の一覧は `AGENTS.md` へ写さない。ADR 0223 を指すだけにする**（ADR 0234 決定1 と同じ理由——一覧は ADR が増えれば動く。この ADR 自身の「⚠ 数を、道具と生成物に焼き込まない」への自己適用でもある）。

**同じ理由で、`docs/autonomy.md` §4.1 の逐語も `AGENTS.md` へ複製しない。** 新設節は「同じ理由をコマンドの書き方として先に持っている」と§4.1を**指すだけ**にする。

### 決定2. ⭐ 線は「repo の中（戻せる）か、GitHub 側の取り消しにくい面か」である — これを一緒に書く

**⛔ 射程だけを広げると、ADR 0179 の `adr-renumber.mjs`（機械が repo の中身へ書き込んでいる、正当な実装）まで規約違反に見えてしまう。**

Issue #505 のコメントが自分で見つけていた線をそのまま採る【受・逐語】:

> ⚠ **線は「機械が書き込むか」ではない**——ADR 0179 の `adr-renumber.mjs` は機械が書き込む。ADR 0211 が引いている線は「**PR タイトルと本文は機械が直せない**」⟹ **repo の中（戻せる）か、GitHub 側の取り消しにくい面か**で割れている。

**新しく作る道具が repo の中だけに書き込み、かつ戻せる（コミット前なら `cp`/`git mv` の取り消しが効く）なら、機械が確定・書き込みまで担ってよい余地がある**（ADR 0179 の実例）。**GitHub 側の取り消しにくい面（PR の状態・issue の状態・squash commit の本文として `main` に永久に残るもの）へは、検出までに留め、確定と実行を人に残す**（ADR 0211 の実例）。

## ⭐ 歯を足すか — ⛔ 足さない

**決定2 の一般形そのもの**（「新しく作る道具の確定・書き込みが、判定と同じ行に繋がっていないか」）**を機械で縛ることを検討した。**

⛔ **足さない。理由は2つ。**

1. **偽陽性率に上限を置けるとは言えない**（[ADR 0223](./0223-cross-cutting-disciplines-extracted-from-the-adr-corpus.md) 決定3「⛔ **偽陽性率に上限を置けない検査は、門にしない**」への自己適用）。「確定と書き込みを、検出と同じ行に繋いでいないか」は、`if` で明示されているかどうかという**構文の形**では判定できず、**意味の判定**（「これは repo の中の戻せる書き込みか、GitHub 側の取り消しにくい面への書き込みか」）を要る。線（決定2 の「⭐」節）自体が「読み手の知識を要する」（ADR 0234「引き受けた負債」節が同種の限界を線について書いている——「モデルの重みのサイズが `main` で動かないことは、`main` を見ても分からない」と同じ族の限界）。
2. **個別インスタンスの ISSUE がまだ無い**。`gh search issues --repo takecchi/mnemora "副作用のある手"` / `"検出 確定 書き込み"` を実行したが、この規律に反する具体的な道具・スクリプトを指す ISSUE は見つからなかった（Issue #505 自身がヒットするのみ）。ADR 0234 決定4 が「個別インスタンスの ISSUE が既に4本在る」うえで「この ADR では歯を作らない」と判断したのと違い、**本 ADR には歯の対象になる具体的な母集合が無い**。⟹ **成文化だけを済ませ、歯は個別の事例が出たときの別の判断とする。**

⚠ **この検索は網羅ではない**（下の「確かめていないこと」）。

## 引き受けた負債

- **残る4つ（[ADR 0223](./0223-cross-cutting-disciplines-extracted-from-the-adr-corpus.md) 決定3 / 5 / 6 / 10）の宛先は、まだ決まっていない。**⟹ この ADR は決定2 の1本だけを動かしており、**[Issue #505](https://github.com/takecchi/mnemora/issues/505) は閉じない。**
- ⛔ **`AGENTS.md` に置いたからといって、守られるとは限らない。**ADR 0223 自身が同じ留保を書いている【現物・逐語】: 「⛔ **「書けば守られる」とは、この ADR は主張しない。**」——同 ADR は、ADR 0213 決定5 が書かれていたうえで PR #481 が外したという実例まで挙げている。

- **決定2 の一般形を機械で縛らないと決めたため、実際に「検出を超えて確定・書き込みを行う道具」が新設されても、この規律だけでは止まらない。**レビュー（人）に依存する。

## これが覆るとしたら

- **残る4つの判定が出そろい、そのうち複数が「`AGENTS.md` では宛先が合わない」となったとき。**⟹ ADR 0223 が残した「3本目の宛先」を、まとめて作り直す判断になりうる。**その場合もこの ADR の本文は書き換えず、追記で訂正する**（[docs/decisions/README.md](./README.md) の規約）。
- **決定2 に反する具体的な道具の実例が ISSUE として立ったとき。**⟹ 上の「歯を足すか」で足さなかった理由2（個別インスタンスが無い）が崩れ、その事例に閉じた歯を検討する材料が生まれる。
- **線（repo の中か GitHub 側か）で切れない例が出たとき。**⟹ この ADR は ADR 0179 / 0211 の2例だけを根拠にしており、**3例目で崩れる可能性を排していない。**
