## 測ったこと【実測】

- 走らせたのは名指しのファイルだけ。Postgres は専用のもの（`C.UTF-8`）を立てた。全スイートは走らせていない。
- 足した歯は、変異を当てる前は緑。
- 変異ごとに `cp` で退避・`cp` で戻し・`cmp` で一致を確かめ、追跡ファイルに変異が残っていないことを確かめた。migration の変異は、変異ごとに新しい DB を作って流し直した。

## 引き受けた負債

- 全スイートを走らせていないので、「名指しのファイルでは緑のままだが、別のファイルの歯が既に塞いでいる」変異を取りこぼしている可能性がある。#1530 の g5・#1546 の m22 は、名指しを広げて当て直したら赤になったので、歯の対象から外した。
- #1457 の「複数の呼び出し元が同時に呼ぶ競合」は、ADR 0319 の追記が防いでいないと書いているので、歯を足していない。
- #1457 の `DROP INDEX CONCURRENTLY` の歯は、`pg_locks` と `pg_stat_activity` を読み、待ちの最中の backend を見つけるまで最大5秒ほど待つ。遅い器では時間切れになりうる。
