⛔ **「0回だった」を「動かない」と読まない。**個人 repo であり、作者が気を変えれば明日動く。

⭐ **順序の前提は満たされた。** Issue #564 は逐語で「**順序は「気づける」が先である。**
気づけないまま「ずれない仕組み」だけ入れると、それが壊れたときに誰も分からない」と
書いていた。[ADR 0253](./0253-local-embedding-weights-fingerprint-gate.md)（PR #563、および追記1・追記2）で「気づける」側は着地している。

## 決定

### 決定1. 鍵に **HF の revision（`main` の commit sha）** を入れる

`scripts/print-local-embedding-cache-key.mjs` が、`GET /api/models/<repo>` を引いて
`sha` を取り、鍵の**接尾辞**を印字する。`ci.yml` の各 cache 段はその前段でこれを走らせ、
`key: local-embedding-${{steps.local-embedding-cache-key.outputs.key}}` を渡す。

⟹ **HF が動けば鍵が変わり、CI は自動で取り直す。**

### 決定2. ⛔ 鍵の材料を、道具にも yml にも焼き込まない

repo 名も dtype も、唯一の出所である
`packages/local-embedding/src/local-embedding-provider.ts` の
`DEFAULT_LOCAL_EMBEDDING_REPO` / `DEFAULT_LOCAL_EMBEDDING_DTYPE` から読む
（`AGENTS.md`「⚠ 数を、道具と生成物に焼き込まない」）。revision は毎回 HF に問い合わせる。
⟹ **この CLI は鍵の材料を1つも持たない。**

⚠ **接頭辞 `local-embedding-` だけは `ci.yml` のリテラルとして残す。** 理由は決定4。

### 決定3. 🔴 HF に届かなくても**ジョブを落とさない**。落ちる先は「変更前の鍵そのもの」

この段は6ジョブで走り、【実測】**そのうち2つは required な context である**
（`examples/chat (…)` と `ルートの test 門の DB 段 (…)`）。⟹ **HF の一過性の不調で
必須の門が止まるのは、この変更が引き受けてよい代償ではない。**

⭐ **落ちる先は `ruri-v3-30m-q8-v1`**——接頭辞と繋ぐと
`local-embedding-ruri-v3-30m-q8-v1`、**revision を入れる前に `ci.yml` が持っていた鍵と
完全に一致する。** ⟹ **HF 障害中の振る舞いは、この変更の前と同じになる**（温かい
キャッシュから復元され、ジョブは進む）。**退化はしても、新しい壊れ方は作らない。**

⛔ **黙って落ちない。** `::warning::` に理由と「前と同じ振る舞いになる」ことを書く。
⛔ **鍵に `-fallback` のような印を付けない**——付けるとキャッシュを外し、**HF が落ちて
いる最中に 4ファイル計42MB のモデル一式を取りに行かせる**ことになる。

### 決定4. ⭐ 既存の歯が cache 段を見分ける手がかりを、壊さない

🔴 **この変更を書く過程で、既存の歯を3つ壊した。3つとも「段を見分ける手がかり」を
私が奪ったからである。**【実測】

| 壊したもの | 既存の歯が使っている手がかり（逐語） | 出た結果 |
|---|---|---|
| `key:` を式だけにした | `ci-yml-local-embedding-cache-wiring.test.mjs`:「**cache 段は `key:` が `local-embedding` で始まることで見分ける。⛔ `path:` では見分けない**」 | 段が0件になり6本が赤 |
| 式の内側に空白を入れた（`${{ x }}`） | `ci-yml-association-wiring.test.mjs`: `/^\s*key:\s*(\S+)/` | 鍵が途中で切れ2本が赤 |
| 新しい段の名前に「キャッシュ」を含めた | 同: `steps.find((step) => step.name.includes("キャッシュ"))` | **手前の私の段が先に当たり**2本が赤 |

⟹ **決めたこと**: 接頭辞は yml のリテラルに残す／式に空白を入れない／鍵を決める段の
名前に「キャッシュ」を入れない。**この3つを、新しい歯が契約として固定する。**

⭐ **ここから得た一般の形**: **既存の歯は「対象をどう見分けるか」をコメントに書いている
ことがある。⟹ 隣にステップを足すだけでも、その見分けを奪いうる。**

### 決定6. ⭐ 純関数を `-lib.mjs` へ分ける —— 体裁ではなく、必要だからである

【実測 2026-09-21】歯が純関数を CLI から `import` したところ、**CI が落ちた**:

```
Error: process.exit unexpectedly called with "0"
  (test file: scripts/__tests__/local-embedding-cache-key.test.mjs)
```

🔴 **CLI はモジュールの末尾で `main()` を起動する。⟹ 純関数を取り出すために CLI を
`import` すると、その時点で CLI が走って `process.exit` を呼ぶ。**

⟹ `scripts/print-local-embedding-cache-key-lib.mjs` へ分けた。
`check-local-embedding-fingerprint-lib.mjs` / `ci-green-check-lib.mjs` と同じ形である。

⚠ **手元では緑だった。** ⟹ **「手元で緑」は CI の緑と同じではない**——この作業では
**3度目**である（1度目: `git ls-files` で走査する歯は未追跡ファイルを見ない。
2度目: `prettier --write` を `.md` に掛けても `format:check` の glob が `.md` を
含まないので CI は気づかない。3度目がこれ）。

### 決定5. ⚠ `name:` を引用符で囲む

【実測】`- name: …（Issue #564 / ADR 0263）` と書いたところ、`workflow-name-comment-wiring.test.mjs`
が赤くなった——**` #564` が YAML のコメントとして食われ、ステップ名が「…（Issue」で
切れていた。** ⟹ **これは見分けの話ではなく本物のバグである。**引用符で囲んで直した。

## この ADR が塞ぐもの／塞がないもの（⭐ 射程）

⭕ **塞ぐ**: **同じ repo のまま HF 側の `main` が動いたときのドリフト。**

⛔ **塞がない**（Issue #564 のコメントにも同じ射程を書いた）:

1. **上流で repo が削除された** —— repo 名が変わらないので鍵も変わらない。そちらは
   ADR 0253 追記1 の前段が 404 を赤にすることで扱う。
2. **repo 名を変えた／書き間違えた** —— **正しさのバグは生じない。**キャッシュの配置は
   `<cacheDir>/<repo>/<path>` なので、新 repo は別ディレクトリに落ち、古い repo の
   ファイルと混ざらない（【実測】CLI 側が同じ規約で探すことは確認した。transformers.js
   側の配置は【受: ADR 0253「測ったこと」3、観測 2026-09-21】）。生じるのは
   **キャッシュが保存されず毎回落とし直す**という効率の劣化であり、**別の住所である。**

## 採らなかった案（Issue #564 が並べたもの。⭐ 依頼者が選んだ）

| | 案 | 却下の理由 |
|---|---|---|
| (2) | 鍵に**重みファイルの hash** | (1) と同じ費用（HF API 1回）で、得るものが少ない——tree の4件より `sha` の1値のほうが「repo が動いたか」に直接答える |

| (1′) | `hashFiles()` で provider ファイルから鍵を作る | 費用0だが**過剰失効する**。【実測】`local-embedding-provider.ts` は 2026-09-10〜09-19 の**9日で5回**変わっている ⟹ 9日で5回 × 6ジョブ × 4ファイル計42MB を落とし直す |

## 引き受けた負債

1. **CI が HF API の可用性に、もう1箇所依存する。** ⚠ ADR 0253 負債1 と同じ向きだが、
   **こちらは落とさない**（決定3）ので、増えるのは「rev を入れられない run が出る」
   ことだけである。
2. **最初の run では鍵が変わるので、6ジョブとも1回だけキャッシュミスする**
   （4ファイル計42MB を取り直す）。⭐ **一度きりである。**
3. **`sha` という1フィールドに依存する。** HF がそれを落としたらフォールバックへ倒れ、
   **黙って「revision 無しの鍵」に戻る**（`::warning::` は出る）。

## これが覆るとしたら何が起きたときか

- **HF が `sha` を返さなくなったとき** ⟹ 決定1 の前提が崩れる（フォールバックは効く）。
- **required な context から `examples/chat` / `ルートの test 門の DB 段` が外れたとき**
  ⟹ 決定3 の「落とさない」理由が弱くなる。
- **`::warning::` が読まれないことが実害になったとき** ⟹ [ADR 0251](./0251-release-follow-up-notice-not-a-gate.md) が記録した形。

## 追記1 (2026-09-24、Issue #597 案(a)): 鍵の revision は、もう Hugging Face から引かない——固定した宣言を読むだけになった

> **⚠ このコメントは、自動化された担い手（クローンのマネージャーのセッション）が書いた。**
> **⛔ オーナー本人が決めたのではない**（[ADR 0220](./0220-issue-comment-author-does-not-distinguish-owner-from-agent.md)）。
> **⚠ 状態欄も本文も書き換えていない。**

### 何が変わったか

本文の決定1は「鍵に HF の revision（`main` の現在の commit sha）を入れる。**毎回
Hugging Face に問い合わせる**」というものだった。[Issue #597](https://github.com/takecchi/mnemora/issues/597) 案(a) の決定（詳細は
[ADR 0253 追記4](./0253-local-embedding-weights-fingerprint-gate.md) 参照）で、CI が使う
revision を採用時の sha に固定したことに伴い、**`scripts/print-local-embedding-cache-key.mjs`
はもう Hugging Face に一度も問い合わせない。**

- **鍵の revision の出所**: `scripts/local-embedding-pinned-revision.json`
  （固定した sha = `cdf9391f1ff2198daa8f63f7ccf97d7b3e7415a0`。出所・取得日時・tree の
  突き合わせは ADR 0253 追記4 に記録済み）。
- **HF API への問い合わせ（決定1・決定3が組んだ再試行・フォールバック）は無くなった。**
  `--api-base` オプションも削除した（もう注入する対象のネットワーク呼び出しが無いため）。
  宣言（repo/dtype/固定revision）のどれかが読めなかった場合のフォールバック（決定3の
  「HF に届かなくてもジョブを落とさない」と同じ精神——**内部のファイル読み取り失敗も
  同様に、ジョブを落とさずフォールバック鍵へ倒す**）は残した。落ちる先は変更前と同じ
  `ruri-v3-30m-q8-v1`。

### この追記が、決定3の前提にどう影響するか

決定3（「HF に届かなくてもジョブを落とさない」）が引き受けていた負債1
（「CI が HF API の可用性に、もう1箇所依存する」）は、**この鍵については解消された**
——もう HF に問い合わせないので、HF の可用性に依存する箇所ではなくなった。
⚠ **ただし、この門（`scripts/check-local-embedding-fingerprint.mjs`）は引き続き HF に
依存している**（ADR 0253 決定3・追記4）。CI 全体で見れば HF 依存が0になったわけではない。
