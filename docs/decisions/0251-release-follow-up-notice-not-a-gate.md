`CHANGELOG.md` が読めなくても `0` で終わる。**【実測】3通りとも `EXIT=0` を確認した。
⟹ **required status check に載せていないだけでなく、構造として何も止められない。**

⛔ **ここを非 0 へ変えると、採らなかった案4 へ移る。**
⟹ **歯がそれを縛っている**——`describe("⛔ 門ではないこと …")` の2本がそれである。

## 根拠 —— **分けた線は「確実さ」ではなく「外したときに誰が巻き添えになるか」**

| | 案2（採った） | 案4（採らなかった） |
|---|---|---|
| どこで走るか | `release: published` の非ブロッキング通知 | `main` の required |
| 3回目を止める確実さ | ⚠ **弱い**（見落とせる） | ⭕ **強い** |
| 🔴 **外したときの壊れ方** | **誰も止まらない。**外すのはファイル2本を消すだけ ⟹ **可逆** | **tag 公開〜節を書くまで `main` の required が恒常的に赤くなり、無関係な PR まで止まる** ⟹ **巻き添えが自分の外へ及ぶ** |

⟹ ⭐ **確実さの高いほうを採らなかった。**判断の軸は「どちらがよく捕まえるか」ではなく、
**「外したときに、決めていない人が巻き添えになるか」**である。

## 引き受けた負債

1. 🔴 **(b)（`docs/migration-v1.md` の世代）は機械が見ていない。**⟹ **人が §5.5 を読むしかない。**
   ⛔ **「通知が出なかったから大丈夫」と読めてしまう**——§5.5 と通知の出力の両方に、そう読まないよう明記した。
2. ⚠ **通知は見落とせる。**非ブロッキングであることは、**見落とせることと同義**である。
   ⟹ ⭐ **だから §5.5（人の手順）を同時に入れた。**片方だけでは足りない、というのが2案を両方入れた理由である。
3. ⚠ **偽陽性が出る形がある**——Release を publish した**直後**に節を書く運用なら、通知は毎回
   「🔴 節が無い」と出る。⛔ **何も止めないので害は無いが、鳴り続ければ読まれなくなる。**
   ⟹ そのときは**運用のほうを直す**（節を先に書いてから Release を作る）か、この仕掛けを外すこと。
4. ⚠ **この歯は「通知が実際に届くところ」を見ていない。**見ているのは
   **道具の述語**と**ワークフローの配線**までである（下の「確かめていないこと」）。

## これが覆るとしたら何が起きたときか

- **通知が3回目を実際に止めたとき**（＝節の欠落が通知で見つかったとき）。
  ⟹ **案4 へ上げる理由は弱くなる**——弱い仕掛けで足りたことになる。
- **通知が出ていたのに3回目が起きたとき。**⟹ 🔴 **非ブロッキングでは足りないという実測になる。**
  そのときは案4 を検討してよい。⚠ **ただし「required が恒常的に赤くなる窓」をどう閉じるかを
  先に解くこと**——解かずに入れると、巻き添えのほうが先に来る。
- **移行ガイドの項目番号と commit を機械可読に結ぶものができたとき。**⟹ (b) も機械で見られる。

## 測ったこと

**この器で実際に走らせたものだけ。**

```
$ node scripts/check-release-changelog-section.mjs v9.9.9   → EXIT=0（節は無い。🔴 と報告して 0 で終わる）
$ node scripts/check-release-changelog-section.mjs v0.4.0   → EXIT=0（⭕「93 行目に在る」）
$ node scripts/check-release-changelog-section.mjs          → EXIT=0（「判定していない」と名乗る）
$ node scripts/generate-adr-index.mjs --check               → （ADR を足す前の時点で）最新
```

### ⭐ 変異試験（⛔ vitest は走らせていない。下の「確かめていないこと」を読むこと）

**素の `node` で、歯が縛っている2つの性質を1つずつ壊して、狙った側だけが反転することを見た。**

| 変異 | 何が起きたか |
|---|---|
| `findChangelogSection` の `` `## [${version}]` `` から **`]` を外す** | `1.2.3` が **`## [1.2.30]` の節に当たるようになった**（`found: false` → `true`）。⟹ **無い節を「在る」と報告する側へ倒れる。**復元で `false` に戻った |
| CLI の末尾を **`process.exit(verdict.found ? 0 : 1)`** へ変える | 節が無い tag で **`EXIT=1`**（＝**門になった**）。復元で `EXIT=0` に戻った |

⭐ **どちらも、狙った1点を壊したときにだけ反転している**——変異Aでは終了コードは 0 のまま、
変異Bでは述語の判定は変わっていない。⟹ **2つの性質は独立に縛られている。**

## 確かめていないこと

- ⛔ **`vitest` を1度も走らせていない。**この器に `node_modules` が無い。
  ⟹ **歯そのものが緑になることは CI で初めて分かる**（`typecheck / lint / test / build`）。
  ⭐ 上の変異試験は**歯が見ている性質**を素の `node` で確かめたものであり、**歯のコードを実行した記録ではない。**
- ⛔ **ワークフローを実際に発火させていない。**`release: published` を起こすには Release を作る必要があり、
  ⚠ **それはリリースそのものである。**⟹ **この通知が本当に GitHub 上へ出るところは、次のリリースで初めて分かる。**
  ⛔ **「配線を読んだ」以上のことを主張しない。**
- ⛔ **`workflow_dispatch` からの手動実行も試していない**（同上、この器から Actions を起こしていない）。
- ⛔ **偽陽性率を測っていない**（引き受けた負債3）。母集合になるリリースが2件しかない。
- ⛔ **(b) の自動化の費用を見積もっていない。**
