## 文脈

ADR 0099 は `packages/openai/src/__tests__/live.openai.test.ts` に、実 API へ適合テストを当てる口を置いた。
しかし**その節は一度も走っていなかった**（ADR 0099「確かめていないこと」1行目、Issue #142 ①）。
live 側の `deterministic: false` も、実測ではなく「再現性の保証を持っていない」という*理由*で置いた値だった
（`docs/conformance.md` §4）。

この ADR は、その2つを実際に測った結果を残す。

## 測ったこと 1: live テストを実 API で走らせた【実測】

```
MNEMORA_LIVE_OPENAI=1 npx vitest run src/__tests__/live.openai.test.ts   # packages/openai で、鍵は環境から
```

| | 結果 |
|---|---|
| ファイル全体 | **9 passed / 3 skipped（12本）** |
| 既存の live 2本（`embed` の次元・`completeStructured`） | 緑 |
| 適合テスト10本のうち、**無条件7本**（`docs/conformance.md` §3 の数え方） | ⭐ **7本とも緑** |
| `deterministic: false` で skip される2本（決定性・3件の巡回による順序） | skipped（宣言どおり） |
| `overLimitText` 未指定で skip される1本（ADR 0305） | skipped（宣言どおり） |

⟹ **赤は1本も無かった。**「実装の誤り」と「契約が測れないものを要求している」を分ける必要は、無条件7本については生じなかった。

## 測ったこと 2: 決定性【実測】

### 方法

`OpenAIEmbeddingProvider.embed` と**同じ引数の形**（`model` / `input` / `dimensions`。`encoding_format` は指定せず SDK 既定。
`openai` SDK 7.10.0）で `embeddings.create` を直接呼び、`index` で並べ直したベクトルを
**要素ごとに `!==` で比べた**（許容誤差なし）。モデルは `text-embedding-3-small`。
使い捨てのスクリプトで測り、**スクリプトはコミットしていない**。

- 3件バッチの入力: 適合テストと同じ `["mnemora conformance a", "… b", "… c"]`
- 単独入力: 上の `a`、および日本語1文（`昨日の打ち合わせで、来月のリリース日を10月15日に決めた。担当は佐藤さん。`）

### 結果

| 入力の形 | 次元 | 呼び出し回数 | 異なるベクトルの数 | 1回目と違った回 | 最大絶対差 |
|---|---|---|---|---|---|
| 3件バッチ `[a,b,c]`（1周目） | 256 | 10 | 各テキスト **2** | 8/9 | 1.83e-4 |
| 3件バッチ `[a,b,c]`（2周目） | 256 | 20 | `a` は **3**、`b`・`c` は **2** | 7/19 | **2.44e-4** |
| 巡回 `[b,c,a]` と1周目の1回目 | 256 | 5 | 2 | 4/5 | 1.83e-4 |
| 単独 `[a]`（1周目、1周目のバッチ1回目の `a` と比較） | 256 | 5 | **1** | 0/5 | 0 |
| 単独 `[a]`（2周目） | 256 | 20 | **1** | 0/19 | 0 |
| 単独 日本語1文（1周目） | 1536 | 10 | **1** | 0/9 | 0 |
| 単独 日本語1文（2周目） | 1536 | 20 | **1** | 0/19 | 0 |
| 単独 日本語1文（2周目） | 256 | 20 | **1** | 0/19 | 0 |

- 2周目の3件バッチで、どのベクトルが返ったかを並べるとこうなる（`b`。0/1 は返ったベクトルの種類）:
  `00010010100110000011`。**隣り合う2回が一致しなかったのは19組中10組**
  （`a` も10組）。⟹ 決定性の歯（同じ `[a,b,c]` を2回続けて呼んで `toEqual`）を実 API に当てたら、
  **約半分の確率で落ちる**と見込める。
- 違いはごく小さい。同じテキストどうしのコサイン類似度の最小値は **0.9999995**。
  表の最大絶対差（1.53e-4・1.83e-4・2.44e-4）は、どれも 2⁻¹⁵ の整数倍（5・6・8 倍）だった。
- 合計: **110 回の `embeddings.create`、2,780 トークン**（ほかに live テスト自身の呼び出しがある）。

### 読めること・読めないこと

- ⭐ **`false` は「測っていない」ではなく「測って、非決定的だった」と書けるようになった**——ただし
  **3件バッチについては**、である。
- **単独入力は、測った範囲（75回・3種類の条件）では一回もずれなかった。**
  同じテキスト `a` でも、単独なら1周目（5回。1周目のバッチ1回目の `a` とも一致）・2周目（20回）とも全回一致し、3件バッチの中では揺れた。
  ⚠ **ずれが「バッチであること」によって起きるのかどうかは確かめていない。**
  この観測と矛盾しないのはそこまでで、サーバ側の仕組みは知らない。
- 測ったのは 2026-09-25 の1日・2周だけで、**仕様の保証ではない**（ADR 0099「確かめていないこと」と同じ留保）。

## `deterministic` を誰が読んでいるか【現物】

- `deterministic` は **`OpenAIEmbeddingProvider` のフィールドではない。**クラスにも `packages/openai/src/*.ts` にも無い。
  `@mnemora/testkit` の `describeEmbeddingProviderConformance(options)` の**引数**であり、
  live 側の値は `live.openai.test.ts` の呼び出しに書かれている。
- 読んでいるのは `packages/testkit/src/embedding-provider-conformance.ts` の `maybeIt` **だけ**で、
  2本の歯（決定性・3件の巡回による順序）を `it` にするか `it.skip` にするかを切り替える。
- `packages/core` / `packages/postgres` / `examples` に、埋め込みの `deterministic` を読む箇所は無い。
  ⟹ **値を変えても runtime の挙動は何も変わらない。**変わるのは「live を opt-in したときに2本が走るかどうか」だけである。
- 仮に `true` にすると、2本はどちらも3件バッチを2回呼んで厳密一致を求めるので、上の実測から
  **約半分の確率で赤になる**見込みである。その赤は実装の誤りではない（`embed` は API の出力を
  並べ直して返すだけである）。**契約が、実 API の3件バッチでは満たせないものを要求している**側の赤である。

## 決めないこと

- **`deterministic` の宣言値は変えない。**変えるかどうかはオーナーが決める。
- `docs/conformance.md` §3 の数え方（無条件7本）は変えない。

## 確かめていないこと

- **ずれがバッチの件数で決まるのかどうか**（2件ではどうか、など）。
- **ほかのモデル**（`text-embedding-3-large` など）と、**ほかの日・ほかの地域**での再現性。
- **`encoding_format: "float"` を明示した場合**（SDK 既定のまま測った）。
- **課金額の実値**。`usage.total_tokens` の合計と公開単価から見積もっているだけで、請求画面は見ていない。
- 巡回の順序の歯（ADR 0099 決定3）を実 API で**通るかどうか**は、決定性が崩れているので判定できない。
  ADR 0095 が「順序の検査は決定性を前提にしている」と書いたのは、この状況のことである。
