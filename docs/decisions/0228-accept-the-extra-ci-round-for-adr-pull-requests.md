# ADR 0228: ADR を持つ PR が CI をもう1周する費用を受容する — 方向4 を選び直す（Issue #267）

- **状態**: 採用 (2026-09)
- **日付**: 2026-09-17

**⚠ 各主張の出所を分ける**（ADR 0132 / 0137 / 0183 / 0192 の体裁を踏む）。

- **【現物】** — この repo のコード・文書を書き手が読んで確かめた。
- **【実測】** — この書き手が自分の手で `git` / `gh` / `node` 等を走らせて確かめた。
- **【受】** — 報告として受け取り、再導出していない（出所を明記する）。

**測定条件**: 断りの無い【実測】は、`origin/main` = `701e3a8d7109844789c8a41bbb42d3f62e237b49` から切った作業木で、2026-09-17 に行った。

## 問い

[Issue #267](https://github.com/takecchi/mnemora/issues/267) が測った費用を、どう決着させるか。

**ADR を足す PR は、CI が必ずもう1周する。**[ADR 0137](./0137-adr-index-generated-from-source.md)「決定」2番が「索引の再生成は**マージ直前・PR ブランチ上**で、マージする側が行う」と定めている以上、**索引再生成のコミットを push した時点で、PR の CI がもう一度走る**からである。

⚠ **これは手順の不備ではない。**Issue #267 の本文が逐語でそう書いている:

> **⚠ これは「手順が悪い」のではない。手順が正しいがゆえに払っている費用である。**

Issue #267 は「考えられる方向」を4つ並べ、⛔ **「本 issue はどれも採らない」と明記して閉じずに置いた。**⟹ **その4つのうちどれを採るかが、まだ決まっていない。**

### 🔴 一度、方向4 は弱くなった

**Issue #267 の 2026-09-16 の追記**が、PR #384（ADR 0190）/ PR #385（ADR 0191）が索引再生成を経ずに squash merge され `main` が赤くなった実例を記録し、こう結論している（逐語）:

> ⟹ 🔴 **本 issue の「方向4（何もしない）」は、この実例によって弱くなった。**費用（1日4回・1回3〜6分）だけなら許容の判断はありえたが、**`main` が赤くなるなら `docs/autonomy.md` §1 段1（壊れているものを最優先で拾う）の信号がノイズ化する**

⟹ **本 ADR の問いは「その弱まりは、いまも残っているか」である。**

## 決定

### 1. ⭐ 方向4（受容）を選び直す

**「ADR を持つ PR は CI がもう1周する」という費用は、この repo の構えの対価であり、受容する。**

**⟹ 方向1・方向2・方向3 のために新しい機構を足さない。**ADR 0137「決定」2番と `docs/autonomy.md` §4 の手順を、そのまま続ける。

### 2. ⛔ Issue #267 は、この ADR では閉じない

**本 ADR は判断を記録するだけである。**閉じるかどうかは、この ADR が着地してから別に決める。⟹ **本 ADR に閉鎖参照（`Closes` / `Fixes` / `Resolves`）を書かない**（`docs/autonomy.md` §4.1 が「打ち消し文の中でも使わない」と名指ししている）。

### 3. ⭐ 受容を覆したい人が次に見る場所を、この ADR に書き残す

**費用の発生源そのものを消せる案は1つだけ在る。**⟹ その所在を「これが覆るとしたら」に置く（下記）。

## 根拠

### 1. 🔴 方向4 を弱めた根拠は、もう消えている

**方向4 を弱めたのは「費用」ではなく「`main` が赤くなること」だった**（上の逐語）。⟹ **その赤は、`main` へ入る前に止まるようになった。**

[ADR 0192](./0192-adr-index-freshness-enforced-in-pull-request-ci.md)（題に「（Issue #267）」を持つ）が鮮度の歯を `pull_request` でも有効にした。【現物】`docs/autonomy.md` §4 の表「ADR PR をマージするとき、索引の再生成を忘れる」の行が、その結果を逐語でこう書いている:

> ⭐ **2026-09-17 以降、これは `main` へ入る前に CI が止める**（ADR 0192）——鮮度の歯は **`main` の push だけでなく CI の `pull_request` でも有効**になり、`typecheck / lint / test / build` は required status check であるため、**索引が陳腐化したままの PR は GitHub 自身がマージを拒む**。

⟹ ⭐ **方向4 を弱めた事故（PR #384 / #385 の形）は、もう同じ形では起きない。**⟹ **残っているのは、追記の前に「許容の判断はありえた」と書かれていた純粋な CI 費用だけである。**

⚠ **ただし ADR 0192 自身が、この強制力の根拠を未検証だと名乗っている**（0192「確かめていないこと」の1点目、逐語）:

> 🔴 **「required check が赤いとき `gh pr merge` が実際に拒まれる」ことを、この repo で実地検証していない。**

⟹ **本 ADR は、その未検証の上に乗っている。**⛔ ここは自分でも確かめていない（「確かめていないこと」に再掲する）。

### 2. ⛔ 自動化しても周回は消えない —— ADR 0137 の「これが覆るとしたら」から機械的に出る

**方向1（索引生成を CI 側でやる）は、ADR 0137 が既に「却下ではなく保留」として扱い、覆る条件まで書いている。**【現物】ADR 0137「これが覆るとしたら」の1点目（逐語）:

> **GitHub Actions が `pull_request` イベントで PR ブランチへ再生成コミットを自動 push できると実際に検証されたとき。** そのときは2番の「マージする側が手で実行する」手順を、ワークフローに置き換えられる——**このとき置き換わるのは「誰が実行するか」だけであり、「マージ直前・PR ブランチ上で行う」というタイミングそのものは変わらない**

⟹ 🔴 **自動化しても「追加の commit + push」は残る。⟹ もう1周は消えない。**⭐ **省けるのは人の手間とミスであって、CI の費用ではない。**

⭐ **これは技術検証を要さない。**ADR 0137 の本文だけから機械的に出る結論である。⟹ **方向1 を実装してから「費用は減らなかった」と気づく必要が無い。**

⚠ 【受】（出所: Issue #267 の `issuecomment-5712642668`。この書き手は再導出していない）: 方向1 が ADR 0137 で保留になった理由（`gh` の書き込み権限が無い環境だった）は、**いまは解けている**（トークンが `admin: true` / `push: true`）。⟹ **それでも上の結論は変わらない**——変わるのは「できるか」であって「費用が消えるか」ではないからである。

### 3. ⛔ 方向3（マージ時に自動生成）は、ADR 0192 が明示的に却下している

【現物】ADR 0192「検討して採らなかった案」(d)（merge queue を有効にし `merge_group` でのみ検査する）の逐語:

> ⛔ **CI がもう1周増える。**`merge_group` は `ci.yml` 全体（DB を要するジョブ群を含む）を走らせる。[Issue #267](https://github.com/takecchi/mnemora/issues/267) が既に実測している「ADR PR は索引再生成の push で2周する」に**3周目**が乗る。

⟹ **方向3 は費用を減らすどころか増やす。**⚠ 0192 は同じ節で「branch protection 側で『Require merge queue』まで設定しない限り**直接 squash merge は依然可能**」とも書いており、**抜け道も残る。**

**方向1 の変種（`main` への push 時に自動再生成）も、0192「採らなかった案」(e) が却下している**（逐語）: 「⛔ **`main` が一度は陳腐化した状態を通る**——本 ADR が塞ごうとしている当のものである。」

### 4. 方向2 は着地済みだが、費用は解消していない

**方向2（鮮度の歯を PR でも有効にする）に当たるものが ADR 0192 として既に着地している。**⟹ **それが足したのは「陳腐化したまま着地するのを止める歯」であって、周回ではない。**

【受】（出所: Issue #267 の `issuecomment-5701649704`、2026-09-16T17:22:28Z。逐語）:

> ⚠ **しかし、この ISSUE が言っていたのは「ADR PR は索引再生成の push で CI がもう1周する」という費用であり、#398 はその周回を減らしていない。** #398 が足したのは「索引が陳腐化したまま着地するのを PR 段階で止める歯」であって、**周回そのものは残る**（むしろ PR 段階でも検査が走る）。

### 5. 残る費用は、この repo では課金されない

【実測】`gh api repos/takecchi/mnemora --jq '{visibility, private}'` → `{"visibility":"public","private":false}`。

【実測】`.github/workflows/ci.yml` と `.github/workflows/publish.yml` の `runs-on` は **13箇所すべてが `ubuntu-latest`** である（`grep -rn "runs-on" .github/workflows/` → `ubuntu-latest` が13、他は無し）。⟹ **larger runner を使っていない。**

⚠ **この「13」を、下の「13ジョブ」と同じ数だと読まないこと。**こちらは `runs-on` の**出現箇所**（`ci.yml` の12ジョブ + `publish.yml` の1ジョブ）であり、下の13は `ci.yml` の `postgres` を matrix の2脚に展開した**ジョブ数**である。⟹ **一致しているのは偶然である。**

【現物】GitHub の課金文書（`https://docs.github.com/en/billing/concepts/product-billing/github-actions`、2026-09-17 に取得）の逐語:

> The use of standard GitHub-hosted runners is free:
>
> - In public repositories
> - For GitHub Pages
> - For Dependabot

> Larger runners are always charged for, even when used by public repositories or when you have quota available from your plan.

⟹ **標準ランナー × public repo ＝ 実行時間の課金は無い。**

⚠ **ADR 0019 §5c 等が言う「課金」は、OpenAI 等の有料 API キーの文脈である**——【現物】`grep -rn "課金" docs/decisions/*.md docs/*.md` の当たりは、1件を除きすべて OpenAI / 埋め込み API の話であり、**GitHub Actions の実行時間についてではない。**⟹ **「課金はオーナーの判断」という先例を、Actions の実行時間に当てはめない。**

⛔ **唯一の例外が [ADR 0183](./0183-local-postgres-makes-postgres-mutation-testing-possible.md) の「確かめていないこと」であり、そこは逐語でこう書いている:**

> **GitHub Actions の課金換算（ジョブ×分）を見積もっていない。**上の数字は壁時計のみである（Issue #267 の「確かめていないこと」と同じ限界）。

⟹ ⚠ **本 ADR もそれを埋めていない。**「課金されない」は「資源を使っていない」と同じではない。⟹ **受容しているのは「無料だから気にしなくてよい」ではなく、「この repo では金銭の請求として現れない」までである。**

### 6. 費用の数字を、自分で数え直した

⚠ **Issue #267 本文の「1周あたり11ジョブ・3〜6分」は 2026-09-15 の値であり、既に古い。**ADR 0183 が「測ったこと」の表で **13ジョブ・壁時計 4〜9分**に更新している（`association-probes` / `validity` が後から入ったため）。

**【実測】その13を、この書き手が2通りで数え直した**（`main` = `701e3a8`）:

| 数え方 | 結果 |
|---|---|
| `.github/workflows/ci.yml` の `jobs:` 直下のキー | **12**。うち `postgres` が `matrix`（`serverEncoding` = UTF8 / SQL_ASCII）の2脚 ⟹ **13** |
| `gh api repos/takecchi/mnemora/commits/701e3a8.../check-runs --jq '.total_count'` | **13**（全て `success`） |

**【実測】その run の壁時計**: 最初の job の `started_at` `2026-09-17T10:46:15Z` → 最後の `completed_at` `2026-09-17T10:51:14Z` ＝ **約4分59秒**。最長は `ルートの test 門の DB 段`。⟹ **ADR 0183 の「4〜9分」の範囲に収まる。**

⚠ **この13という数字は `ci.yml` が変われば変わる**（ADR 0223 決定9「焼き込んだ数字は腐る」）。⟹ **本 ADR はこれを歯にしない。**上の表は「どの sha で数えたか」を添えた記録であって、守るべき不変条件ではない。

## 検討して採らなかった案

### (1) 方向1 — 索引生成を CI 側でやる（bot がコミットする）

⛔ **費用が消えない**（根拠2）。⟹ **「もう1周する」を解決しない案に、bot の書き込み権限の設計という新しい面倒を足すことになる。**

⭕ ただし**人の手間とミスは減る。**⟹ **その目的で提案されるなら、それは別の ISSUE である**——本 ADR が落としているのは「#267 の費用を解決する案として」だけである。

### (2) 方向2 — 鮮度の歯を PR の最後の1回だけにする

**既に ADR 0192 として着地しており、費用は残った**（根拠4）。⟹ **採る／採らないの対象として、もう存在しない。**

### (3) 方向3 — マージ時に自動生成する（merge queue 等）

⛔ **ADR 0192 (d) が却下済み。3周目が乗る**（根拠3）。

### (4) ⭐ ADR 0192「採らなかった案」(a) — 索引をコミットせず、生成物として扱う

🔴 **これだけが、費用の発生源そのものを消す。**【現物】ADR 0192 の逐語:

> ⭕ **唯一、「陳腐化する対象そのもの」が消える案である。**抜け道も無い。
>
> ⛔ **それでも採らない。**ADR 0137 が「問い」節で置いた制約を正面から破るからである（逐語）:
>
> > 制約は1つ：生成された結果が1つのファイルとして読めること（`docs/decisions/README.md` を1枚の索引として読めなくしてはならない）
>
> **これは実装の判断ではなく、読み手の体験を変える製品の判断である。**⟹ オーナー／クローンの領分であり、この ADR では決めない。**airtight を望むならこの案が正解である**、という事実だけ残す。

⛔ **本 ADR もこの案を採らない。**理由は 0192 と同じである——**制約を覆すかどうかは、CI 費用の話ではなく、索引を読む人の体験の話だからである。**⟹ **費用を理由にこの制約を崩さない。**

⭐ **だが「どこを見ればよいか」は書き残す。**⟹ 下の「これが覆るとしたら」の1点目がそれである。

### (5) Issue #267 をこの ADR で閉じる

⛔ **採らない**（決定2）。**閉じるかどうかは、判断を記録することとは別の手である。**

## 引き受けた負債

### 1. 🔴 周回は、これからも払い続ける

**ADR を足すたびに、PR の CI が2周する。**⟹ **本 ADR は「減らす」を諦めた記録である。**⚠ **ADR を足す頻度が上がれば、費用は比例して上がる。**

⚠ **Issue #267 自身が「4回/日 が典型かどうかは分からない」と書いている**（逐語: 「**2026-09-15 の1日を数えただけ**であり、他の日は数えていない」）。⟹ **本 ADR も、受容の判断を「1日あたり何回」という数字の上には置いていない。**置いているのは「**方向1〜3 のどれも費用を減らさない**」という構造のほうである。

### 2. 受容の判断は「public であること」に全面的に乗っている

⟹ **repo が private になれば、根拠5 は成立しなくなる**（「これが覆るとしたら」に再掲）。

### 3. ⛔ 資源消費（ジョブ×分）は、いまも誰も見積もっていない

Issue #267 の「確かめていないこと」も、ADR 0183 の「確かめていないこと」も、同じ限界を名乗っている。⟹ **本 ADR もそれを埋めずに受容している。**⚠ **「金銭の請求が無い」を「資源を消費していない」と読まないこと。**

## これが覆るとしたら

- ⭐ **ADR 0192「採らなかった案」(a)（索引をコミットせず生成物として扱う）を採る判断がされたとき。**⟹ **それは「`docs/decisions/README.md` を1枚の索引として読める」という ADR 0137 の制約を、明示的に覆す判断である。**⛔ **CI 費用を理由にこの判断をしないこと**——0192 が書いたとおり、**読み手の体験を変える製品の判断**だからである。**逆に、費用ではなく「airtight であること」を望むなら、この案が正解である。**⟹ そのとき本 ADR の受容は要らなくなる——**陳腐化する対象も、再生成する手順も、その周回も、まとめて消えるからである。**
- **repo が private になったとき。**⟹ 根拠5（public repo の標準ランナーは無料）が崩れ、**GitHub Actions の実行時間に課金が発生する。**⟹ そのときは「ジョブ×分」を実際に見積もったうえで、受容を測り直す。⚠ **その見積もりは、負債3 のとおり、いまだ誰も作っていない。**
- **`typecheck / lint / test / build` が branch protection の `required_status_checks.contexts` から外れたとき。**⟹ ADR 0192 の強制力がこの1点に全面的に乗っている（0192「これが覆るとしたら」2点目）。⟹ **外れると「`main` へ入る前に止まる」が成立しなくなり、方向4 を弱めた 2026-09-16 の事故が同じ形で戻る。**⟹ **本 ADR の根拠1 が消える。**

## ⭐ 本 ADR 自身が、この周回を実際に踏んだ【実測】

**本 ADR を出す PR（[#510](https://github.com/takecchi/mnemora/pull/510)）は、CI を2周した。**⟹ **書いている当の現象を、書いて出す過程でそのまま踏んだ。**

### 1周目 —— ADR を1本足しただけの push

| | |
|---|---|
| **何の push か** | ADR ファイルを1本追加しただけ。⛔ **索引（`docs/decisions/README.md`）は触っていない**（ADR 0137 決定1） |
| **head sha** | `03f0c60e3747ead275e3cc54b56f275d87d01fc7` |
| **ジョブ数** | **13**（上の表で数えた13と一致した） |
| **壁時計** | `2026-09-17T11:08:53Z` → `11:13:02Z` ＝ **4分09秒**。最長は `ルートの test 門の DB 段` |
| **結果** | 🔴 `typecheck / lint / test / build` が **`conclusion: failure`**。他の12ジョブは `success` |
