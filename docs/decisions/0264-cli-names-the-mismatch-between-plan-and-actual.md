## 決めたこと

### 決定1. 予定と実測が食い違ったら、画面がそれを名指しする（Issue #594 案(3a) を採る）

`printProviderMode` が「予定」を受け取り、`detectPlanActualMismatch` が食い違いを検出したら
`describePlanActualMismatch` の行を画面へ出す。⭐ **ADR 0260 の `cassetteIgnored` と同じ形を、
`openai` 枝へ広げる**——新しい発明ではない。

### 決定2. 🔴 これは判定ではなく**開示**である。⛔ 例外にはできない

`cli.ts` の `buildArmSpecs` が組む `retrieval` の arm A（擬似LLM+擬似埋め込み）と
arm B（擬似LLM+本物の埋め込み）は、**意図して**予定と食い違わせる対照群である【現物】。
⟹ **食い違いそのものは欠陥とは限らない。**

⛔ **そして、正当な食い違いと事故の食い違いを、プログラムは区別できない。**
これは `Providers.cassetteIgnored` が例外になれないのと**同じ理由**であり、
[ADR 0255](./0255-tools-output-candidates-not-verdicts.md) /
[ADR 0223](./0223-cross-cutting-disciplines-extracted-from-the-adr-corpus.md) 決定5 の適用である。
⟹ **行の文面自身が「開示であって判定ではない」と名乗る。**

### 決定3. 「予定」は省略可能にしない。名乗っていない経路は `null` を**明示する**

⭐ **理由は `Providers.cassetteIgnored` を必須引数に畳み込んだのと同じである**——
「予定を名乗ったのに、食い違いを開示しないまま provider バナーを出す」経路を**書けなくする**
（AGENTS.md「形で塞ぐ」）。

⛔ **`null` は「食い違っていない」ではない。「予定を名乗っていない」である。**
`chat` / `scope` / `backfill` などは `[cassette]` 行を1行も出さない——
**名乗っていない予定と食い違うことはできない。**

### 決定4. 予定は `RecordedRunPlan` が運ぶ

`resolveRecordedRun` は `[cassette] provider source の予定` を**必ず**画面へ出す。
⟹ **その予定を返り値に含めることで、呼び出し側が渡し忘れる経路そのものを無くす。**
⭐ `RecordedRunPlan.env` が Issue #577 に対して同じ形で効いたのと同じ理由である
（**名乗ることと、名乗りを検査へ渡すことを、分離できない形にする**）。

### 決定5. 歯は、陽性対照を同じファイルに置く

🔴 **[ADR 0256](./0256-positive-control-before-claiming-absence.md) の適用。**
「食い違いを検出した」という歯が赤くなったとき、それが**食い違いを作れていないから**では
ないことを示せなければ、その赤は何も証明しない。⟹ 同じファイルに:

- **陽性対照**: 予定=`openai` / 実測=`deterministic` が**実際に起きている**こと、
  かつ **`cassetteIgnored` がそれを見ていない**こと（この2本は実装の前後で常に緑）
- **本題**: 食い違いを名指しすること（実装の前だけ赤）

【実測】実装前: **陽性対照2本が緑、本題6本が赤**。実装後: **8本すべて緑**。

## 引き受けた負債

1. **`retrieval` の3 arm のうち2 arm（A・B）で、この行が毎回出る**【推論・未検算。DB が無く `retrieval` を走らせていない】。
   ⛔ **毎回出る開示は、読み飛ばされやすい。**⟹ **`cassetteIgnored` が arm A で毎回出るのと同じ性質**であり、
   ADR 0260 がそれを承知で採った形をここでも踏襲している。⚠ **「毎回出るなら消すべきか」は測っていない。**
2. 🔴 **`record` / `verify` サブコマンドは `resolveRecordedRun` を通らないため、`null` を渡している**【現物】。
   ⟹ **あちらが予定を名乗るようになったら、ここも見直すこと。**⛔ いま名乗っていないことは確かめたが、
   **名乗るべきかは判断していない。**
3. **`describeProviderSourceReason` の理由文（「実 API を叩く」）は、依然として結果の断定に読める**
   （ADR 0262 の負債1 をそのまま引き継ぐ）。⛔ **この ADR も直していない。**
4. 🔴 **「この実行が最後まで通るか」は、この行を足しても分からない**（ADR 0262 の負債3）。
   ⟹ **`[provider]` 行が名乗れるのは「何で組んだか」までである。**⛔ **この ADR はそこを塞いでいない。**

## これが覆るとしたら

- **`createProviders` が `decideProviderSource` を読むようになったとき。**
  ⟹ 予定と実測が構造的に一致し、この検出器も ADR 0262 決定2 の「予定」も要らなくなる。
- **開示が読み飛ばされていると実測できたとき。**⟹ 負債1 の形を測り直すことになる。

## 確かめたこと

- **【実測】** `openai` 経路で予定と実測が食い違うこと、そのとき `cassetteIgnored` が `false` のままであること
- **【実測】** 食い違いが無い `openai` 経路でも `cassetteIgnored` が `false` であること（＝この経路で区別していない）
- **【実測】** 実装前の赤（陽性対照2本が緑、本題6本が赤）と、実装後の緑（8本）
- **【実測】** 変異試験2種——`!llmDiffers && !embeddingDiffers` を `||` にすると片側だけの食い違いを見落として2本が赤、
  `plannedSource === null` の枝を殺すと `null` の歯が赤。**どちらも戻すと緑に復帰する**
- **【現物】** `resolveRecordedRun` の `openai` 枝が `cassette: undefined` を返すこと ／ `buildArmSpecs` の arm A・B が意図して食い違わせること

## 確かめていないこと

- **実 API を叩く実行（鍵あり・モード無指定）は走らせていない。⛔ 鍵を持っていない**（ADR 0262 と同じ）。
- **負債1（毎回出る開示が読み飛ばされるか）は測っていない。**
