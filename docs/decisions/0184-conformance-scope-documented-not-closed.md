# ADR 0184: 適合テストが「何を保証していないか」を、塞ぐ前に名乗る — v1.0.0 は弱さを明示した状態で出す

- **状態**: 採用 (2026-09)
- **日付**: 2026-09-17

- **この ADR の根拠の種別**:

  - **【現物】** — `main` = `18a8a09`（2026-09-17）のコード・workflow・README を
    書き手が自分の手で読んで数えた。
  - **【実測】** — 書き手がこの器で実際に走らせた、または取得した。
  - **【受】** — [Issue #142](https://github.com/takecchi/mnemora/issues/142) 本文、
    および ADR 0095 / 0099 / 0019 の「確かめていないこと」。

- **文脈**:

  [Issue #142](https://github.com/takecchi/mnemora/issues/142) は、`EmbeddingProvider` の
  適合テスト（ADR 0095）が4実装すべてに当たった（ADR 0099 / PR #141）後に**残った2つの欠落**を
  住所として開けたものである【受】:

  1. 🔴 **実 API には一度も当てていない。**「宣言は在るのに、その宣言が裏づけられていない」。
  2. ⭐ **適合テストは「実際にどのモデルを読み込んでいるか」を見ていない。**

  **⚠ どちらも「見つかった穴」ではなく、作業した本人が自分で測って名乗った穴である。**

  **🔴 v1.0.0 は `@mnemora/openai` と `@mnemora/anthropic` を含む6パッケージを publish する。**
  実 API に一度も当てずに 1.0 を名乗るのは弱い。**その弱さをどう扱うかが本 ADR の主題である。**

  ### 調べる過程で、Issue #142 が触れていない、より手前の欠落を見つけた【現物】

  🔴 **`LLMProvider` の適合 suite が、そもそも存在しない**（`describeLLMProviderConformance` = 0件）。
  ⟹ **`@mnemora/anthropic` は publish 6本の1つでありながら、適合テストに1本も当たっていない。**
  ⟹ **これは「v1.0.0 でこれから起きること」ではない。**
  【実測 2026-09-17: `npm view @mnemora/anthropic versions` = `0.1.2` 〜 `0.2.0` の9版、
  `latest` = `0.2.0`】**既に公開されており、今日入れている人が居るかもしれない。**

- **北極星の5つの問いに実際に当てた結果**（`docs/north-star.md`「迷ったときの問い」。
  問いは書いた時点では飾りと区別が付かない、という同文書の戒めに従い、
  **実際に何が落ちたか**を記録する）:

  | 問い | この判断にどう当たったか | 落ちた案 |
  |---|---|---|
  | **1**（毎回渡す量を減らす方向に働くか） | 該当しない（文書だけの変更であり、recall の経路に1バイトも触れない）。 | — |
  | **2**（無効にしても Memory Framework として成立するか） | **これが「歯を足す案」を落とした。**新しい検査を CI へ足せば、「これが無いと着地しない」が1つ増える。**文書は、無視しても既存の呼び出し側が今日と同じ結果を得る。** | **「強い版（fixture の値を厳密照合）＋ CI で走らせる」案**（下記1）。 |
  | **3**（選ばれた理由を後から説明できるか） | **これが本題である。**採用する側が「この緑は何を保証していないか」を読めるようになる。**説明できない緑は、説明できない賢さと同じく採らない。** | **「何もしない（穴として記録もしない）」案。**ADR 0099 の「確かめていないこと」に埋もれたままにする形は、**採用する側から見えない。** |
  | **4**（推論と事実を区別しているか） | **`deterministic: false` の2つの意味を分けた**（「測って非決定的だった」と「測っていない」）。これは本質的に問い4の適用である——**根拠の種別を潰さない。** | **`deterministic: true` へ「たぶん決定的だから」で変える案**（Issue #142 が明示的に禁じている）。 |
  | **5**（LLM を呼ばずに済ませられないか） | 該当しない。 | — |

- **決めたこと**:

  1. **`docs/conformance.md` を新設し、適合テストの「保証の範囲」と「範囲の外」を
     1箇所に集める。**中身は次の8節:
     - **何が在るか** — 7 suite・合計 **288 it**【現物】
     - 🔴 **`LLMProvider` の適合 suite は存在しない**
     - **どの実装に実際に当たっているか** — store 系は2箇所、`EmbeddingProvider` は6箇所。
       **そのうち「本物に当たる」2箇所が走っていない**
     - 🔴 **構造的に一度も走らない歯: 4ファイル・28 it**（必要な env と、CI にそれが無いこと）
     - ⚠ **「無条件7本」は無条件ではない**（読み違えやすいので明示する）
     - 🔴 **`deterministic: false` は「測っていない」を意味する**
     - ⭐ **「どのモデルを読み込んでいるか」を見ていない**ことと、**なぜ簡単には塞げないか**
     - **実 API に当てる手順**と、**測ったら何をどこに記録するか**

  2. **⛔ 歯を1本も足さない。**Issue #142 が逐語でこう書いているためである:

     > ⛔ **どれを採るかは、まず「この穴が実際に踏まれうるか」を測ってから決めるべきである**
     > （`repo` を差し替える運用が実在するのか）。⛔ 測る前に歯を足さないこと。

     **⟹ issue 自身の指示に従う。**本 ADR は Issue #142 の案(う)（穴として記録だけする）である。

  3. **`packages/anthropic/README.md` に、採用する側が読める形で欠落を書く。**
     **`docs/` ではなく README に置く**——採用する側が読むのは npm の README であって、
     リポジトリの `docs/` ではない。**⛔ 弱さを隠さない。**
     **⚠ 同時に「動かない」と読ませない**——固有の検査は在る。
     足りないのは **adapter 非依存の契約を横断で測る層**である、と書き分ける。

  4. **⛔ CI で実 API を叩かない。**鍵の管理と課金の判断はオーナーのものである。
     代わりに **「鍵を持つ人が1コマンドで測る」手順**を `docs/conformance.md` に置き、
     **測ったら ADR に記録する**と書く。**⟹ 後から鍵が渡れば、そのまま1回走らせられる。**

  5. **⛔ `LLMProvider` の適合 suite を、この PR では新設しない。**
     **1つの PR は1つの ADR とその実装**（`docs/autonomy.md` §2）であり、
     新設は Issue #142 の範囲を大きく超える。**別の issue に切る。**

  6. **⭐ `local` の live 15本を CI で走らせる形が可能であることを、
     判断材料として `docs/conformance.md` に残す**（§6）。**⛔ いまは採らない。**
     **後から誰かが決められるようにする**のが目的である。

  7. **`AGENTS.md` の「文書の地図」に `docs/conformance.md` の行を足す。**
     ⛔ それ以外の場所を触らない。

- **採らなかった案**:

  1. **「強い版」— `fixtures/real-ruri-embeddings.json` の実測値と、
     `live.local-embedding.test.ts` で成分ごとに厳密照合する**（Issue #142 の案(あ)）。
     ⭕ **材料は既に揃っている**——fixture には本物の推論値が在るのに、
     本物の onnxruntime を通す唯一のテストは次元数と類似度の大小しか見ていない【現物】。
     ⭕ repo / 量子化 / 変換の違いをほぼ確実に検出できる。
     ❌ **Issue #142 が「測る前に歯を足すな」と明示的に禁じている。**
     ❌ **そして、その歯は CI で走らない**（`MNEMORA_LIVE_LOCAL_EMBEDDING` が要る）。
     ⟹ **歯は増えるが「走る歯」は1本も増えない。**
     **この案は捨てていない**——`docs/conformance.md` §5 に「いつでも強い版にできる」と書いた。

  2. **「弱い版」— `extractor.model.config`（`model_type` / `architectures` /
     `_name_or_path` 等）を assert する。**
     ❌ 🔴 **実測で効かないと分かった。**
     【実測 2026-09-17】`sirasagi62/ruri-v3-30m-ONNX` の `config.json` の
     `_name_or_path` は **`cl-nagoya/ruri-v3-30m`**（ONNX の変換**元**）を指しており、
     **実際に読み込んだ repo id ではない。**
     ⟹ **同じ変換元から作られた別の ONNX repo に差し替えられても区別できない。**
     ⟹ **この案は、塞いだつもりで塞げていない形になる。**最も危険な種類の歯である。
     **⚠ この実測は Issue #142 本文にもコード内コメントにも無かった。**
     **`docs/conformance.md` §5 に根拠ごと残した**——次に同じことを考えた人が、
     同じ調査を繰り返さずに済むように。

  3. **`space.model` と `repo` の対応表を1箇所に持つ**（Issue #142 の案(い)）。
     ❌ issue 自身が退けている理由をそのまま採る——**宣言どうしの整合しか見ないので、
     「宣言と実物」のずれは相変わらず見えない。**

  4. **「強い版」＋ CI で `MNEMORA_LIVE_LOCAL_EMBEDDING` のジョブを足す。**
     ⭕ **鍵も課金も要らない**（要るのは重み42MBのダウンロードだけ）。
     ⭕ **CI は既に3ジョブで同じ重みを落としている**（`identifier-probes` /
     `consolidation-cost` / `archive-sweep-cost`）。
     ❌ **CI のジョブが1本増える**（13 → 14）。1周は壁時計 4〜9分である
     （[ADR 0183](./0183-local-postgres-makes-postgres-mutation-testing-possible.md) の実測）。
     ❌ [Issue #267](https://github.com/takecchi/mnemora/issues/267) が **CI の1周の費用を
     既に問題として挙げている。**
     ❌ **多数の担い手が並行して CI の緑を待っており、増分は全員に掛かる。**
     ⟹ **費用の理由で退けた。成立しないから退けたのではない。**
     **判断材料は `docs/conformance.md` §6 に残した。**

  5. **`LLMProvider` の適合 suite を、この PR で新設する。**
     ❌ **1 PR = 1 ADR の規律と衝突する**（`docs/autonomy.md` §2「ついでに直すをしない」）。
     ❌ Issue #142 の範囲を大きく超える。**別の issue に切る。**

  6. **v1.0.0 を止める。**
     ❌ **v1.0 の基準は北極星の7項目**（`docs/roadmap.md` §7.2）**であって、
     テストの網羅率ではない。**
     ⟹ **止めない。ただし「無い」ことを隠さない。**

  7. **`deterministic: false` を `true` に変える。**
     ❌ **測っていない。**Issue #142 が逐語で禁じている
     （「⛔ 『たぶん決定的だから』で変えないこと」）。

- **引き受けた負債**:

  1. **実 API には、この ADR の後も一度も当てていない。**手順を書いただけである。
     **v1.0.0 は「実 API に当てていない」ことを明示した状態で出る。**
  2. **`LLMProvider` の適合 suite は無いままである。**別の issue に切る。
  3. **「どのモデルを読み込んでいるか」の穴は塞いでいない。**記録しただけである
     （Issue #142 の案(う)）。
  4. **`local` の live 15本は走らないままである。**走らせる形が可能だと**書いただけ**である。
  5. **Issue #142 を閉じない。**本 ADR は2つの欠落のうち**どちらも塞いでいない**。
     **「名乗った」だけである。**

- **これが覆るとしたら**:

  - **鍵が渡されて実 API を測ったとき。**そのとき `docs/conformance.md` §4 の表は
    実測で置き換えられる。**⛔ 赤を消すために契約を書き換えないこと。**
  - **`repo` を差し替える運用が実在すると分かったとき。**そのとき「強い版」（案1）へ進む。
    **判断に要る材料は `docs/conformance.md` §5 に揃えてある。**
  - **CI の1周の費用が下がったとき。**そのとき案4（`local` の live を CI で走らせる）の
    釣り合いが変わる。**判断材料は `docs/conformance.md` §6 に在る。**
  - **`_name_or_path` 以外に repo id を同定できる経路が見つかったとき。**
    そのとき案2（弱い版）が復活しうる。

- **確かめていないこと**:

  - **実 API を測っていない**（上記の通り）。
  - **`_name_or_path` 以外の経路で repo id を同定できるかを、網羅的に調べていない。**
    実測したのは `config.json` の中身だけである。
  - **「`repo` を差し替える運用が実在するか」を測っていない。**
    ⟹ この穴が実際に踏まれうるかは、分かっていない。
  - **`local` の live 15本を実際に走らせていない**（重み42MBのダウンロードが要るため）。
    ⟹ **「走らせれば緑になる」ことは確かめていない。**走らせる**形が可能**だと言っただけである。
  - **`packages/anthropic` の固有テスト**（`llm-provider.test.ts` /
    `provider-parity.test.ts` / `json-schema.test.ts` / `refusal.test.ts`）**の中身を
    読んでいない。**⟹ README に「固有の検査は在る」と書いたが、**その検査が何を
    保証しているかは測っていない。**
  - **`packages/testkit` 以外の各パッケージ固有の unit テストを数えていない。**

- **歯**（`docs/autonomy.md` §2「歯が実際に噛むことを変異試験で示した」）:

  **本 ADR の変更は文書（`docs/conformance.md` / `packages/anthropic/README.md` /
  `AGENTS.md`）だけであり、実行されるコードを1行も足していない。**
  ⟹ **変異試験の対象が存在しない。**

  **⚠ これは「歯が要らない」ではない。**本 ADR の主張は
  **「何が測られていないかを正確に書いた」**であり、その正しさを担保するのは
  **住所（ファイル:行）と実測値**である。**上の「測ったこと」がその代わりを務める。**

- **出所について**:

  - **【現物】の本数と住所**は `main` = `18a8a09` を読んで数えた。
  - **【実測】の2つ**（`config.json` の中身、npm の公開版）は 2026-09-17 に取得した。
  - **【受】の部分**（2つの欠落の定義、`deterministic: false` の表、
    「測る前に歯を足すな」）は Issue #142 本文と ADR 0095 / 0099 / 0019 からの引用である。
  - **`LLMProvider` の suite が無いという指摘は、Issue #142 本文には無い。**
    本 ADR の調査で見つけたものである。
