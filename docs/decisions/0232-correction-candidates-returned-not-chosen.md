# ADR 0232: 訂正の相手は mnemora が選ばない — **候補を返し、採用者が選ぶ**（Issue #369 (C)）

- **状態**: 採用 (2026-09)
- **日付**: 2026-09-17

**⚠ 各主張の出所を分ける**（ADR 0132 / 0137 / 0183 / 0192 / 0228 / 0230 の体裁を踏む）。

- **【現物】** — この repo のコード・文書を書き手が読んで確かめた。
- **【実測】** — この書き手が自分の手で `git` / `gh` / `node` / `psql` 等を走らせて確かめた。
- **【受】** — 報告として受け取り、再導出していない（出所を明記する）。

---

## 問い

[Issue #369](https://github.com/takecchi/mnemora/issues/369) の (C)「訂正の口」は、
**採用側が「これは訂正である」とだけ宣言し、どの記憶の訂正かは mnemora が既存の recall で
探す**という形である。

**その「探す」がどこまで行ってよいか**が、この issue の未決の点だった。issue 自身が、
着手の前に測るべき項目としてこう書いていた【現物】:

> 🔴 **recall の1位が本当に「訂正された相手」である割合。**一度も測っていない。**低ければこの案の形が変わる**

**測った。⟹ この ADR は、その数字と、数字が決めた形を記録する。**

⭐ **この ADR の本体は実装の説明ではない。「機械が相手を選ぶ形を採らなかった理由」を、
数字とともに残すことである。**

---

## 決定

⛔ **採らない**: 機械が `recall` で相手を選び、そのまま `supersede` まで到達する形。

⭕ **採る**: **mnemora は候補を返すところまで。相手は採用者が選ぶ。**

**口の形**: `Runtime.findCorrectionCandidates(ctx, { text, limit?, excludeMemoryIds? })`。

- 採用側が「これは訂正だ」と判断した発話の `text` を渡す。
- mnemora は **既存の `recall()` を1回呼ぶだけ**で候補を返す。⛔ 新しい探索を書かない。
- ⛔ **書き込みを1件もしない。** `markContested` / `resolveContested` の**前**に立つ口であり、
  相手を確定して書き込むのは採用側である。
- ⛔ **LLM を1回も呼ばない。**
- ⛔ **新しい閾値を置かない**（後述の測定が、閾値では分離できないことを示した）。

## なぜこの数字がこの形を決めたのか

### 1. 🔴 **hit@1 = 100% は「機械が選んでよい」を意味しなかった**

**Issue #369 が測ろうとした量（hit@1）は、この案の危険を測っていなかった。**
危険は「相手が実在するとき当てられるか」ではなく、**「相手が実在しないときに手を止められるか」**
の側に在り、そこは **棄権 0/8・深い誤爆 6/8** である。

⟹ ⭐ **hit@1 だけを見ていたら「100% だから機械に選ばせてよい」と誤って読めた。**

### 2. Issue #369 が二段構えを取り下げた「理由4」は、数字に支持された

【現物】Issue #369 の[取り下げのコメント](https://github.com/takecchi/mnemora/issues/369#issuecomment-5701078690)は
逐語でこう書いている:

> **「勝者は人が決めた」とは言えなかった** …… (C) で人が渡すのは「これは訂正である」だけで、
> **相手は mnemora が recall で選ぶ**⟹ **相手が決まれば敗者は自動的に決まる**⟹
> **実質的に「誰が消えるか」を選んでいるのは推論である。**

⟹ **深い誤爆 75% は、その「推論で相手を選ぶ」ことの危険が実測されたということである。**

### 3. 「閾値が買えるのは頻度であって深刻さではない」も、数字に支持された

同じコメントの逐語【現物】:

> ⚠ **確からしさの閾値で倒す先を分ける案も支持されなかった** …… **閾値が買えるのは頻度で
> あって深刻さではない。**

⟹ **上のスコア表がそのとおりになった。**閾値を上げて落ちるのは A の正解であって、B の深い
誤爆ではない。

### 4. ⭐ この形は ADR 0223 決定2 と同じ形である

【現物】[ADR 0223](./0223-cross-cutting-disciplines-extracted-from-the-adr-corpus.md) 決定2 が
横断の規律を**一般形**として置いている。逐語:

> **歯（機械検査）の担当は「検出」までである。「確定」と「書き込み」は人に残す。そして機械が判定できなかったときは、従来どおりに倒さず赤／保留で止める。**

⚠ **この一般形が名指ししている主語は「歯（機械検査）」であり、実行時の口ではない。**
⟹ **この ADR は、その形を実行時の口へ広げて当てている。**広げてよいと判断した理由は、
一般形の後半（**判定できなかったときは通さず止める**）が、まさにこの測定で壊れた点
（**棄権 0/8 ＝ 止まれない**）と同じ場所を指しているからである。
⛔ **ADR 0223 が実行時の口についてこれを決めた、とは読まないこと。**

### 5. 北極星の項目5 は、この形でも満たせる

【現物】`docs/north-star.md` は「間違いを正すと、古いほうが先に出てこなくなる」と書いており、
**誰が選ぶかを書いていない。** ⟹ 採用者が候補から相手を選んで `markContested` →
`resolveContested({ kind: 'supersede' })` まで進めれば、項目5 は立つ。
⚠ **その経路を通すのはこの ADR の範囲外である**（下記「この ADR が着地させないもの」）。

## 設計で選んだこと

### 1. 口は `Runtime` の新しいメソッドにした（`observe()` のオプションにしない）

`observe()` にオプションを足すと、**取り込みの経路と探索の経路が1つの呼び出しに同居する**。
⟹ 「候補を返すだけ」であることが呼び出し側から見えなくなる。**別の口にすれば、
呼ばなければ今日と全く同じ挙動である**（Issue #369 本文の「問い2」）。

⚠ **`Runtime` interface にメソッドを足すのは、interface を自分で実装している側には
破壊的である。** 直前の `main` に入った `Runtime.restoreSuperseded`（[ADR 0230](./0230-restore-superseded-recovery-path.md)）
と同じ立場である。【現物】`docs/autonomy.md` §3 は、オーナーが 2026-09-15 にクローンへ直接回答した逐語「**破壊的変更であっても構わず実装してください**」を引き、
「**公開 API の破壊的変更も、ADR を書けば実装してよい**」と定めている（[ADR 0156](./0156-delegate-5-grade-judgment-and-breaking-changes.md)）。⟹ **この ADR がその「書くこと」に当たる。**

### 2. ⛔ 新しい閾値を置かない

**測定が「閾値では分離できない」を示した。** ⟹ 訂正用の閾値を足さず、既存の recall
パイプラインの既定をそのまま通す。**置くなら、なぜ置けるかを新しい測定で示す必要がある。**

### 3. 候補の既定件数は **3**

**強い根拠のある値ではない。**根拠にできるのは測定の次の2つだけである:
gold が **15/15 で1位**、distractor が **14/15 で4位以内**。
⟹ **3件あれば「正解」と「紛らわしい対抗」が採用者の目に入る。**
⚠ **これは裁量値である。**`limit` で呼び出し側が上書きできる。

### 4. ⭐ `recallRank` を詰め直さない

`excludeMemoryIds` で候補を除いても、残った候補の `recallRank` は
**`recall()` が返した並びでの順位のまま**にする。
⟹ 採用者が「これは recall の何位だったか」を説明に使えるようにするため
（北極星の問い3「なぜそれを思い出したのかを、後から説明できる」）。

### 5. 「見つからなかった」と「探していない」の扱い

⛔ **この口に「探していない」状態は無い**——必ず `recall()` を1回呼ぶ。
「見つからなかった」は `outcome: "no_candidates"` と、`recall()` から素通しした `omitted`
の両方で説明される（`omitted` が**なぜ**返らなかったかを持つ）。

## 歯が噛むことを示した【実測】

**変異は `cp` で退避・復元した**（⛔ `git checkout` は使っていない）。

| 変異 | 赤くなった歯 |
|---|---|
| `recallRank` を「除外後に詰め直した順位」に変える | 「`excludeMemoryIds` が効く」1本だけ |
| `limit` の切り取りを外す | 「`limit` を守る」2本 |
| `excludeMemoryIds` の除外を外す | 「除外が効く」＋「全部除外したとき候補0件」2本 |
| ⭐ **結果を返す前にイベントを1件積む**（＝書き込む） | 🔴 **「書き込みを1件もしない」1本だけ**（他10本は緑のまま） |
| ⭐ **`deps.llmProvider.complete()` を1回呼ぶ** | 🔴 **「LLM を1回も呼ばない」を含む6本**（⚠ 多くの歯の擬似 LLM が `complete` で落ちるため、この変異は切り分けが粗い） |

⚠ **上の2つの変異（書き込み／LLM）を入れるとき、1回目は無効だった**——シェル越しに埋め込んだ
コードの引用符が落ち、**構文エラーで全件が赤くなっただけ**だった。⛔ **それを「歯が噛んだ」と
読まずに、書き方を直してやり直した**（正しく書いた版では、書き込みの変異は**狙った1本だけ**が
赤くなった）。⟹ ⭐ **この ADR は同じ間違いを2度記録している**——測定の器でも、実装の歯でも、
**「赤くなった」だけでは壊したのが狙ったものかどうかが分かれていない。**

## 引き受けた負債

### 1. 🔴 候補を返すだけなので、**採用者が黙って1位を採れば、測定が示した危険はそのまま残る**

この口は「候補を出す」ところまでしか責任を持たない。**採用側が候補[0] を機械的に採る実装を
書けば、深い誤爆 75% はそのまま再現する。**
⟹ **この ADR が買ったのは「mnemora が勝手に消さない」ことだけであり、
「誰も間違えない」ことではない。**

### 2. 誤爆率・棄権率を守る歯が無い

この PR が足した歯は `findCorrectionCandidates` の契約（書き込まない・LLM を呼ばない・
`limit`・除外・順位）についてのものであり、**「誤爆率がこれ以上悪化したら赤くする」門は無い。**
ベンチは測るだけである（`scripts/retrieval-quality-summary.mjs` が exit 0 なのと同じ立場。
[ADR 0088](./0088-retrieval-quality-measured-in-ci.md)）。
⟹ ⚠ **n=8 では偽陽性率に上限を置けない。**門にするなら別途、
[ADR 0223](./0223-cross-cutting-disciplines-extracted-from-the-adr-corpus.md) 決定3 に当てて判断すること。

### 3. ベンチは CI に配線していない

`correction-candidates` サブコマンドは手で走らせるものであり、CI ジョブを足していない。
⚠ [Issue #217](https://github.com/takecchi/mnemora/issues/217) が「probe を作ったが CI に
配線しなかった」形で残債になった前例がある。**同じ形の残債である。**

## ⛔ 確かめられなかったこと

1. 🔴 **実 API 経路では測っていない。** LLM が `deterministic`（発話を40字で切る）なので
   `digest` は発話そのままである。実 API の抽出は要約・言い換えをするため
   （[ADR 0052](./0052-compare-cassette-and-provenance-survival.md)）、**類似度の並びが
   変わりうる。**
2. 🔴 **規模は 96件だけである。** [Issue #377](https://github.com/takecchi/mnemora/issues/377)
   は「1万件では probe 自身の anchor が上位3件から押し出される」と実測している。
   ⟹ **hit@1 = 100% が規模で保つかは測っていない。**
3. **「訂正を `observe()` してから自己を除外して探す」形は測っていない。** ベンチは
   自己一致を避けるため訂正の発話を `observe()` する前に測っている。
   ⟹ `excludeMemoryIds` はその形のために在るが、**その形での的中率は未測定である。**
4. 🔴 **B 群の誤爆率に代表性は無い。** ケースは「守るべき事実が最近傍に来るように」書いてある。
5. **揺れは2回ぶんしか見ていない。** `fixedClock` を注入していない。
6. **[Issue #207](https://github.com/takecchi/mnemora/issues/207) /
   [#293](https://github.com/takecchi/mnemora/issues/293) /
   [#284](https://github.com/takecchi/mnemora/issues/284) のコメント全文は読んでいない**
   （重複の有無は本文と、コメント全文検索 `gh search issues --match comments` で確かめた）。

⚠ **一般化しないこと**:

> **この測定は `deterministic` LLM・96件規模・手書き23件での結果である。
> 実 API 経路・1万件規模・代表性のある母集合では測っていない。**

---

## これが覆るとしたら

- **実 API の抽出を通した digest で測り直したら、B 群の深い誤爆が大きく下がったとき。**
  ⟹ 「機械が選ぶ」を再検討する材料になる。⛔ **ただし棄権率が 0% のままなら、
  「止まれない」という性質は変わらない。**
- **「訂正である」という宣言に加えて、採用側が『何についての訂正か』を渡せる形が入ったとき。**
  ⟹ B 群の別人・別期間は、主語や期間が渡れば落とせる可能性がある。
  ⚠ **それは (C) ではなく (B)（主張キー、Issue #370 / #371）の領域である。**
- **候補を人に見せる経路そのものが要らないと判断されたとき**（例: 訂正を `contested` で
  止める形に戻す）。

---

## 採らなかった案

### 1. 確からしさの閾値で「`supersede` まで進む／`contested` で止める」を分ける（二段構え）

⛔ **測定が落とした。**A と B のスコアが重なっており、閾値は「頻度」しか買えない。
Issue #369 自身も[取り下げのコメント](https://github.com/takecchi/mnemora/issues/369#issuecomment-5701078690)で
先に落としている——この ADR は**その判断に数字を付けた**だけである。

### 2. `contested` までで止める（Issue #369 本文の当初の条件）

⛔ **採らない理由は「悪い」からではなく「この ADR の範囲ではない」から。**
`contested` にするかどうかは**相手が確定してからの話**であり、この口は相手の確定より手前に立つ。
⟹ **候補を受け取った採用側が `markContested` を呼ぶかどうかは、採用側が決める。**

### 3. `recall()` 自体に「訂正モード」を足す

⛔ 既存の測定（`compare` / `retrieval` / 各 probe ベンチ）が乗っている経路を変えることになる。
**新しい探索を書かない**という Issue #369 本文の要求にも反する。

### 4. 候補を返すときに distractor を機械的に除く

⛔ **できない。**「同じ話題・違う主語」を機械が見分けられるなら、そもそも相手の特定が推論で
なくなる。**測定の distractor 逆転率 0% は、distractor が『下にいる』ことを示しただけで、
『見分けられる』ことを示していない。**
