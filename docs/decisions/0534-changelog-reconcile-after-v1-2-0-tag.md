# ADR 0534: CHANGELOG と migration-v1 の帳尻 — `v1.2.0` の tag より後に着地した #1615（ADR 0521）・#1616（ADR 0525）の項目を `[1.3.0]` 側へ移し、`[1.3.0]` の冒頭の「まだ何も棚卸ししていない」を直す

- **状態**: 採用 (2026-10)
- **日付**: 2026-10-02

クローン miku の委譲先（担い手。マネージャー mgr-0d3098f9 の指示による）が書いた。移す・戻すという判断は依頼主が決めた（前例はオーナー自身の #1619。0499・0502・0504 の分を同じ基準で `[1.3.0]` へ移した）。オーナーの判断ではない（[ADR 0220](./0220-issue-comment-author-does-not-distinguish-owner-from-agent.md)）。
出所の区別: 【現物】は読んだコード・文書・コマンドの出力、【判断】は担い手の判定、【未確認】は確かめていないこと。

## 根拠【現物】

```
$ gh release view v1.2.0 --json tagName,publishedAt,targetCommitish
{"publishedAt":"2026-10-02T05:55:45Z","tagName":"v1.2.0","targetCommitish":"d49c46c26748692e9f69f5d0c5729169ef7a1ef3"}
$ git rev-parse v1.2.0^{commit}
d49c46c26748692e9f69f5d0c5729169ef7a1ef3        # PR #1613（ADR 0522）の commit
$ gh pr view 1615 --json mergedAt,mergeCommit    # eb168b70
2026-10-02T05:37:57Z
$ gh pr view 1616 --json mergedAt,mergeCommit    # 6c000d8d
2026-10-02T05:47:05Z
$ git merge-base --is-ancestor eb168b70 v1.2.0   # → no （#1615 は v1.2.0 の tag に入っていない）
$ git merge-base --is-ancestor 6c000d8d v1.2.0   # → no （#1616 は v1.2.0 の tag に入っていない）
$ git merge-base --is-ancestor v1.2.0 eb168b70   # → yes
$ git merge-base --is-ancestor v1.2.0 6c000d8d   # → yes
```

- `v1.2.0` の tag は `d49c46c`（PR #1613）を指す。#1615（ADR 0521）と #1616（ADR 0525）は、**この tag の後**に `main` へ入った（どちらも tag の子孫で、祖先ではない）。マージの順は #1615（05:37:57Z）→ #1616（05:47:05Z）→ Release の公開（05:55:45Z）。マージの時刻は Release の公開より前だが、tag の指す commit は2本のマージより前で、tag にも Release の `targetCommitish` にも2本は含まれない。
- したがって、出荷された `v1.2.0` には #1615・#1616 の変更は入っていない。`[1.2.0]` 節と「v1.1.0 → v1.2.0」の節に残っていたこの2本の項目は、出荷物と食い違う事実の誤りだった。【未確認】npm に出た tarball の中身そのものは見ていない（tag の commit から作られる前提）。

3. **#1624（ADR 0527）の migration の🟡は足さない**（依頼主の判断。断る入力も例外の種類も変わらず、大文字の id を渡した場合に書かれる綴りが変わるだけ）。

## 触らなかったもの【判断】

- `[1.2.0]` の他の箇所。特に、l.105 の「`d49c46c`（PR #1609）」（`d49c46c` は #1613 の commit で、#1609 は `b19115dc`）の取り違えと、ADR 0472・0500・0423 の事実の誤りは、依頼主からオーナーに伝える。この PR の `[1.2.0]` 節の差分は、移した跡（項目の削除2行と空行1行）と、ADR 0525 の注記を外した跡（1行）だけ。
- migration の「v1.2.0 → 次の版」🟡 の既存の追記（「下の2項目は…」）。移した項目が加わって、その文の「2項目」は実際の項目数と合わなくなる。件数を書き換える方針ではない（ADR 0234）ので直していない。
- 「v1.1.0 → v1.2.0」の🔴の見出しにある件数（「確定は CHANGELOG の `### Breaking` で22件」など）は、今回移したものが `### Breaking` の項目ではない（ADR 0525 は非破壊の Changed、ADR 0521 は Fixed）ので、数は変わらない。

## 検討した代替案

1. **`[1.2.0]` に残し、注記で「tag より後」と書く**。採らなかった。Release に出た節に、出荷物に無い変更が載ったままになる。
2. **項目56から ADR 0525 の注記を外さず、`[1.3.0]` にも同じ文を書く**。採らなかった。出荷された `v1.2.0` の項目56が、出荷物に無い振る舞い（bullmq の例外型）を言ってしまう。
