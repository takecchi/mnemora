# ADR 0507: 言語の事後検査（ADR 0391）の観測側の数えを、観測ごとに1回へ畳む（判定は変えない）

- **状態**: 採用 (2026-10)
- **日付**: 2026-10-02

クローン miku の決定。担い手が書いた。オーナーではない（ADR 0220）。[ADR 0490](./0490-language-mismatch-latin-letters-only.md) の「材料」2番（観測の数え直しが候補ごと）を、判定を1バイトも変えずに直した。

出所の区別: 【現物】は読んだコード、【実測】は手元で走らせた結果、【判断】は担い手の判定、【未確認】は確かめていないこと。

- **文脈**: `buildCreatedEventFor`（`packages/core/src/runtime.ts`）は候補（Memory）ごとに呼ばれ、そのたびに `detectLanguageMismatch(observationPayloadText(observation), memory.content)` が観測の本文を合成して、かな・漢字とラテン文字を数え直していた【現物】。ADR 0490 の実測は、33万字の観測で1候補 62 ms（100 候補で約6秒の同期 CPU）。

## 決めたこと

1. **観測側の数え**（本文の合成と、かな・漢字・ラテン文字の数）を、観測ごとに1回にした。`packages/core/src/language-mismatch.ts` に `profileObservationLanguage`（観測の本文 → `{ cjk, latin }`）と `detectLanguageMismatchFromProfile`（数え済みの観測 × 本文 → 判定）を足し、`detectLanguageMismatch(観測, 本文)` は両者の合成にした（同じ結果）。どれも `index.ts` から export しない（公開 API は変えない。`pnpm api:check` に出ない）。
2. **候補ごとに変わる部分は、候補ごとに計算する**: 本文のかな・漢字の有無、コード片、URL の除去、ラテン文字の数と割合、小文字語の数。観測の側で畳むのは、候補に依らない数だけ。
3. **畳む場所**: `runtime.ts` の `observationLanguageProfileOf`。`Observation` のオブジェクトを鍵にした `WeakMap`。同じ抽出の候補は同じオブジェクトを `buildCreatedEventFor` に渡す【現物】（sync・deferred・`reextract`、store が同じトランザクションで呼ぶ `buildCreatedEvent` の経路のどれも）。`buildCreatedEventFor` とその呼び出し側の引数は増やしていない。観測が捨てられれば項目も消える。
4. **観測のかな・漢字が下限（4字）に満たないとき、ラテン文字は数えない**（判定に使われないので結果は同じ。巨大な非日本語の観測の数えが半分になる）。
5. 判定の結果・`rule`・`languageMismatch` の印・閾値・ADR 0490 の判定基準は変えない。

## 採らなかった案

- **`buildCreatedEventFor` に数え済みの引数を足して呼び出し側から渡す**: 呼び出し側が複数あり、`reextract`・store の callback まで引数を通す必要がある。`WeakMap` なら入口を1つに保てる。引数を通す案のほうが明示的なので、負債の節に残す。
- **判定の結果そのものを観測ごとに畳む**: 本文が候補ごとに違うので、結果が変わる（誤り）。変異試験で歯が赤になることを確かめた。
- **時間で縛る歯**: フレークのもと。呼び出し回数で縛った。

## 歯

`packages/core/src/__tests__/language-mismatch-count-once.test.ts`。

- (a) 振る舞いが変わらない: 畳む前の `detectLanguageMismatch`（ADR 0490 時点）を歯の中に写して参照実装にし、観測13種（空・かな・漢字だけ・下限の手前・ラテン・混在・ローマ数字・ハングル・巨大）× 本文12種（空・短い・固有名詞・コード片・URL・かな混じり・キリル・巨大）の全組で、`detectLanguageMismatch` と `detectLanguageMismatchFromProfile`（観測を1回数えて使い回す）の両方が参照実装と `toStrictEqual` で一致する。陽性対照として、組の中に印が付くものと付かないものの両方が10組以上在ることも縛る。
- (b) 畳めている: `vi.mock` で `profileObservationLanguage` の呼び出し回数を数え、候補 1・5・40 件の `observe` で呼び出しが1回であること、`observe` を2回呼べば2回であること（観測をまたいで使い回さない）を縛る。印は偶数番目の候補にだけ付く（候補ごとの判定が生きている）ことも同じ歯で縛る。
- 既存の `language-mismatch.test.ts`・`language-mismatch-mark.test.ts` は変えずに緑。

## 測ったこと

- 【実測】赤→緑: (b) を、直す前（`runtime.ts` の `WeakMap` を引かず毎回数える形）で走らせると、161 件中 3 件が赤（候補 5 件・40 件・「2回呼べば2回」が、呼び出し 5・40・4 回で赤。候補 1 件は直す前でも1回なので緑のまま）。(a) は直す前の実装と同じ関数を比べるので緑。直して、新しい歯と既存の2ファイルの計 184 件が緑。
- 【実測】変異: (1) 候補ごとに戻す → 上の 3 件が赤。(2) 結果そのものを観測ごとに畳む（`runtime.ts`） → (b) の 5 件・40 件が赤（印の数が合わない）。(3) 結果そのものを観測ごとに畳む（`detectLanguageMismatchFromProfile` の側） → 161 件中 20 件が赤（(a) の参照実装との一致が崩れる）。戻して緑。
- 【実測】時間（手元の1回。門にしない）: 33万字（`今日は渋谷のパン屋で働いています。…` を1万行）の観測 × 100 候補で、判定だけ（`runtime` の外）を3回測って、候補ごとに数え直す形 4.7〜5.0 秒、観測を1回数えて使い回す形 54〜73 ms（3回の範囲）。ADR 0490 の「約6秒」と同じ桁。ふつうの大きさ（数千字）では差は無視できる。

## 引き受けた負債

- `WeakMap` は「同じ観測なら同じオブジェクトが渡る」ことに頼る。別のオブジェクトを渡す呼び出し側が増えると、畳みが効かなくなる（結果は正しいまま、遅いだけ）。歯 (b) がそれを呼び出し回数で捕まえる。
- `Observation` のオブジェクトを書き換えてから同じオブジェクトで呼ぶ経路は無いと【判断】した（読み取り専用の値として扱われている）。【未確認】: 全経路の網羅的な確認はしていない。
- 本文の側（候補ごと）の数えは、本文が巨大なら本文の長さに比例する。今回は触っていない。

## これが覆るとしたら何が起きたときか

- `Observation` が呼び出しの途中で書き換わる経路が見つかったとき: 鍵を `Observation` のオブジェクトから、本文の文字列を使う形（または引数で通す案）に改める。
- 判定が観測と本文の相互作用（観測の数に応じて本文の閾値が動く等）を持つ規則に変わったとき: 観測側だけの畳みが成り立たない。
