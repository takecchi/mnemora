# ADR 0149: 日本語の語を語彙チャンネルで引けるようにするため `REQUIRED_EXTENSIONS` を増やさない — 「引けない」を明記する

- **状態**: 採用 (2026-09)
- **日付**: 2026-09-16

**⚠ 各主張の出所を分ける**（[ADR 0084](./0084-lexical-recall-channel.md) /
[ADR 0092](./0092-lexical-or-coverage.md) の体裁を踏む）。

- **【受】** — マネージャーから受け取った判断・理由。この ADR の書き手が新たに実測し直してはいない。
- **【現物】** — この repo のコード・文書を読んで確かめた。
- **【実測】** — [ADR 0084](./0084-lexical-recall-channel.md) が本物の PostgreSQL に対して
  行った実測を、この ADR が引用している箇所。**この ADR 自身が新たに測ったものではない**
  （下記「確かめていないこと」参照）。

---

## ⚠ この ADR が言っているのは何であって、何でないか（先に区別する）

**この ADR が決めるのは「必須依存にはしない」であって、「日本語を引けるようにしない」ではない。**

- `docs/north-star.md`「やらないこと」（オーナーが仕様 §41 に明示した非目標の一覧）に、
  「日本語の語彙検索」のような項目を**足していない。足さない。**その一覧の追加・削除は
  オーナーの判断であり（`docs/north-star.md` 末尾）、この ADR の射程ではない。
- この ADR が閉じるのは「`REQUIRED_EXTENSIONS` を増やすかどうか」という、**全導入者への
  条件追加の可逆性**についての判断だけである。「日本語の語を将来も永久に引けないままにする」
  という決定ではない——[ADR 0084](./0084-lexical-recall-channel.md) §3.4・§9 が既に
  「`pg_trgm` / `pg_bigm` / `pgroonga` を採らないと決めたわけではない。いま必須にしないと
  決めた」と書いている立場を、この ADR は引き継いでいるだけである。

---

## 文脈

**[Issue #139](https://github.com/takecchi/mnemora/issues/139)**（[Issue #106](https://github.com/takecchi/mnemora/issues/106)
から切り出された残件）が、[ADR 0084](./0084-lexical-recall-channel.md) §3 の帰結として残った
判断——**「日本語の文に埋もれた日本語の語（人名を含む）は語彙チャンネルで引けない。
これを埋めるために `REQUIRED_EXTENSIONS` を増やすか」**——を問うている。

**【現物】いま何が引けないか**: `PostgresLexicalStore` の索引・クエリは
`to_tsvector('simple', …)`（組み込み、分かち書きをしない）を使っており
（[ADR 0084](./0084-lexical-recall-channel.md) §1・§4.1）、クエリ側は非 ASCII の連なりを
空白に落とす（`mnemora_lexical_query_terms`、[ADR 0084](./0084-lexical-recall-channel.md)
§2.1.1）。**⟹ クエリ全体が日本語の場合、クエリ側の語彙が1つも残らず、語彙チャンネルは
常に0件を返す。**

**【現物】この Issue の閉じる条件は、既に歯として在る。**
`packages/postgres/src/__tests__/lexical-store-reporter-questions.test.ts` の8本のうち
歯6（「6. 🔴 人名（日本語）は今も引けない」）が、本物の PostgreSQL に対して
「田中さんについて何か言ってましたか」で0件を assert している。**この ADR はこの歯を
消さない・緩めない**（§5「実装」参照）。

**Issue #139 が並べた3案**:

- (a) `pg_trgm` を `REQUIRED_EXTENSIONS` に足す
- (b) `pg_bigm` / `pgroonga` を `REQUIRED_EXTENSIONS` に足す
- (c) 要求しない（現状維持。ただし「引けない」を明記するかは別途決める）

---

## 決めたこと

**【受】(c) を採る。`REQUIRED_EXTENSIONS` を増やさない。`pg_trgm` / `pg_bigm` / `pgroonga` の
いずれも必須にしない。** ただし「何もしない」ではない——次を実装する:

1. **「日本語の語は語彙チャンネルで引けない」を、導入を検討する人が読める場所に明記する**
   （§5.1）。
2. **「引ける」と誤読させない**——日本語表記のチャンネル名・システム名にも実測・歯が無いことを、
   「確かめていない」と明記する（§5.1・§5.2）。
3. **既存の歯（歯6）を消さない・緩めない**（§5.3）。
4. **将来「任意の拡張」を許す方向を ADR に書くが、この PR では実装しない**——follow-up issue
   [#278](https://github.com/takecchi/mnemora/issues/278) を立てた（§6）。

---

## なぜ (a)(b) を落としたか — 北極星の問いに当てる

**⭐ この Issue は他の3件（#106 から分岐した残りの案件）と性質が違う。**
「運用者に新しい必須依存を課す」判断であり、**可逆性が低い**——一度リリースした
`REQUIRED_EXTENSIONS` に依存した導入が広がった後で取り下げるコストは、
実装しなかったものを後から足すコストより高い。だからこそ北極星の問い2を強く当てた。

### 問い2（これを無効にしたとき、Memory Framework として成立するか）が決め手

**オーナーの設計原則 §42-6 逐語「Background Cognition を無効にしても Memory Framework として
成立する」の精神は「これが無いと動かない」を増やさないことである。**
**⟹ 必須拡張を1つ増やすことは、全導入者にとって「これが無いと動かない」を1つ増やす。**
買えるものは「日本語の固有名詞1点」（[ADR 0084](./0084-lexical-recall-channel.md) §3.1
の実測——`pg_trgm` の `word_similarity` で拾えるのは人名のような固有名詞だけで、
`納期` のような一般語は2文字では `%>` が立たず引けないまま）であり、
**全導入者への条件追加とは釣り合わない。この問いで (a)(b) は落ちる。**

### 問い3（選ばれた理由を後から説明できるか）が (a) にさらに追い討ちをかける

**Issue が実測している通り**（[ADR 0084](./0084-lexical-recall-channel.md) §3.2 の【実測】）、
**`C` ロケールのクラスタでは `pg_trgm` の日本語トライグラムが空になり、黙って0件を返す**:

```
show_trgm('田中さん')  --> {}          （空）
similarity('田中さんが請求書を…','田中さん') --> 0
'田中さんが請求書を…' %> '田中さん'          --> f
```

**⟹ 「引けない」が「引けた（0件）」の顔をする。**導入者は語彙チャンネルが動いていると
信じたまま、日本語の想起だけを永久に落とす。**これはいまの状態（引けないと歯が明示している）
より悪い**——説明可能性を失う方向であり、**問い3 で落ちる。**
`AGENTS.md`「擬似物へ黙ってフォールバックしない」・北極星「『見つからなかった』と
『探していない』を、同じ顔で返さない」に、この形は正面から反する。

### 問い1（毎回渡す量を減らす方向に働くか）は中立

**語彙チャンネルは埋め込みを増やさずに候補を作るので方向は正しい**が、
**全導入者への条件追加という代償は、量の削減には何も寄与しない。**
この問いだけでは (a)(b) を積極的に推す材料にはならない。

### (b) はそもそも実測できていない

**Issue が実測している通り**、`pg_bigm` / `pgroonga` は測定に使った器に control ファイルが
無く `CREATE EXTENSION` が通らなかった。**⟹ 「動く」とも「動かない」とも言えないものを
必須にすることはできない。**判断材料そのものが無い。

---

## 何を落としたか

- **(a) `pg_trgm` を必須にする案**——日本語固有名詞を語彙的に引けるようになったはずだが、
  **全導入者への条件追加**と**`C` ロケールでの静かな0件**を引き受けることになる。上記の
  問い2・問い3で落ちる。
- **(b) `pg_bigm` / `pgroonga` を必須にする案**——実測できていないものを必須にできない。

---

## 5. 実装 — 何を変えたか

### 5.1 「引けない」を、導入を検討する人が読める場所に明記する

**【現物】`docs/recall.md` は既に ADR 0084 §2 を引いて「語彙チャンネルは日本語の文に
埋もれた日本語の語（人名を含む）を引けない」と書いていた**（段1の節、2026-09-10 追記）。
この ADR は**そこに本 ADR への参照を足し**、**「確かめていないこと」（§5.2）へ繋げる
1文を追加した**——「ここから読者が『日本語が引けない』という帰結に辿り着けるか」を
確かめたところ、**辿り着けてはいたが、この ADR への参照が無かった**ため、繋いだ。

**【現物】`packages/postgres/README.md` には、語彙チャンネル自体の言及が1つも無かった**
（「前提」節は接続に要る3拡張のみを列挙し、語彙検索の機能面には触れていない）。
**⟹ ここが「明記するかを決める」の実質的な空白だった。** 「前提」節の3拡張の直後に、
**追加の拡張を要求しないこと・その代償として日本語の語は引けないこと**を明記し、
本 ADR と [ADR 0084](./0084-lexical-recall-channel.md) §3 を参照させた。

### 5.2 ⚠ 「引ける」と誤読させない — 確かめていないことを確かめていないと書く

**Issue #139 が明示している通り、日本語表記のチャンネル名・社内システム名には実測も歯も
無い**（[Issue #106](https://github.com/takecchi/mnemora/issues/106) で ✅ を付けた分は
すべて ASCII 表記（`#proj-alpha` / `gurumi-chan-backend`）での実測である）。

**⟹ `docs/recall.md` と `packages/postgres/README.md` の両方に、次を明記した**
（`AGENTS.md`「確かめていないことは『確かめていない』と書く」の規律そのもの）:

> 人名だけでなく、日本語表記のチャンネル名・システム名も同じ穴に落ちる可能性が高いが、
> 確かめていない。

### 5.3 既存の歯（歯6）を消さない・緩めない

**⛔ 絶対条件。**`lexical-store-reporter-questions.test.ts` の歯6
（「6. 🔴 人名（日本語）は今も引けない」）は**この Issue の閉じる条件そのもの**である
（Issue #139 の逐語）。この PR は歯の assertion を1つも変えていない——
**コメントにこの ADR（0149）への参照を足しただけ**であり、期待値・入力・
`expect(hits).toEqual([])` はそのままである。

**⟹ 文書（§5.1・§5.2）と歯（歯6）が同じことを言っている状態になった。**
どちらかを直してもう片方を直し忘れる形（`AGENTS.md`「複製した瞬間から正文と要約はずれ始める」）
を避けるため、歯のコメントは「この ADR を読めばなぜこの歯が緑であり続けるべきかが分かる」
形にした。

### 5.4 やっていないこと

- **`REQUIRED_EXTENSIONS`（`packages/postgres/src/migrate.ts`）を1バイトも変えていない。**
- **migration・実行時の拡張検出・ロケール検査には踏み込んでいない。**これらは
  「任意の拡張」を実装するときに要るものであり、この PR の射程を超える（§6）。
- **`docs/north-star.md`「やらないこと」への追記はしていない**（冒頭の区別の通り、
  この ADR の射程ではない）。

## 6. 将来の方向 — 「任意の拡張」の形だけを許す

**この PR では実装しない。** migration・実行時検出・ロケール検査に踏み込むため、
Issue #139 の射程を超えると判断した。**代わりに follow-up issue
[#278](https://github.com/takecchi/mnemora/issues/278) を立て、そこから本 ADR を指した。**

**方向として許すのは次の形だけである**——`LexicalStore` は既に独立した interface として
切られているので（[ADR 0084](./0084-lexical-recall-channel.md) §4.1・§3.4）、
**「拡張が在れば効く／無ければ語彙チャンネルの日本語カバレッジが縮むだけ」**という
任意（optional）の実装を、導入側が差し替えて使える形にする。**必須にはしない。**

**⚠ Issue #139 の逐語の指摘を、follow-up issue に必ず持たせた**——
**採るなら、`C` ロケールで黙って0件になる静けさを潰す仕組みが同時に要る。**
`pg_trgm` を任意で使えるようにするだけでは§3.2 の穴がそのまま残る。
拡張の実在だけでなく、ロケールが日本語のトライグラムを作れる状態かどうかまで検査し、
検査結果を呼び出し側に伝える機構が要る。

## 引き受けた負債

- **🔴 日本語の文に埋もれた日本語の語（人名を含む）を、今も語彙チャンネルで引けない**
  （[ADR 0084](./0084-lexical-recall-channel.md) §2/§8 からの継続）。
- **🔴 日本語表記のチャンネル名・社内システム名についても、引けるかどうかを確かめていない**
  ——人名と同じ穴に落ちる可能性が高いと考えているが、実測していない（Issue #139）。
- **文書が「明記した」ことと「機構として検査される」ことは別である。**
  README・`docs/recall.md` の記述は、`AGENTS.md`「複製した瞬間から正文と要約はずれ始める」の
  対象になりうる——歯6が唯一の機械的な歯止めであり、文書はそれを補うだけである。

---

## これが覆るとしたら

- **日本語の想起が製品の主要な要件になったとき。**そのときは (a)(b) の代償
  （全導入者への条件追加、または実測できていないものを採用するリスク）を、
  再度オーナー判断として引き受けるかどうかを問い直す。
- **ロケール依存の静かな0件を確実に検出できる仕組みが手に入ったとき。**
  §3.2 の「`C` ロケールで黙って空になる」問題を、実行時検査で確実に呼び出し側へ
  伝えられるようになれば、問い3で (a) を落とした理由が消える。follow-up issue
  [#278](https://github.com/takecchi/mnemora/issues/278) はこの条件を先取りして
  検討する場である。
- **分かち書き（トークナイザ）を拡張なしで持てるようになったとき。**
  PostgreSQL 本体または依存の追加を要さない形で日本語の分かち書きが手に入れば、
  この ADR が問うている「必須依存を増やすかどうか」という前提そのものが変わる。

## 確かめていないこと

- **この ADR 自身は、[ADR 0084](./0084-lexical-recall-channel.md) が行った `pg_trgm` の
  ロケール実測・`websearch_to_tsquery` の実測を再実行していない。**すべて ADR 0084 からの
  引用であり、出所を【実測】ではなく引用として明示している。
- **歯6を含む DB 段のテスト（`lexical-store-reporter-questions.test.ts` 全8本）を、
  この作業環境では実行していない**（`DATABASE_URL` が無い。`AGENTS.md`・
  `docs/autonomy.md` §1.1 の通り）。コメントを足しただけで assertion は変えていないため
  挙動が変わるとは考えていないが、**CI の実行結果でのみ確かめられる。**
- **follow-up issue [#278](https://github.com/takecchi/mnemora/issues/278) に書いた
  「任意の拡張」の実装可能性そのもの**（`LexicalStore` の差し替え機構が、拡張の有無・
  ロケール検査を含めてどこまで簡単に書けるか）は検討していない。設計はそこで行う。
