# ADR 0707: `recall()` の忘却ゲートを既定では掛けない（`includeFullyDecayed` の既定を `true` にする）——ADR 0153 の既定を覆す

- **状態**: 採用 (2026-11)
- **日付**: 2026-11-10

**方向はオーナーの指示である。**オーナーのコメント「消えるというか薄れていくべきではないでしょうか？」（2026-11-10、対話セッション。出所の限界は [ADR 0704](./0704-recall-time-weight-floor.md) の冒頭と同じ）を受けた、2つ目の変更である。PR の切り方と既定値は担い手（Claude Code）の判断。Issue #2121。

**⚠ この ADR の番号は仮である。** マージの直前に `node scripts/adr-renumber.mjs` が確定する（[ADR 0179](./0179-adr-number-assigned-at-merge.md)）。

## 文脈

- [ADR 0153](./0153-recall-decay-floor-gate.md) は、忘却ゲート（`decayFloorAt` を過ぎた記憶を recall の候補から外す）を、opt-out の形で既定で効かせた。「使われない記憶が、静かに遠ざかる」を、掃引を呼んでいない期間にも効かせるためである。
- だが、ゲートは**時間だけで**候補から外す。問いとの関連がどれだけ強くても、`decayFloorAt`（既定で作成から約130日）を過ぎた記憶は返らない。正典「必要な場合だけ過去の記憶を再び呼び戻せる」と両立しない。
- [ADR 0704](./0704-recall-time-weight-floor.md) は時間の重みに下限を置き、時間を「順位を下げる」ことだけに使うようにした。ADR 0704 の測定（ゲートを外して測った）では、休眠の事実は90日まで 7/8 を保ち、その後は新しい記憶との競争で薄れていった。⟹ 下限とゲートを組み合わせると、約130日の時点で、薄れる途中の記憶が一斉に消える崖が残る。

## 何を決めたか【判断】

1. **`includeFullyDecayed` の既定を `true` にする**（`DEFAULT_INCLUDE_FULLY_DECAYED`）。既定の `recall()` は忘却ゲートを掛けず、減衰しきった記憶も候補に残る。`explain` の `decayGate` は `"disabled"` になり、`omitted` の `filtered(decayed)` は積まれない。
2. **`includeFullyDecayed: false` で、従来のゲートに戻せる。**ゲートの実装（ANN への押し下げ・語彙の後置フィルタ・omission の報告）は、そのまま残す。
3. **掃引（`sweepArchive`）は変えない。**減衰しきった記憶を `archived` にする明示的な操作で、archive された記憶は今までどおり返らない。「使われない記憶を落とす」が要る運用は、掃引を明示的に呼ぶ。
4. **ゲートの振る舞いを縛るテストには `includeFullyDecayed: false` を明示した**（見ているものを変えないため）。既定でゲートが掛からないことを縛る歯を新しく足した。

## 互換性

- 型は変わらない。既定の振る舞いが変わるので 🟡 に数える（`docs/migration-v1.md`）。
- `consolidate`・`reflect` が内部で呼ぶ `recall()` にも効く。
- Postgres の実測値と突き合わせる一致テスト（活動時計）の期待値が動いた。Postgres で走らせ直した値に置き換えた。置き換える前に、core の fake・Postgres・testkit の fixture の3つの出力が完全一致することを確かめた。

## 引き受けた負債

- **段1の候補の母数が増える。**ゲートの押し下げで外れていた行も ANN の窓に入る。k' = limit × 4 の窓は変わらないので、1回の recall の費用は変わらない。ただし、窓の中を減衰しきった記憶が占めうる。下限があるので、関連が弱ければ順位で後ろに回る。
- ADR 0153 が挙げていた「掃引を呼んでいない期間にも遠ざける」は、ゲートではなく、下限つきの順位の低下で担う形に変わった。

## 採らなかった案

- **ゲートを残し、`decayFloorAt` の閾値（`DEFAULT_DECAY_THRESHOLD`）を下げる。**崖の位置が先に延びるだけである。
- **ゲートを削除する。**明示的に使う呼び出し側（減衰しきった記憶を外したい用途）が残りうる。口は残して既定だけを変える。

## これが覆るとしたら

- 実運用で、減衰しきった記憶が窓を占めて、新しい記憶が返らなくなると分かったとき。
- オーナーが「使われない記憶は既定で落とす」と決め直したとき。
