# ADR 0113: コミット・PR に帰属トレーラ（`Co-Authored-By:` / `🤖 Generated with`）を付けない

- **状態**: 採用 (2026-09)

- **文脈**:

  Claude Code などの harness は既定で、コミットメッセージの末尾に
  `Co-Authored-By: Claude <...>` を、PR 本文の末尾に
  `🤖 Generated with [Claude Code]` を付けるよう指示してくることがある。
  **これは harness 側の作法であり、このリポジトリが決めたものではない。**

  このリポジトリにはこれまで、この点について書いた場所が1つも無かった
  （`Co-Authored-By` / `Generated with` を md/yml から grep して0件）。
  姉妹プロジェクトの [alteroid](https://github.com/takecchi/alteroid) は
  `AGENTS.md` にこの規約を書いており、読めば気づける形になっている。
  mnemora 側にはその記述が無く、**harness の既定と読み比べる場所が無いまま
  非対称になっていた。**

  この非対称に気づいたクローンが、「alteroid と揃えて付けないか、mnemora では
  付けるか」をオーナー（takecchi）に諮った。**回答は逐語で「つけない」だった**
  （2026-09-15）。この ADR は、その決定を正典（`AGENTS.md`）に記録するものである。
  実装（`AGENTS.md`「## 作業のときの決まり」への追記、commit `06da77b`）は
  この ADR に先行して着地しているが、**設計判断としての記録がこの ADR である。**

- **検討した選択肢**:

  1. **alteroid と揃えて、付けない（採用）。**
     harness の既定に流されず、このリポジトリの規約を明文化して
     `AGENTS.md` に書く。alteroid と同じ形にすることで、
     両リポジトリを行き来する作業者・クローンが規約を覚え直さずに済む。
  2. **mnemora では付ける（現状維持）。**
     harness の既定に従い、`Co-Authored-By:` と `🤖 Generated with` を
     コミット・PR 双方に残す。**オーナーが明示的に「つけない」と回答した以上、
     この案は既に却下されている。**同じ提案をやり直さないことを
     `AGENTS.md` に明記した（下記「決定」参照）。
  3. **片方だけ付ける**（例: `Co-Authored-By:` はコミットの慣習として残し、
     PR 本文の `🤖 Generated with` だけ外す。あるいはその逆）。
     オーナーの回答は「つけない」であり、どちらか一方を残す形は
     回答をこちらで勝手に弱めることになる。**回答を字義通り「両方とも
     付けない」と読むほうが、後から解釈し直す余地を残さない。**
  4. **これから付ける分だけでなく、既に付いている分も履歴から削る**
     （squash や `filter-repo` で過去のトレーラを除去する）。
     決めたのは「これから付けない」であって「1本も付いていない状態が
     正しい」ではない。**履歴の書き換えは取り消せない操作であり、
     `docs/autonomy.md` §3 の「取り消せるか」の基準に照らして
     ここで決める範囲を超える。**採らない。

- **決定**:

  `AGENTS.md`「## 作業のときの決まり」に、次を明文化する（commit `06da77b`
  で既に反映済み）:

  - `Co-Authored-By:` のトレーラと `🤖 Generated with [Claude Code]` を、
    **コミットメッセージにも PR 本文にも付けない。**
  - これはオーナーの決定（2026-09-15）であり、**同じ提案をやり直さない。**
  - harness の既定と規約が食い違ったら、**規約を採る。**
  - **既に付いている分は履歴として残す。書き換えない。**
  - **規約の有無を履歴の分布から推定しない**（推定して実際に誤った実測を
    `AGENTS.md` に残してある——大文字小文字を区別する `grep` で
    「39/40 が付けない側」と報告したが、`-i` を付けて数え直すと
    `main` 162本中106本が持っており、報告した向きと逆だった）。

- **理由**:

  **オーナーの決定を正典に記録するのが目的であり、この ADR 自体が
  新しく何かを決めているわけではない。**製品・組織上の判断
  （リポジトリの慣習をどう見せるか）はオーナーの領分であり、
  `docs/autonomy.md` §3 の「ライセンス・パッケージ名・依存の追加方針の変更」
  と同種の、作業側が勝手に決めてよい範囲の外側にある。
  一度回答が出ている以上、**次に読む作業者が同じ諮り方を繰り返さないよう、
  規約として固定する**ことに意味がある。

- **結果（この決定が招くもの）**:

  - **今後のコミット・PR には帰属トレーラが付かない。**この ADR 自体の
    コミットと、これを含む PR の本文にも付けていない
    （自己適用であり、そうでなければ本末転倒になる）。
  - **既存の不整合を履歴に残す。** `origin/main`（`8367318`、163コミット、
    2026-09-15 時点で自分で数え直した実測）のうち **106本**に、既に
    `Co-authored-by:`（大文字小文字混在。`-i` 無しでは97本しか当たらない）
    ないし `Generated with [Claude Code]` が付いている
    （下の「確かめていないこと」に検算の詳細）。この決定は遡って適用
    されないため、**リポジトリの履歴は「途中から規約が変わった」形の
    まま残る。**将来 `git log` の帰属トレーラを機械的に数えて何かを
    判定するような処理を書くなら、**この非連続を前提に設計しないと誤る**
    （`AGENTS.md` 自身に、大文字小文字を区別する `grep` で向きを
    取り違えた実測が記録されている）。
  - **`AGENTS.md` を読まずに harness の既定にまかせて作業すると、
    この規約に気づかず違反しうる。**この ADR・`AGENTS.md` を読む以外に
    harness 側でこれを強制する歯（pre-commit hook 等)は、現時点では
    このリポジトリに置いていない。

- **これが覆るとしたら**:

  - **オーナーが方針を変えたとき。**例えば、複数モデル・複数エージェントが
    同じリポジトリで並行して作業する状況が増え、「どのコミットをどの
    エージェントが書いたか」を追跡する必要が製品上・運用上に生じた場合。
    そのときは新しい ADR で上書きし、この ADR は「そのときまで有効だった
    規約」として残す。
  - **法務・コンプライアンス上の要請で、AI による生成物であることの
    明示が必要になったとき。**現時点でそのような要請がある、という
    情報はこの ADR を書いた時点では持っていない（下記「確かめていないこと」）。
  - **既存の不整合（`8367318` 時点で163本中106本）を解消する必要が
    生じたとき。**ただしその対応は「今後どう書くか」ではなく
    「過去をどう扱うか」の別の判断であり、履歴の書き換えを伴うなら
    別途 ADR が要る（この ADR は「書き換えない」とだけ決めている）。

- **確かめていないこと**:

  - **オーナーの逐語回答「つけない」は、この ADR の作業者が本人から
    直接受け取ったものではない。**マネージャー経由の伝聞であり、
    出所は `AGENTS.md`（commit `06da77b`）の記述である。
    自分でオーナーとやり取りして確認したものではない。
  - **既存の不整合の割合（163本中106本）は自分で数え直した——引用ではない。**
    手元のクローンは当初 shallow clone だったため、`git fetch --unshallow
    origin main` でフル履歴を取得したうえで、次を実行した
    （【実測】2026-09-15、`origin/main` = `8367318`）:

    ```
    $ git log origin/main --oneline | wc -l
    163
    $ git log origin/main --format='%H' --grep='Co-Authored-By' | wc -l   # 大文字小文字を区別
    12
    $ git log origin/main --format='%H' -i --grep='co-authored-by' | wc -l
    98
    $ git log origin/main --format='%H' --grep='Generated with' | wc -l
    68
    $ git log origin/main --format='%H' -i --grep='co-authored-by' \
        --grep='Generated with \[Claude Code\]' | wc -l                    # どちらか
    106
    $ git log origin/main --format='%B' | grep -o 'Co-authored-by:' | wc -l  # 綴りの内訳
    97
    $ git log origin/main --format='%B' | grep -o 'Co-Authored-By:' | wc -l
    25
    ```

    自分の数字は163本中106本であり、`AGENTS.md`（commit `06da77b`、
    その時点の `origin/main` = `c3dda79`、162本）に書かれた162本中106本と
    分母が1（着地した1コミット分）違うだけで、割合の実態は変わっていない。
    **この数字はマネージャーから提示された値と一致した**が、それを見て
    合わせに行ったのではなく、上記コマンドを自分で実行した結果として
    一致している。
  - **フル履歴を取得する前（shallow clone のまま、`git log --oneline
    origin/main` が56件しか返らなかった時点）に同じコマンドを走らせると
    24件しか返らなかった。**これは母数不足によるもので、規約の有無や
    分布そのものについて何かを意味するものではない
    （`git fetch --unshallow` 後の163件が正)。
  - **harness 側の既定（コミット・PR にトレーラを付けろという指示）が、
    将来のバージョンでどう変わるかは確かめていない。**この ADR は
    現在の harness の挙動を前提にした記述である。
