# ADR 0220: OPEN な ISSUE のコメント投稿者名は、オーナーと担い手（エージェント）を見分けない — 見分けられるのは本文中の逐語の名乗りだけである

- **日付**: 2026-09-17

**⚠ 各主張の出所を分ける**（ADR 0126 / 0127 / 0128 / 0132 / 0217 の体裁を踏む）。

- **【実測】** — この作業でコマンドを打って得た。
- **【現物】** — この repo・GitHub 上のものを直接読んで確かめた。
- **【受】** — 報告として受け取り、この作業では再導出していない。出所を明記する。

## 文脈

[ADR 0217](./0217-provenance-naming-lost-in-duplication-swept-from-the-population.md) は
`docs/` 220本の母集合から、「伝聞の主張が名乗りを落として複製されていないか」を測った。
**本 ADR はその隣の問題を扱う——複製ではなく、ISSUE コメントの投稿者アイデンティティである。**
別物なので、混同しないこと。

**【受】**（出所: 上位の担い手からの報告。この作業では再導出していない）:
**作業者の1体が「`takecchi` 名義のコメントだからオーナーの決着である」を根拠に使い、
判定を1つ誤った。** 具体的にどの判定かは、この作業では引き継いでいない。

⚠ **これは実害が出ている、という報告である。** ⛔ **本 ADR はこれを事実の顔で書かない**——
上の1段落がその全部であり、それ以上の詳細（どの ISSUE・どの判定か）はこの作業では確かめていない。

測り方:

```bash

  --json number --jq '.[].number' > numbers.txt

for n in $(cat numbers.txt); do

done

jq -r '.comments[].author.login' issue-*.json | sort | uniq -c | sort -rn
```

## 帰結 — 投稿者名では見分けられない

🔴 **「`takecchi` 名義のコメントだから、それはオーナー本人の決着である」は成り立たない。**
`takecchi` は、この作業を含め、**担い手が使っているのと同じアカウントである。**
⟹ **投稿者名という1本の情報からは、オーナーと担い手を判別できない。**

**見分ける手段は、本文中の逐語の名乗りだけである。** この repo のコメントは実際に、
一人称でその区別を書き分けている——【実測、上と同じ全141コメントから
`grep -c "オーナー"`】**`takecchi` 名義のコメント139本のうち152箇所**（1コメントに
複数回出ることがある）が「オーナー」という語を含み、その多くが

- 「オーナーの判断である」
- 「オーナー判断待ち」
- 「オーナーの回答（実 API に当てるか）。逐語...」

のように、**三人称でオーナーの決定・回答を報告する形**を取っている。⟹ **投稿者欄が
`takecchi` であっても、本文が「オーナーが判断した」と三人称で報告している箇所は、
それ自体が「この投稿はオーナー本人の一人称の発言ではなく、誰か（担い手を含みうる）が
オーナーの判断を書き起こしたものだ」と読める構造を持つ。**

⟹ **決着の根拠として使えるのは、次のどちらかがコメント本文に在るときだけである**:

1. **オーナー本人であるという逐語の名乗り**（例:「オーナーの判断」「オーナーが回答した」
   ということそのものが、書き手が誰かの決定を代弁・報告している形であることを自覚して
   書かれている場合）
2. **オーナーの発言そのものの逐語引用**（例:「逐語:」に続けて引用符付きで示されている場合）

**それも無ければ、「決着していない」として扱うこと。** 投稿者が `takecchi` であることは、
決着の根拠にならない。

## 確かめていないこと

- ⛔ **CLOSED な ISSUE のコメントは数えていない。** 母集合は OPEN 43本に限る。
- ⛔ **PR のコメント・レビューコメントは数えていない。** ISSUE のコメントだけを数えた。
- ⛔ **「オーナー」という語を含む152箇所それぞれが、実際に三人称の報告なのか、
  オーナー本人が一人称的に自分の判断を「オーナーの判断」と書いているのか**は、
  1件ずつ全文を読み分けてはいない。⭐ **測ったのは語の出現数までであり、
  「本文が名乗りとして十分か」の判定は、決着を求める側がその都度、該当コメントを
  読んで下す必要がある。**
- ⛔ **上位の担い手が報告した「判定を1つ誤った」の具体的な ISSUE・PR は特定していない**
  （【受】のまま引いている）。
- ⚠ **この数字は sha に厳密には縛られない。** ADR 番号や `main` のコミット数と違い、
  ISSUE のコメントは `main` のコミット履歴とは独立に増減する——`origin/main` が同じ sha の
  ままでも、次に誰かがコメントを足せばこの数字は動く。⟹ **ここでの sha 併記は
  「いつの時点の `main` と同時に測ったか」という文脈情報であり、「この sha であれば
  この数字になる」という再現性の保証ではない。** 数字そのものの鮮度は、**測った時刻**
  （08:16〜08:18 UTC）のほうで見ること。
- ⚠ **報告されている実測【受】の数字（OPEN 43本、コメント総数140本、`takecchi` 138本、
  `the-phage-dev` 2本、2026-09-17 08:10 UTC 前後）とは、コメント総数が1件・`takecchi` 名義が
  1件ずれている**（本 ADR: 141本・139本）。差分はどのコメントかまでは特定していないが、
  上の「sha に縛られない」の通り、**2つの測定の間に ISSUE へ新しいコメントが1件増えた**
  という以上の説明を要しない差である。

## 覆るとしたら何が起きたときか

- **この repo の運用が変わり、担い手が `takecchi` とは別のアカウントで ISSUE に投稿する
  ようになれば**、投稿者名からオーナーと担い手を分けられるようになる。⛔ **この ADR は
  それを提案しない**——アカウント運用は器の運用であり、オーナーの判断である。本 ADR が
  書くのは「読む側が今の状態をどう読むか」だけである。
- **GitHub 側が投稿主体（人間 / 自動化）を区別するメタデータをコメントに付与するように
  なれば**、それも見分ける手段になりうる。今日の `gh issue view --json comments` の
  スキーマにはそのようなフィールドは無い。
- **この repo のコメント作法が変わり、オーナー本人の発言に固定の逐語マーカー
  （例: 署名）を付けるようになれば**、本文中の名乗りを探す手間が減る。今日はそういう
  マーカーは存在しない。
