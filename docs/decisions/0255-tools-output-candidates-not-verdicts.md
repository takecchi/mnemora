## 文脈

**[ADR 0223](./0223-cross-cutting-disciplines-extracted-from-the-adr-corpus.md) は、ADR 211本の母集合から「繰り返し採られているのに入口の文書に書かれていない規律」を10本抽出した。**その決定5 がこれである【現物・逐語】:

> **一般形**: **取りこぼしがゼロにならないと分かっている道具に、「これが全部です」と名乗らせない。**⟹ **判定（exit 非0）ではなく一覧として出し、取りこぼす側と余計に拾う側の実例を、出力そのものに焼く。**

**⛔ そして ADR 0223 は、成文化の場所を自分では決めなかった**【現物・逐語、「⛔ 成文化の場所 —— **未決のまま残す**」節】:

> **どこへ置くかで読者が変わる。**`AGENTS.md` は人もエージェントも読む。`docs/autonomy.md` は「オーナーに逐一確認せずに進める担い手」向けだと自ら宣言している。⟹ **決定2・3・5・9 は *道具を作る側* への規律であり、そのどちらの宛先とも一致しない。**⭐ **3本目の宛先が要るのかどうかも、この ADR は決めない。**

**その未決を [Issue #505](https://github.com/takecchi/mnemora/issues/505) が引き取り、6つの決定（2/3/5/6/9/10）を1本ずつ判断することにした。**うち決定9 は [ADR 0234](./0234-bake-no-numbers-into-tools-and-artifacts.md)（[PR #520](https://github.com/takecchi/mnemora/pull/520)）、決定2 は [ADR 0250](./0250-machines-detect-humans-confirm-and-write.md)（[PR #553](https://github.com/takecchi/mnemora/pull/553)）が既に答えている。**この ADR は、決定5 だけに答える。**

⚠ **【受】Issue #505 の判定コメントは、当初「半分だけ書かれている」を4本と誤って数え、その取り違えで決定5 が対象から落ちかけたと自ら記録している**（逐語「⛔ **この取り違えのせいで、下の 3.（決定5）が対象から落ちかけた。**⟹ **この ISSUE は6本すべてを挙げる。**」／「⚠ **本文自身が「この項が、上の数の取り違えで落ちかけたものである」と書いている。**⟹ **落ちなくてよかった。**」）。⛔ **この経緯は Issue #505 本文とコメントを読んだだけで、当事者に確認していない。**

⚠ **【受】この ADR の判断そのものは、Issue #505 のコメントに先に置かれている**（逐語「✅ **yes。5問のうちこれがいちばん素直。宛先を広げるだけで、新しい線を引かない。**」、[issuecomment-5714613359](https://github.com/takecchi/mnemora/issues/505#issuecomment-5714613359)）。⛔ **そのコメントは「クローン miku（自動化された担い手）による判定である。オーナー本人の判定ではない」と自ら名乗っている**（同コメント冒頭「**クローン miku（自動化された担い手）による判定である。** ⛔ **オーナー本人の判定ではない。**」）。**この ADR が足すのは、その判断を記録の形にすることと、下の「測ったこと」（現物への当て直し・反例探し・線の導出）である。**

⭐ **この ADR 自身も、クローン（担い手）の作業であり、オーナー本人の判断ではない**（ADR 0156 と同じ留保。上と同じ理由で、下の決定・線・反例探しの結論も、オーナーに未確認のまま記録している）。

## 決めたこと

### 決定1. `AGENTS.md`「作業のときの決まり」に「### ⚠ 名乗れないものを道具に名乗らせない — 判定ではなく候補の一覧で出す」を新設する

**書くのは2つ**: (1) 一般形（取りこぼしがゼロにならない道具に「これが全部」と名乗らせない。判定ではなく一覧にし、取りこぼす側・余計に拾う側の実例を出力へ焼く） (2) **線**。

⭐ **ADR 0223 決定5 が挙げる7本の一覧は `AGENTS.md` へ写さない。ADR 0223 を指すだけにする**（ADR 0234 決定1・ADR 0250 決定1 と同じ理由——一覧は ADR が増えれば動く。この ADR 自身の「⚠ 数を、道具と生成物に焼き込まない」への自己適用でもある）。

**同じ理由で、`AGENTS.md` の既存箇条書き（「確かめていないことは『確かめていない』と書く」）と `docs/autonomy.md` §5 の逐語も `AGENTS.md` へ複製しない。** 新設節は「同じ規律を人が書く報告について先に持っているのがこれである」と**指すだけ**にする（ADR 0250 が `docs/autonomy.md` §4.1 に対して取った形と同じ）。

### 決定2. ⭐ 線は「取りこぼしが検査の対象の中で構造的か、対象の外の宣言で足りるか」である — これを一緒に書く

**⛔ 射程だけを広げると、正しい検査まで飲み込む。**上の「測ったこと」2節で見たとおり、`check-public-api-surface.mjs`（完全一致比較）と `check-cjs-transpile-parse.mjs`（構文解析）は、**自分の検査対象の中では取りこぼしが構造的に起こらない**——宣言されている非対応範囲は検査の**外延**（意味的な破壊性の判定・他のトランスパイラの互換性）であって、対象の**中の**未検出ではない。⟹ **その宣言は ADR やソースの doc コメントで足り、毎回の実行出力に焼く義務は無い**（[ADR 0184](./0184-conformance-scope-documented-not-closed.md) の形）。

**この節が要求するのは、検査の対象そのものが機械的に確定できないとき**——[ADR 0214](./0214-release-candidates-lists-not-judges.md) の `release-candidates.mjs` の実例のとおり、「どの commit が破壊的変更か」は commit の書き方だけでは決まらない。**そのときは exit を判定に使わず、取りこぼす側・余計に拾う側の実例を出力へ焼く。**

### 🔴 この決定は、判定コメントの見立てから外れている——外れたことを明記する

**【受・逐語】Issue #505 の判定コメントは、決定5 についてこう書いていた:**

> ⟹ ⭐ **これは「宛先を広げるだけ」であり、新しい線を引かない。**

⛔ **この ADR はその一点で判定から外れている。**上の決定2 は、線（「取りこぼしが検査の対象の中で構造的か、対象の外の宣言で足りるか」）を新しく引いている。

**外れた理由**: **「新しい線を引かない」は、判定者が反例を探す前に下した見立てである。**同じ判定コメントには、5問すべてに掛かる全体条件が別に書かれている【受・逐語】:

> **射程を広げるときは、必ず「線」を一緒に書くこと。そして線が引けないなら「引けない」と名乗って書くこと。**
> 🔴 **射程を広げた規律は、線が書かれていないと「正しい運用」まで飲み込む。**

**この ADR は、判定コメント自身の指示どおり反例を1回探し**（上の「測ったこと」2節）、**`check-publish-pack.mjs` / `check-pr-adr-reference.mjs` という反例に近いものを2本見つけた。**⟹ **見立ての前提（「反例は無いだろうから線は要らない」）が崩れたので、個別項目の見立てより全体条件（「線を一緒に書くこと」）に従った。**

⚠ **これは書き手（担い手）の判断であり、判定者にもオーナー本人にも確認していない。**判定コメントの個別項目からの逸脱として、報告に明記する必要があると判断した。

## ⭐ 歯を足すか — ⛔ 足さない

**決定5 の一般形そのもの**（「exit 非0 の門が、自分の取りこぼしを出力に焼いているか」）**を機械で縛ることを検討した。**

⛔ **足さない。理由は2つ。**

1. **偽陽性率に上限を置けるとは言えない**（[ADR 0223](./0223-cross-cutting-disciplines-extracted-from-the-adr-corpus.md) 決定3「⛔ **偽陽性率に上限を置けない検査は、門にしない**」への自己適用）。上の「測ったこと」2節が示すとおり、**「取りこぼしが検査の対象の中で構造的か、対象の外の宣言で足りるか」は意味の判定であり、構文からは決まらない**——`check-public-api-surface.mjs` と `check-publish-pack.mjs` はどちらも doc コメントに「検出しない／見落とす」という語を持つが、前者は対象外の宣言、後者は対象内の取りこぼしである。この区別を機械的な文字列検査で行うと、確実に前者を誤検知する。
2. **この ADR が見つけた2本（`check-publish-pack.mjs` / `check-pr-adr-reference.mjs`）は、まだ ISSUE 化されていない**（下の「測ったこと」で `gh search issues` を打っていない——この点は「確かめていないこと」に明記する）。ADR 0234 決定4 が「個別インスタンスの ISSUE が既に4本在る」うえで歯を作らないと判断したのと違い、**この ADR にはまだ母集合すら固まっていない。**⟹ **成文化だけを済ませ、歯と個別対応は別の判断とする。**

## 引き受けた負債

- **`check-publish-pack.mjs` と `check-pr-adr-reference.mjs` は、この ADR が成文化する規律に、射程通りに読めば違反している。**⟹ **この ADR はどちらも直さない。**マネージャーへの報告に明記し、個別 ISSUE を立てるかどうかの判断を上へ渡す。

- **線（対象の中の構造的取りこぼしか、対象の外の宣言で足りるか）は、判定に読み手の知識を要する。**新しく作る道具が、自分の検査対象をどこまで狭く宣言しているかを読み解く必要がある。⟹ **この線は機械的ではない**（ADR 0250「引き受けた負債」・ADR 0234「引き受けた負債」と同型の限界）。
