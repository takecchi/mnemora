## 問い

**`docs/release-v1.md`（`v1.0.0` を出す当日に読む手順書）が、当日ほんとうに使えるか。**

🔴 **使えない箇所が2つ在った。どちらも「値が古い」のではなく、「形が腐りを生む」ものだった。**

### 1. 基準 sha の読み取りが、`CHANGELOG.md` の*書き方*に依存していた

【現物】§0.8 の手順 (a) は、逐語こうだった:

```bash
# (a) [1.0.0] 節が、どの sha を基準に書かれていると宣言しているか
git show origin/main:CHANGELOG.md | grep -n '実測' | head
```

🔴 **【実測】そのまま打つと、基準 sha を1行も拾えない。**返るのは `[0.3.0]` / `[0.2.0]` 節の
別の数字（`101` / `30` など）であり、`grep -c` で基準 sha を数えると **0** である。

**原因**: [PR #540](https://github.com/takecchi/mnemora/pull/540) が `[1.0.0]` 節の pin 行を
書き直したとき、**その行に `【実測】` を付けなかった。**
⟹ **手順が本文の書き方に依存していたので、本文の書き方が変わった瞬間に壊れた。**

⚠ **倒れる向きが悪い。**「何も返らない」なら気づけるが、**別の節の数字が返る**ので、
**それを基準 sha だと読み違える。**

### 2. 「いま出ている版」が本文に書いてあった

【現物】§0.7 の見出しは逐語「**いま出ている版は `v0.2.0` である**」だった。

🔴 **【実測】この節は書かれてから2回腐った**——`v0.3.0`（2026-09-17）と
`v0.4.0`（2026-09-18T20:36:04Z、tag が指すのは `3cf2663`）が出ている。
【実測】`npm view <pkg> dist-tags` は publish 対象6本とも **`latest: 0.4.0`** を返す。

⚠ **同じ文書の中で、要約表（§0 の `0.7` 行）だけが先に直っていた**
——そちらは既に「⛔ **版をここに書かない**」と書いてあり、**本体と食い違っていた。**

## 🔴 決定

1. ⭐ **当日の手順書は、`main` や Release が動けば変わる事実を本文に持たない。**
   ⟹ **その場で引く手順**（コマンド）と、**読み方**だけを持つ。
2. ⭐ **既に在る抽出器を、手順書が再実装しない。**
   基準 sha の読み取りは `scripts/release-candidates-lib.mjs` の
   `extractChangelogBaseSha`（`:183`）が唯一の持ち主であり、手順書は
   `node scripts/release-candidates.mjs` を打つだけにする。
3. **読み取れなかったときに黙らせない。**
   【現物】道具は逐語「**`CHANGELOG.md` から基準 sha を読み取れなかった**」と出力する
   （`scripts/release-candidates.mjs:192`）。⟹ **その出力が出たら、それ自体が §0.8 の不通過である。**
4. ⛔ **既存の記述は書き換えず、訂正は追記で積む。**
   【実測】の表や当時の記録は**残す**。⟹ **腐ったのが値なのか形なのかを、読む人が自分で見られる。**
   ⚠ **ただし「いま出ている版は `v0.2.0` である」のような*見出し*は、記録ではなく標識である。**
   ⟹ **標識が偽を主張し続けるのは当日の事故になるので、見出しだけは手順を指す形へ変えた。**
   本体の表は1行も書き換えていない。

## 根拠

**1. これは新しい規律ではなく、既存の規律をこの文書自身に当てたものである。**

【現物】`AGENTS.md`「⚠ 数を、道具と生成物に焼き込まない」が逐語で
「**`main` が動けば変わる数——件数・行番号・版・tag・sha——を、道具や生成物に写さないこと。**
⟹ **唯一の出所をその場で引くか、指すだけにする。**」と定めている
（[ADR 0234](./0234-bake-no-numbers-into-tools-and-artifacts.md)）。
⟹ **「版」は逐語でその一覧に入っている。**⛔ **当日の手順書だけが例外である理由は無い。**

**2. `grep` のパターンを直すだけでは足りない。**

⛔ **「`実測` を `範囲を数えたものである` に変える」で済ませると、次に誰かが書き方を変えたらまた壊れる。**
⭐ **抽出器へ一本化すると、壊れたときに直す場所が1つになり、そこには歯が在る**
——【現物】`scripts/__tests__/release-candidates-lib.test.mjs` が `extractChangelogBaseSha` を
**7箇所**で縛っている。⟹ **書き方が変わって抽出が壊れれば、CI が赤くなる。**

**3. 手順書から、破壊的変更の正本への線が1本も無かった。**

【実測】`grep -c 'migration-v1' docs/release-v1.md` = **0**。
⟹ **当日「何が壊れるか」を数えようとした人が、`CHANGELOG.md` を正本だと思って数える。**
⚠ **`CHANGELOG.md` の未リリース節は件数を持たない**（[#433](https://github.com/takecchi/mnemora/issues/433)）ので、
**そこを数えても答えが出ない。**⟹ 線を張った。

## 採らなかった案

**(A) §0.8 (a) の `grep` のパターンだけを直す。**
⛔ **却下。**上の根拠2。**同じ壊れ方が繰り返し起きる形を残す。**

**(B) `CHANGELOG.md` の pin 行に `【実測】` を付け直して、手順を元のまま使う。**
⛔ **却下。**⚠ **`CHANGELOG.md` は別の担い手が `v0.4.0` への追随で触っている最中である**（この作業では触らない）。
そして**より重いのは、それが「手順書のために本文の書き方を縛る」形になること**である
——**依存の向きが逆**であり、次に本文を書く人がその制約を知らなければ、また壊れる。

**(C) §0.7 の版を `v0.4.0` へ書き換える。**
⛔ **却下。****3回目の腐りを仕込むだけである。**【実測】この節は既に2回腐っている。

**(D) 当日の手順書を丸ごと書き直し、記録を落として手順だけにする。**
⛔ **却下。****当時の【実測】は、腐ったのが値か形かを読む人が判定するための材料である。**
⟹ 残したうえで、訂正を隣に積んだ。

## 引き受けた負債

⚠ **1. 手順書が `scripts/release-candidates.mjs` に依存する。**
道具が壊れれば §0.8 の手順が打てなくなる。⭕ **黙って誤らない**（読み取れなければそう出力する）が、
**道具が無い状態は想定していない。**

⚠ **2. 「その場で引く」は、引く人が居ることを前提にしている。**
⛔ **この ADR は CI の歯を1つも足していない。**§0.7 / §0.8 はどちらも
**通過条件が「人間が読んで判断したこと」**のままである（§0.8 はもともとそう書かれている）。
⟹ **忘れれば通る。**これは [#433](https://github.com/takecchi/mnemora/issues/433) の方向 (B) が
埋めるべき穴であり、**そちらは `v1.0.0` の後へ繰り延べられている。**

⚠ **3. 訂正を追記で積む形は、文書を長くする。**
【実測】この変更で `docs/release-v1.md` は 1946 行から増えた。
⟹ **当日読む人は、訂正ブロックを先に読む必要がある。**⭐ そのため訂正は
**すべて対象の記述の直前または直後**に置き、**「上／下の本文は書き換えていない」と各ブロックに明記した。**

## これが覆るとしたら

- **`CHANGELOG.md` の鮮度を見る CI の歯が入ったとき**（[#433](https://github.com/takecchi/mnemora/issues/433) 方向 (B)）。
  ⟹ §0.8 は「人間が読む」から「歯が緑」へ移りうる。**そのとき負債2 が消える。**
- **`release-candidates.mjs` が廃止されたとき。**⟹ 決定2 の一本化先が消えるので、
  **抽出器の新しい持ち主を決め直す必要がある。**
- **オーナーが「当日の手順書には、その日の版を書いておいてほしい」と決めたとき。**
  ⟹ 🔴 **それは方向そのものの変更であり、クローンの判断では覆せない**（冒頭のバナー）。
