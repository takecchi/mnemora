## 決定【判断】

1. **実装は変えない。**公開の適合テストにも足さない。歯は `packages/postgres` の新しいテストファイルに置く。
2. 次の歯を足す。

| PR    | すり抜けた変異                                                           | 足した歯（置き場所）                                                                                                                                           | 変異での赤 |
| ----- | ------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------- |
| #1459 | 索引の演算子クラスを `jsonb_ops` にする・`tenant_id` との複合 GIN にする | 索引の定義が `(index_band->'digestBand')` の `jsonb_path_ops` で、`tenant_id` も `WHERE` も持たない（新規 `recalls-digest-band-index-edges.postgres.test.ts`） | 赤（各1）  |
| #1459 | 墓石の `digest` に `tombstone.content` を書く                            | `content` と `digest` を別の値にして、目次帯が `digest` の値になり、ほかのエントリは変わらない（同上）                                                         | 赤（1）    |
| #1464 | subject のカウンタの鍵を `record.subjectId` にする                       | `record.subjectId` と `advanceActivityClock.subjectId` を別の値にして、後者のカウンタだけが進む（新規 `create-recall-activity-clock-edges.postgres.test.ts`）  | 赤（1）    |
| #1464 | advance なしの分岐を `db.transaction` で包む・余計な文を足す             | advance なし（`undefined`・`false`）は、撃つ文が `INSERT INTO recalls` の1本だけ（同上）                                                                       | 赤（各2）  |

3. **歯を足さないもの**

| PR    | 変異                               | 理由                                                                     |
| ----- | ---------------------------------- | ------------------------------------------------------------------------ |
| #1459 | `index_band ? 'digestBand'` を外す | 元と同じ働き。`@>` が真なら `digestBand` は在る                          |
| #1459 | UPDATE の `tenant_id` を外す       | 名指しの外の適合テスト（`conformance.postgres` の `-t purge`）が捕まえる |

## 測ったこと【実測】

- 走らせたのは名指しのファイルだけ。Postgres は専用のもの（`C.UTF-8`）を立てた。全スイートは走らせていない。
- 足した歯は、変異を当てる前は緑。
- 変異ごとに `cp` で退避・`cp` で戻し・`cmp` で一致を確かめ、追跡ファイルに変異が残っていないことを確かめた。migration の変異は、変異ごとに新しい DB を作って流し直した。

## 引き受けた負債

- 実測（時間・`ops/s`・索引のサイズ）は走らせていない。性能の約束は、索引の形（計画・`idx_scan`・定義）と文の数でだけ縛っている。
- 全スイートを走らせていないので、別のファイルの歯が既に塞いでいる変異を取りこぼしている可能性がある。#1459 の q4 は、名指しを広げて当て直したら赤になったので、歯の対象から外した。
