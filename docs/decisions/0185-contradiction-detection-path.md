### 1. 北極星が矛盾について約束していること —— **全文はこれだけである**

**【実測】`grep -n "矛盾\|訂正\|間違い\|contested\|争" docs/north-star.md` は 2行しか返さない。**
要約せずに、その2行を逐語で引く。

**（1）「目指す姿」の項目5**（`docs/north-star.md:32`）:

> - **間違いを正すと、古いほうが先に出てこなくなる。**

**（2）「この問いが、実際に案を落とすことの確認」の表、問い5 の行**（`docs/north-star.md:112`）:

> | 5 | 「矛盾を recall のたびに LLM に判定させる」「目次帯を LLM に要約させる」 | **落とせた**（`status` 列と集約クエリで解ける） |

**⟹ 正典が矛盾について言っているのは、「外から見てこう現れる」が1つと、
「この形では解かない」が1つ、それだけである。**

🔴 **ここから3つのことが従う。読み違えやすいので分けて書く。**

1. **正典は「mnemora が矛盾を自動で検出する」とは書いていない。**項目5 の主語は
   「間違いを正す」側であり、それが mnemora なのか採用者なのかは文面から決まらない。
   ⛔ **だから「検出が無いのは正典違反である」とは、この2行からは言えない。**
2. **正典が落としたのは「recall のたびに LLM に判定させる」である。**
   ⛔ **「LLM に判定させる」一般ではない。**【現物】Issue #197 に付いた2件目のコメントが
   同じ区別を既に指摘している（逐語: 「**北極星が問い5を落とした案とは別物である点に注意
   ——落とされたのは『recall のたびに』であり、これはバッチで1回**」）。
   ⚠ **ただし、この区別に寄りかかる案は問い5 の本文
   （「列と索引で解けるものを、モデルに問わない」）を別途通す必要がある**——
   落とされた行の外に出ることと、問いを通ることは別である。
3. **括弧の中の「`status` 列と集約クエリで解ける」は、矛盾の*提示*について言っている。**
   `status IN ('active','contested')` のゲートと段3 の同伴取得のことであり、
   **「どの2件が矛盾しているかを `status` 列から導ける」とは言っていない。**
   検出の側は、正典のこの行では解かれていない。

### 6. 🔴 これは3回目である —— **出荷される既定が、北極星と反対を向く**

⛔ **項目5 の「半分」を、個別の不足として片付けない。**同じ形が既に3回出ている。

| # | 何が | 機構は | 出荷される既定は | 結果 |
|---|---|---|---|---|
| 1 | **連想枠**（項目2「聞かれていないことを、自分から思い出す」） | 在る（`recall-runtime.ts` の段3.5） | **off**（`recall.ts` の `association?:` は optional で既定値の代入が無い） | **半分**（§7.4） |
| 2 | **矛盾の検出**（項目5「間違いを正すと、古いほうが先に出てこなくなる」） | **検出は無い**。書き込みの口だけ在る | 呼ばれない（`packages/` に呼び手0件） | **半分**（本 ADR §4） |
| 3 | **連想枠の `omitted`**（項目6「知らないことを、知らないと言える」） | — | — | 【受】**別の担い手が 2026-09-17 に見つけたと受け取った。⛔ この作業者は現物を確認していない** |

**⟹ 共通の形は「機構が無い」ではない。「機構は在るが、出荷される既定がそれを使わない」である。**

🔴 **そして、この形は #284 の規律では捕まらない。**#284 が問うのは「**それを書くコードが1行でも在るか**」であり、
**在れば通る。**⟹ `examples/chat` に1本在れば、#284 の字義では「在る」になる。
⛔ **だが `examples/chat` は `"private": true` で出荷されない**（`package.json:4`、`PUBLISH_TARGETS` 6件に不在）
⟹ **利用者には1バイトも届かない。**

**⟹ #284 は「機構が空振りしていないか」を測る歯であって、「利用者に届いているか」を測る歯ではない。**
§7.2 が要求しているのは後者である（逐語「目指す姿が*外から見て*満たされる」）。
**この2つを同じ歯で測ろうとしたことが、3回とも同じ形の誤判定を生んでいる。**

⚠ **本 ADR はこの癖を直さない。**名指しするだけである——直すなら
**「`packages/` の外に唯一の呼び手が在る」を機械的に検出する歯**が要り、
それは矛盾の設計とは別の主張である。⛔ **混ぜない。**

## 決定

### 決定1: 検出を「誰が矛盾だと決めるか」×「誰が相手を探すか」の2軸で分ける

**⛔ 「自動検出を入れるか / 入れないか」の1軸で考えない。**その形にすると、
ADR 0134 が既に落とした案（案A）を再提出するか、今日のまま何もしないかの2択になる。
**現物を読むと、独立した2つの仕事が1つに潰れている。**

| | **相手を探すのは採用側** | **相手を探すのは mnemora** |
|---|---|---|
| **矛盾だと決めるのは採用側** | **(A) 今日の姿。**採用側が2件の `MemoryId` を知っている前提で `markContested` を呼ぶ | **(C) 訂正の口。**採用側が「これは訂正である」とだけ言い、相手は mnemora が自分の recall で探す |
| **矛盾だと決めるのは mnemora** | （意味を成さない） | **(B) 主張キー。**抽出時に「何についての主張か」を構造として持たせ、同じ鍵の衝突を列と索引で見つける／**(E) LLM に矛盾判定そのものを問う** |

**⟹ (A) と (B) の間は空白ではない。(C) が在る。**
Issue #197 が挙げた3択（抽出時 / 背景処理 / 明示的操作）は**置き場所**の軸であり、
**責務の軸ではなかった**——(C) はその3択のどこにも現れない。

### 決定2: 候補の評価 —— **(C) を第1弾、(B) を第2弾、(D)(E) は落とす**

| 案 | 中身 | 費用 | 北極星 | 判定 |
|---|---|---|---|---|
| **(A) 現状維持** | 何も足さない | 0 | 問い1◯ 問い2◯ 問い3◯ 問い4◯ 問い5◯ | ⛔ **落とす。**どの問いにも触れないが、**項目5 が「半分」のまま固定される。**#197 は永久に閉じない |
| **(C) 訂正の口** | `Runtime` に「この発話は訂正である」を受ける口を足す。相手は既存の recall で探し、見つけた相手と `markContested` する。**LLM を1回も呼ばない** | 🟡 中。core に口1本 + 相手探しの配線。**抽出プロンプトを変えないのでカセットの録り直しが要らない**（後述の費用の節） | 問い1△（同伴で増えるが、解決で恒久的に減る）問い2◯（呼ばなければ今日と同じ）問い3◯（相手を選んだスコアを `explain` に出せる）問い4◯（`provenance` を触らない）問い5◯ | ⭕ **採る（第1弾）** |

3. 🔴 **戻せない**【実測】`docs/memory-model.md` §11 の lifecycle は **14行**で、`archived → active`（行14）は在るが **`superseded → active` の行は無い。**`restoreArchived` の CAS は `archived` を要求し、`resolveContested({both_active})` は**取り消しではない**（`runtime.ts:1084` 逐語「どちらも正しかった（対向ではなかったと分かった）」）。**`supersede` 後は `contestedWithId` が両側 `null` になり、適用対象も残らない。**
4. **「勝者は人が決めた」が成り立たない**——人が渡すのは「これは訂正である」だけで、**相手は mnemora が選ぶ**⟹ **相手が決まれば敗者も決まる**⟹ **誰が消えるかを選んでいるのは推論である。**

⚠ **確からしさの閾値で倒す先を分ける案も支持されなかった**——本 ADR が問い3 で落とした (D) と**同じ形**であり、**閾値が買えるのは頻度であって深刻さではない。**

##### ⭐ 検算が同時に明らかにしたこと —— **決定4 の前提は、リポジトリの不変条件ではなかった**

🔴 **「推論で利用者の述べた事実を消してはならない」は、この repo 全体の規律ではない**【実測】:

- **`Runtime.reextract`** が `MemoryStore.supersedeWithNewMemories`（ADR 0100）を呼ぶ（`runtime.ts:2052`、関数は `:1964`）
- **`Runtime.consolidate`** も `superseded` を書く（`runtime.ts:3390`）。**そして consolidate は LLM を呼ぶ**（`strategies/consolidate.ts` の `buildConsolidationPrompt`）
- **どちらも `contested` を一度も経由しない。どちらも `packages/core` の中に在る＝出荷されている。**

⟹ **mnemora は今日すでに、LLM の出力を根拠に `superseded` を書いている。**

⛔ **⟹ 決定4 は、問い4 から必然的に導かれるものではなく、(B) について置いた「方針」である。**本 ADR が決定4 を「決めた」と書いているのは**強すぎる**——この ADR の状態は「**提案**」であり、[PR #366](https://github.com/takecchi/mnemora/pull/366) は **draft・レビュー0件**である。

⭐ **では consolidate の supersede は、なぜ許されているのか。**正典の問い4 の表がその答えを持っている（`docs/north-star.md:111` 逐語）:

> | 4 | 「consolidate したら元の Memory を捨てる」 | **落とせた**（統合物は `basis` を解決できなければならない） |

⟹ **repo の実際の基準は「推論は supersede してよい。ただし結果が辿り直せること」である。**「推論は supersede してはならない」ではない。

##### 🔴 ⟹ 最小経路の判定し直し —— **要るのは「復旧口」である**

**項目5 が要求しているのは `superseded` である**（主張1。⚠ ただし精度は下の訂正を見ること）。**そして `superseded` を書けるのは、①人が勝者を渡す ②機械が書く、の2つしかない。**

- **①（人が勝者を渡す）は今日すでに出荷されている**（`markContested` / `resolveContested`）⟹ **(C) を足しても、ここは1ミリも動かない。**(C) が自動化するのは**相手探し**だけである
- **②（機械が書く）は reextract / consolidate で既に出荷されている**⟹ **技術的にも規律的にも、前例が在る**

⟹ **訂正の場合に②を使えない理由は、「推論だから」ではない。「戻せないから」である。**

**consolidate との差はここに在る:**

| | 推論で supersede するか | 消えた内容は辿れるか |
|---|---|---|
| `consolidate` | ⭕ する（LLM） | ⭕ **統合物が `basis` で元を解決できる**（正典 問い4 の表） |
| 訂正で相手を間違えた場合 | ⭕ する | 🔴 **その主張を持つものが他に無い。`omitted` に名前は出るが、`active` へ戻す口が無い** |

⟹ ⭐ **最小経路 = 「`superseded → active` の復旧口」を先に作り、そのうえで (C) を決着まで到達させる。**

**⭐ そしてこの復旧口には、項目5 と独立した根拠が在る**【実測】——**機械が駆動する状態遷移のうち、`archived` には復旧口が在る**（`Runtime.sweepArchive` が `archived` へ倒し、`Runtime.restoreArchived` が戻す。§11 行8 と行14）。**`superseded` だけが、機械が駆動するのに戻す口を持たない。**⟹ **これは項目5 の都合ではなく、既存の非対称である。**

⛔ **この ADR はそれを決めない。**復旧口を作るかはオーナーの判断であり、**測って決めることではなく、決めて作るものである。**

##### ⛔ ⟹ (C) 単独では項目5 は立たない

**検算の結論に同意する:**

> **(C) は「相手探しの自動化」であって「項目5 の充足」ではない。**(C) を入れても、項目5 を立てるには依然として明示的な決着が要る。**これは今の `examples/chat` が既にやっていること。**

⟹ **[#369](https://github.com/takecchi/mnemora/issues/369) は `contested` までで入れる。**項目5 を立てるのは**復旧口の判断**である。

##### ⚠ 数え直し（在る5 / 半分2）は、これでも生き残る

**「人が勝者を渡す形は今日すでに出荷されている ⟹ 項目5 はもう在るのでは」という読みがありうる。**⛔ **採らない。**⚠ **都合が良い読みだからこそ、根拠を書く。**

|---|---|---|

| **項目5（今日）** | 🔴 **答え**（この2件は対向する／こちらが勝つ） | 記帳（書き込みと、recall からの除外） |

##### ⚠ 精度の訂正 —— **「北極星が要求している」は1段強かった**

**上の追記は「後件『古いほうが先に出てこなくなる』が要求しているのは `superseded` である」と書いた。⛔ 要求を立てているのは正典ではない。**

## 北極星の問いに当てた結果

**上ほど強い。衝突したら上を採る**（`docs/north-star.md:55`）。

### 問1: 毎回渡す量を減らす方向に働くか。増やすなら、その分だけ想起が良くなると言えるか

**🔴 検出**（`active → contested`）**は増やす。**`contested` は段3 で対向を必ず連れてくる
（`recall-runtime.ts:908-950`）⟹ スコアだけなら選ばれない1件が強制的に足される。

**⭕ 解決**（`contested → superseded`）**は恒久的に減らす。**`superseded` は段1 の SQL の
`status IN ('active','contested')` ゲートから外れ、候補にすら上がらない
（【実測】`recall-runtime.ts:563` ANN ／ `:630` 語彙 ／ `:1123` 連想枠。⚠ **`docs/roadmap.md` §7.4 が挙げる `:474`/`:550`/`:1057` は既にずれている**——`grep` で取り直した）。

⟹ **検出単体では増える。検出と解決が対で回って初めて減る。**
⛔ **これは ADR 0134 が問1 に出した答えと同じ形であり、この ADR で変わっていない。**
**増える分の正当化**: 争われている事実を単独の顔で出すより、対向を隣接させるほうが、
下流の LLM が古い事実を信じる事故を減らす（`memory-model.md` §5 機構3）。

⚠ **「どれだけ減るか」は測っていない。**⭐門の12行に矛盾は1件も含まれていない
（`correction-scenario.ts:21-24` が `compare` から完全に隔離されている）
⟹ **今日の器では、この削減を測る場所が無い。**

### 問2: これを無効にしたとき、Memory Framework として成立するか

**⭕ 成立する。**(C) も (B) も **opt-in として設計する**（採らなかった案2）。
呼ばなければ・鍵が無ければ、**今日と全く同じ挙動が続く。**
`tick()` / `observe()` から自動で駆動しない。

🔴 **ただし、その代償が項目5 の「半分」である**（採らなかった案2 の ⚠）。
**問2 と §7.2 は、ここで正面から当たる。**
⛔ **この ADR はその衝突を解かない**——**解けるのはオーナーだけである**（既定を変えるか、
項目5 の読みを確定するか）。§7.4 が項目2 で通ったのと同じ分岐である。
🔴 **衝突そのものには決定7 で名前を付けた。**「決めない」と「解けた」を混ぜないためである。

### 問3: この記憶が選ばれた理由を、後から説明できるか

**⭕ 説明できる。これが (D) と (E) を落とす基準そのものである。**

| 案 | 「なぜ矛盾と判定したか」の説明 | 判定 |
|---|---|---|
| (C) | 「採用側が訂正だと宣言し、その発話に対する recall の1位がこれだった」+ そのスコアの内訳 | ⭕ |
| (B) | 「同じ `subjectId`・同じ主張キー・有効期間が重なる・内容が違う」 | ⭕ |
| (D) | 「コサイン類似度が閾値を超えた」 | 🔴 **数であって理由ではない** |
| (E) | （モデルの中） | 🔴 |

さらに、どの案でも `memory_events` に `kind:'updated', meta.reason:'contested'` が積まれ
