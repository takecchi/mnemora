# ADR 0259: `check-publish-pack.mjs` / `check-pr-adr-reference.mjs` の実行時出力に、doc コメントにしか無かった断りを焼く（Issue #580）

- **状態**: 採用 (2026-09-21)
- **日付**: 2026-09-21

**⚠ 各主張の出所を分ける**（ADR 0132 / 0137 / 0179 / 0199 / 0200 / 0211 / 0212 / 0234 / 0250 / 0255 の体裁を踏む）。

- **【現物】** — この repo のコード・文書を書き手が読んで確かめた。
- **【実測】** — この書き手が自分の手で `git`/`vitest`/`node` 等を走らせて確かめた。
- **【受】** — 依頼元（マネージャー）からの指示として受け取り、再導出していない箇所。

## 文脈

**[ADR 0255](./0255-tools-output-candidates-not-verdicts.md) は「取りこぼしがゼロにならないと分かっている道具に、『これが全部です』と名乗らせない。判定ではなく一覧として出し、取りこぼす側・余計に拾う側の実例を出力そのものに焼く」を `AGENTS.md` へ成文化した**（決定5）。同 ADR は成文化の作業のなかで反例を1回探し、**`scripts/check-publish-pack.mjs` と `scripts/check-pr-adr-reference.mjs` の2本を「反例に近いもの」として見つけている**【現物・ADR 0255 の逐語を確認】:

> **`check-publish-pack.mjs`**: doc コメントに「対象は固定リストである…見落としを機械的には検知できない」とある。**そしてその認めた取りこぼしは、実行時の出力（成功メッセージ）には焼かれていない**——doc コメントにしか無い。
> **`check-pr-adr-reference.mjs`**: doc コメントに「残る穴（塞いでいない）…これは検査ではなく依拠である」とある。**同じく、`violations.length === 0` のときの成功メッセージには、この穴は一言も出ていない。**

**⛔ 大事な区別**: この2本は、ADR 0255 が成文化した規律が**入る前から**在る実装である。**「規律に違反していた」という言い方はしない**——順序が逆になる。**正しい言い方は、「成文化の反例探しで見つかった、断りの置き場所が読む人の目に入る側でない2本」**である。doc コメント（ソースを開いた人だけが読む）に断りは既に在った。**無かったのは、CI のログだけを見る人・grep する人にも同じ断りが届く経路である。**

**ADR 0255 はこの2本を自分では直さず、「引き受けた負債」に送った**【現物・逐語】:

> `check-publish-pack.mjs` と `check-pr-adr-reference.mjs` は、この ADR が成文化する規律に、射程通りに読めば違反している。⟹ この ADR はどちらも直さない。マネージャーへの報告に明記し、個別 ISSUE を立てるかどうかの判断を上へ渡す。

**その負債を [Issue #580](https://github.com/takecchi/mnemora/issues/580) が引き取った。この ADR はその1本だけに答える。**

## 測ったこと

### 1. 2本の現状を現物で確認した【現物】

- `scripts/check-publish-pack.mjs` 冒頭の doc コメントは「対象は固定リストである（動的に発見しない）…新しい publish 対象パッケージが増えたら、このリストにも手で足す必要がある——見落としを機械的には検知できない」と書いている。**この認めた取りこぼしは `PUBLISH_TARGETS`（`scripts/publish-targets.mjs`）が持つ固定リストそのものに由来し、機械的な目印で対象・非対象を分けられないことも同じコメントが書いている。**成功分岐（`✔ publish 梱包の門を通りました。`）にも失敗分岐（`✗ 違反が N 件見つかりました`）にも、この断りは出ていなかった。
- `scripts/check-pr-adr-reference.mjs` 冒頭の doc コメント「## 🔴 残る穴（塞いでいない）」は「最後の緑の push の『後』に PR タイトル・本文を編集すると、この検査は効かない…これは検査ではなく依拠である」と書いている。成功分岐（`OK: …`）には出ておらず、失敗分岐だけが「⭐ 直すのは『最後の push の前』であること。squash merge のタイトル・本文は…」という段落でこの事実の一部を説いていた——**ただし成功側には無く、失敗側の説明もマーカー行を持たず grep できない自由文だった。**

### 2. 失敗分岐を実行時に測る経路が実在するかを手で確かめた【実測】

`scripts/check-publish-pack.mjs` は `PUBLISH_TARGETS` の各要素の `dir` を `cwd` にして `pnpm pack` を spawn する。`publish-targets.mjs` を、実在しないディレクトリを指す1パッケージだけの合成版に差し替えて実行したところ:

```
$ node scripts/check-publish-pack.mjs   # 合成 publish-targets.mjs 使用
...
✗ 違反が 1 件見つかりました
  - [@mnemora/does-not-exist] pnpm pack が失敗しました（@mnemora/does-not-exist, exit null）:
```

**実測で 約40ms。**`spawnSync` が `cwd` の ENOENT で即座に失敗し（`pnpm` プロセス自体が起動しない）、`packOne()` の例外を `violations` へ積む経路が実際に速く exit 1 になることを確認した。⟹ **失敗分岐も実行時出力で測る歯を書けると判断した**（下の「決めたこと」）。

### 3. 既存の歯が、いま足そうとしている文言に依存していないことを確認した【実測】

`scripts/__tests__/check-pr-adr-reference.test.mjs` の既存10ケースを `grep` し、失敗分岐の「⭐ 直すのは『最後の push の前』であること…」段落の逐語（`squash_merge_commit_title` / `儀式の順序` 等）を assert している箇所が無いことを確認した——`expect(result.stderr).toContain("gh pr edit")` だけが「直し方:」節に依存しており、この節は残すので壊れない。⟹ **この段落を、共通マーカー行を持つ1ブロックへ書き換えても、既存の歯を壊さない。**

## 決めたこと

### 決定A. 成功（exit 0）と失敗（exit 1）の両方に断りを焼く

**成功側が本体である。**「通った＝安全」と読ませないことが目的なので、緑のときに断りが無いと、その回だけ「全部見た」という誤読を許す。失敗側にも同じ断りを出す理由は3つ:

1. `✗ 違反が N 件見つかりました` という書き方も、暗に「見つけられる違反は全部数えた」という完全性を主張している。
2. 緑のときだけ注意書きが出る形だと、読み手は「注意書きが無い＝安全」という読み方を学習してしまう。
3. 断りの置き場所が固定されていれば、CI ログを人が読まなくても `grep` で横断できる。

### 決定B. 置き場所は「判定の直後」。冒頭バナーには足さない

**1回の実行につき1ブロックだけ。**冒頭バナー（検査項目の一覧）は「これから何を見るか」の予告であり、「何を見なかったか」はその予告の後、判定が出た直後に置く方が近い。一般的なお断り文ではなく、**具体**（何を見たか・何を見ていないか・人が代わりに何をするか）を書く。

### 決定C. 2本で形は揃え、中身は文脈に合わせる

**共通マーカー行を逐語で同一にする**: `⚠ この門が見ていない範囲:`。その下に、それぞれの門固有の内容を置く。マーカー行が逐語で揃っていることは、`scripts/__tests__/gate-scope-caveat-marker.test.mjs` が2本のソースから直接抜き出して比較する歯で縛った。

### 決定D. 既存の逐語を壊さない。共有モジュールは作らない

- `check-publish-pack.mjs` の成功行 `✔ publish 梱包の門を通りました。` はそのまま残す——`docs/release-v1.md` ほか複数の ADR がこの文字列を逐語で引用している。新しい行はその**後**に足した。
- `check-pr-adr-reference.mjs` の `OK: …` 行も残し、後ろに足した。
- **`check-publish-pack.mjs` の冒頭バナーの `console.log(` は 109〜131行目に在り、`docs/release-v1.md` がその行番号でこのバナーを引用している。** ⟹ **109行目より上に1行も足していない**（import も含む）。新しい定数（`SCOPE_CAVEAT_MARKER` / `buildScopeCaveat`）は131行目の `);` より下、`violations` 配列の定義の手前に置いた。実装後に `sed -n '109,131p' scripts/check-publish-pack.mjs` を実行し、この範囲が変更前と文字単位で同一であることを確認した（下の「確かめたこと」）。
- **この制約から、2本で共有するモジュールは作らなかった。**モジュールを切り出すと `check-publish-pack.mjs` の import 行が増え、109行目より上が動く。各スクリプトにローカルな `SCOPE_CAVEAT_MARKER` 定数を持たせ、**文言の一致は歯で縛る**（決定C）ことで、行番号を動かさずに書式を揃えた。

### 決定E. 各ファイルの断りの中身

**`check-publish-pack.mjs`**: 対象が `scripts/publish-targets.mjs` の `PUBLISH_TARGETS`（固定リスト・手で保守）であること、いま見たパッケージ数と名前一覧、このリストに載っていない publish 対象には気づけないこと。**パッケージ数と名前一覧は `PUBLISH_TARGETS` から動的に組み立て、数を直書きしていない**（[ADR 0234](./0234-bake-no-numbers-into-tools-and-artifacts.md) 決定9・`AGENTS.md`「⚠ 数を、道具と生成物に焼き込まない」への自己適用）。

**`check-pr-adr-reference.mjs`**: 見たのが「この CI 実行を起こした push の時点」の PR タイトル・本文だけであること、最後の緑の push の後にタイトル・本文を編集すると検査が効かないこと（`ci.yml` の `pull_request` トリガーに `edited` を足していないため）、直してから push し直すという儀式の順序に依拠していること。**失敗分岐に既に在った同趣旨の段落（マーカー行を持たない自由文）は、重複させず、この共通マーカー行を持つ1ブロックへ書き換えて統合した**（「直し方: gh pr edit …」の指示部分は変更していない）。

## 検討して採らなかった案

| 案 | ⛔ 落とした理由 |
|---|---|
| **成功時だけに断りを出す** | 決定Aの理由(1)〜(3)に反する。「✗ 違反が N 件」自体が暗に完全性を主張しており、失敗側だけ免除する理由が無い |
| **冒頭バナーに足す** | バナーは「これから何を見るか」の予告であり、判定結果と切り離されている。判定の直後に置く方が、結果とセットで読まれる |
| **2本で共有するモジュールへ括り出す** | `check-publish-pack.mjs` の冒頭バナー（109〜131行目）が `docs/release-v1.md` に行番号で引用されており、import を1行でも増やすとその引用がずれる。共有モジュールは109行目より上に import を増やす以外の実装方法が無い |
| **既存の全ての門（exit 非0 の検査すべて）に、この形の断りを機械的な歯で足す** | [ADR 0255](./0255-tools-output-candidates-not-verdicts.md)「⭐ 歯を足すか — ⛔ 足さない」が既に検討し、退けている——「検査の対象の中で取りこぼしが構造的か、対象の外の宣言で足りるか」は意味の判定であり構文からは決まらない。偽陽性率に上限を置けない検査は門にしない（[ADR 0223](./0223-cross-cutting-disciplines-extracted-from-the-adr-corpus.md) 決定3）への自己適用として、この ADR でも機械的な横断の歯は足さない |
| **2本の出力書式を別々にする（共通マーカー行を持たせない）** | grep で横断できなくなる。ADR 0255 決定5 の一般形が求めるのは「出力そのものに焼く」ことであり、置き場所が2本でバラバラだと、次にこの形を真似る3本目の道具が書式を選び直すコストを負う |

## 引き受けた負債

- **[ADR 0255](./0255-tools-output-candidates-not-verdicts.md)「引き受けた負債」の1点目（この2本の欠落）はこの ADR で解消した。**同 ADR の残り3点（決定3/6/10 は別担当・「書けば守られるとは限らない」という留保・線が機械的でないという限界）はこの ADR の対象外のまま残る。
- **この2本以外に、同じ形（doc コメントには断りが在るが実行時出力には出ていない）の門が `scripts/` 配下に他に在るかは、全ファイルを1本ずつ通読して確かめていない。**ADR 0255 の反例探しが名指しした4本（`check-public-api-surface.mjs` / `check-pr-adr-reference.mjs` / `check-publish-pack.mjs` / `check-cjs-transpile-parse.mjs`）のうち後者2本は「対象の外の宣言で足りる」側だと ADR 0255 が既に判定しており、この ADR もその判定を検算し直していない。
- **「取りこぼしが検査の対象の中で構造的か、対象の外の宣言で足りるか」という線（ADR 0255 決定2）は、依然として機械的ではない。**この ADR が2本の実装を直したことは、線そのものを機械で判定できるようにはしていない——次に似た穴が見つかったときも、人が読んで判断する必要がある。
- **`check-pr-adr-reference.mjs` の失敗分岐から削った旧文言**（`squash_merge_commit_title=PR_TITLE` 等、squash merge の具体的な設定値への言及）**は、共通マーカー行のブロックには含めていない。**この情報は [docs/autonomy.md](../autonomy.md) と [ADR 0211](./0211-check-pr-adr-reference-catches-abandoned-numbers-in-title-and-body.md) に既に在る（本 ADR の「測ったこと」3節で確認済み）ため重複を避けたが、CLI の出力だけを読む人がこの詳細を失うという小さな後退ではある。

## これが覆るとしたら

- **`ci.yml` の `pull_request` トリガーに `edited` を足す判断が下ったとき。**⟹ `check-pr-adr-reference.mjs` の断りは前提（`edited` を足していないこと）を失い、書き換えが要る。
- **`publish-targets.mjs` の対象を機械的に発見する目印が将来見つかったとき。**⟹ `check-publish-pack.mjs` の断りは「機械的な目印が無い」という前提を失う。
- **他の門にも同じ形の欠落が見つかり、3本目以降が同じマーカー行を使い始めたとき。**⟹ 「2本で共有モジュールを作らない」という決定D の理由（109〜131行目の引用保護）は3本目には当てはまらない可能性があり、そのときは共有モジュール化を検討し直す価値がある。

## 確かめたこと

- **【実測】`ls docs/decisions/ | sort` の最大が `0257`、`node scripts/adr-renumber.mjs --next` が `0259`、`gh pr list --state open` が主張する最大の ADR 番号が `0258`（PR #573 のタイトル）であることを確認した。** 3つの答えは食い違った——単純な「最大+1」（`0258`）は、まだ `main` に着地していない open PR が既に取っている番号と衝突する。`adr-renumber.mjs --next` は open PR の主張を内部で勘定に入れたうえで `0259` を返しており、これは `gh pr list` の実測と整合する。⟹ **一番大きい数（0258 が使用中）の次である `0259` を採った。**
- **【実測】`scripts/check-publish-pack.mjs` の成功時・失敗時の両方で、実行時出力に断りが出ることを、本物の `pnpm pack` 起動（成功）と合成 `publish-targets.mjs`（失敗、約40ms）で確認した。**
- **【実測】`scripts/check-pr-adr-reference.mjs` の成功時・失敗時の両方で、実行時出力に断りが出ることを、`scripts/__tests__/check-pr-adr-reference.test.mjs` と同じ合成 git 履歴フィクスチャで確認した。**
- **【実測】`sed -n '109,131p' scripts/check-publish-pack.mjs` を変更前後で比較し、この範囲が文字単位で同一であることを確認した。**
- **【実測】5種の変異試験**（(a) 成功分岐の断りを消す (b) 失敗分岐の断りを消す（`check-publish-pack.mjs`） (c) 成功分岐の断りを消す (d) 失敗分岐の断りを消す（`check-pr-adr-reference.mjs`） (e) マーカー行の文言を片方だけ変える）**を、それぞれ `cp` で退避 → 変異 → 対象の歯だけ実行 → `cp` で復元 → `git status --porcelain` で意図した差分のみに戻ったことを確認する手順で行い、狙った歯だけが red になり、復元後に green へ戻ることを確認した**（詳細はマネージャーへの報告に記録。`git checkout` は使っていない）。
- **【実測】`pnpm exec prettier --check` と、変更した3本のテストファイル + `scripts/__tests__/adr-citation.test.mjs` + `scripts/__tests__/adr-duplicate-number.test.mjs` を対象を名指しして実行し、全て green であることを確認した。**
- **【実測】`git diff --name-only origin/main...HEAD` を `packages/` に絞って確認し、該当が無いことを確認した。**

## 確かめていないこと

- ⛔ **`scripts/` 配下の全ファイルを1本ずつ通読して、この2本以外に同型の欠落（doc コメントには断りが在るが実行時出力には無い）が在るかどうかは確かめていない。**ADR 0255 が名指しした4本だけを踏まえている。
- ⛔ **`gh search issues` で、この2本についての既存 ISSUE の有無を検索していない**（ADR 0255「確かめていないこと」と同じ限界を引き継いでいる）。Issue #580 がその個別対応そのものなので、この ADR の範囲では影響しない。
- ⛔ **この ADR の判断（決定A〜E、線の当て方）は、依頼元（マネージャー）の設計指示をそのまま実装したものであり、そこからの逸脱は無いと書き手は認識しているが、オーナー本人には確認していない。**
- ⛔ **`check-pr-adr-reference.mjs` の失敗分岐から削った squash merge の具体的な設定値への言及が、CLI の出力だけを読む運用者にとって実際に不便かどうかは、運用実績で確かめていない。**
