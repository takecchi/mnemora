# ADR 0348: 抽出の出力言語・話者取り違えの指示は `subjectCandidates` 併用時にのみ足す — デフォルト経路はオーナー判断待ち

- **状態**: 提案 (2026-09-29)
- **日付**: 2026-09-29

**⚠ この ADR を書いたのは、マネージャーから [Issue #1370](https://github.com/takecchi/mnemora/issues/1370) の
残作業（CHANGELOG・ADR・変異試験・CI 確認）を切り出された担い手である。**実装本体（`packages/core/src/extraction.ts`・
`strategies/consolidate.ts`・`strategies/reflect.ts` の変更とそのテスト）は先行するセッションが書いたものを
そのまま引き継いでいる——文面・条件は変えていない（依頼元の指示）。

**⚠ 各主張の出所を分ける**（ADR 0271 の体裁を踏む）:

- **【現物】** — この repo のコード・文書を読んで確かめた。
- **【実測】** — 実際に走らせて得た。
- **【推論】** — 読解・設計判断から導いたが、実測ではない。

---

## 問い —— [Issue #1370](https://github.com/takecchi/mnemora/issues/1370)

観測が日本語なのに、抽出された記憶の `content`・`digest` の一部が英語になる。また、話者自身の
発言が、別の人物（利用者など）の発言・意見として記録される（話者の取り違え）。**この2件を
system プロンプトへの指示追加で減らせるか。**

## 決めたこと

### 決定1. `EXTRACTION_PROMPT_SYSTEM_BASE` と `extractionContext` 分岐は1バイトも変えない

【現物】`EXTRACTION_PROMPT_SYSTEM_BASE`（`packages/core/src/extraction.ts`）は
`examples/chat/cassettes/` の記録済みカセット（ADR 0051 の `llmCassetteKey`、`{system, messages}`
の sha256）と、Issue #704 評価用録音の鍵の一部になっている。ADR 0271 が同じ理由でこの定数を
1バイトも変えなかった前例に倣い、**この PR もその規律を保つ**。`extractionContext` 分岐の文面を
変えると `extraction-context*.test.ts` の録音再生テストが壊れることは、実際に一文足して確かめている
（実測: 51件が赤くなった。前セッションの記録）。

### 決定2. `subjectCandidates` を渡した呼び出しにだけ、2文（言語・話者）を足す

新しい関数 `buildLanguageAndSpeakerInstruction()` を `hasCandidates`（`subjectCandidates` が
非 `undefined` かつ非空）の分岐にだけ差し込む。`subjectCandidates` を渡す呼び出しは録音に
無いことを grep で確認済み（前セッションの記録）——**録音のキーを1本も動かさずに直せる**。

言語の一文:

> 記憶の本文（content）と要旨（digest）は、観測の本文と同じ言語で書いてください
> （subjectId や provenanceKind などの識別子はこの限りではありません）。

話者の一文:

> 観測の発言の話者（本文の先頭の話者ラベル、または speaker）自身の発言は、
> その話者についての記憶として扱い、別の人物（利用者など）の発言・意見として書かないでください。

話者の一文は、`extractionContext` を同時に渡したときに直後へ続く既存の一文「他の話者の発言を
対象話者の事実として抽出しないでください」と**向きが逆で、補い合う**（他者→対象話者の誤帰属を
止める既存の一文に対し、対象話者→他者の誤帰属を止める新しい一文）。重複も矛盾もしない
（`packages/core/src/__tests__/extraction.test.ts` の「両方を渡すと…重複・矛盾しない」テストで固定）。

### 決定3. `consolidate`・`reflect` へは無条件で言語の一文を足す

【現物】`buildConsolidationPrompt`・`buildReflectionPrompt` は録音済みカセットの鍵に使われていない
（`@mnemora/openai` の recorded 層は抽出プロンプトだけを再生対象にしている——`examples/chat` の
`compare`/`retrieval` が呼ぶのは抽出であり、統合・内省は Phase 1 の実運用経路に無い。
`docs/roadmap.md` §1.3）。⟹ 鍵を気にする理由が無いので、条件を付けずに言語の一文を足す。

### 決定4. デフォルト経路（`subjectCandidates` を渡さない呼び出し）への適用はオーナー判断待ち

**この PR は、抽出の言語・話者の指示を `subjectCandidates` を渡さない呼び出しへは広げない。**
広げれば `EXTRACTION_PROMPT_SYSTEM_BASE` 自体を変えることになり、決定1の理由がそのまま
「広げない理由」になる——録音済みカセット（約1,194件、前セッションの記録）と Issue #704 の
評価用録音がすべて動き、再録音が要る。**再録音のコストと、デフォルト経路でも同じ問題が
起きているはずだという直感を、どちらを取るかはオーナーの判断であり、この PR の裁量ではない**
（`CHANGELOG.md` `[1.1.0]` にその旨を明記した）。

**検討して採らなかった案**: **`EXTRACTION_PROMPT_SYSTEM_BASE` 自体に2文を足し、全呼び出しへ
一律に広げる案。**

- 却下した理由: 決定4のとおり、録音済みカセットと Issue #704 録音の再録音が即座に要る。
  再録音の要否・費用（実 API 呼び出し）をこの PR の裁量で決めてよいかが不明であり、
  `AGENTS.md`「オーナーの判断を待っている点」に該当すると判断した。

## 🔴 実測 —— 90発話・2 arm・3 run（合成日本語対話、`gpt-5.4-mini`）

**測定は Issue #1370 の残作業として本セッションが行った。**setup:

- 90件の合成日本語発話（架空のキャラクター「ミク」とユーザーの対話。実利用者ログは含まない）。
  payload は `{ text: "<ラベル>: <本文>", speaker }`。
- `subjectCandidates: ["user", "character"]`、`extractionContext` は渡さない。
- provider は `gpt-5.4-mini`（`@mnemora/openai`、実 API）。
- before（決定2の変更前）／after（決定2の変更後）の2 arm、それぞれ3 run。90 × 2 × 3 = 540 回の
  抽出呼び出し。

**判定方法**（生データは `analyze.mjs` 参照。この ADR には数値の写ししか置かない——鍵は
道具・生成物の側にある）:

- **英語判定**: かな・漢字（ひらがな/カタカナ/CJK統合漢字）を1文字も含まず、かつ空白を除いた
  全文字数に占めるラテン文字（a-z/A-Z）の割合が0.5以上、を「英語」とする機械的ルール。
- **話者取り違えの構造的信号**: LLM が返す候補の `subjectId` が、その観測の実際の話者
  （character/user）と逆になっているもの。キーワードに頼らず全件を機械的に数える。
- **話者取り違えのキーワード候補**: `content`/`digest` の文面に取り違えを示唆するパターン
  （`ユーザーは`/`the user (thinks|wants|...)` など）が現れるものを候補として拾い、
  `sourceText` と突き合わせて目視で確認する（副次・要目視）。

**結果**:

| 指標 | before | after | 判定 |
|---|---|---|---|
| 英語（content、Wilson 95% CI） | 1/318（0.31%、CI 上限 1.76%） | 0/296（0.00%、CI 上限 1.28%） | **CI が重なり、差は主張できない** |
| 英語（digest） | 3/316（0.95%） | 0/296（0.00%） | 同上 |
| 話者取り違え（構造的信号、character発話由来） | 46/176（26.14%、CI 20.20–33.09%） | 0/168（0.00%、CI 上限 2.24%） | **CI が重ならず、明確な差** |
| 話者取り違え（構造的信号、user→character 逆方向） | 0/142 | 0/128 | 両方0（もともと稀） |
| 話者取り違え（キーワード候補＋目視） | 4件（4件とも確認・除外0） | 0件 | after で再現せず |

**⚠ 話者取り違えの構造的信号は、候補ラベル（`subjectCandidates`）が在ることが前提の指標である。**
`subjectId` という構造化出力自体が `subjectCandidates` を渡したときにしか意味を持たないため、
**この実測は決定2の条件下（`subjectCandidates` を渡す呼び出し）でのことしか示していない。**
デフォルト経路（`subjectCandidates` を渡さない）での話者取り違えの発生率・改善効果は
**測っていない**——測る手段自体が無い（`subjectId` が返らない）。

**⚠ 英語比率の差は主張できない。**before・after とも信頼区間が重なっており、90件規模の
標本では「話者ラベルを本文の先頭に持つ発話」の英語混入率はもともと低く（before ですら
0.31–0.95%）、この一文の効果をこの標本サイズで検出するだけの検定力が無い。**この PR は
英語混入を直したと主張しない**——直したと主張できるのは話者取り違えだけである。

## 引き受けた負債

- **デフォルト経路は直っていない。**`subjectCandidates` を渡さない呼び出し（Issue 本文が
  報告した状況がこれに当たるかは未確認）では、この PR の変更は一切効かない。
- **抽出（`subjectCandidates` 併用時）・consolidate・reflect の出力文面が変わる。**
  ADR 0051 前提1と同じ実測手順（録音の再パース・鍵の再計算）は、この PR では
  `subjectCandidates` を渡す呼び出しが録音に無いことの grep 確認に留めた——録音そのものを
  対象に「変わらないこと」を確かめたのではなく、「対象の呼び出しが録音に含まれない」ことを
  確かめた。利用者には `RuntimeConfig.promptVersion` を上げることを勧める
  （`CHANGELOG.md` に明記）。
- **英語混入の改善効果は実測で主張できない。**話者取り違えほど明確な効果が無い。今回の指示が
  無害以上の効果を持つかは、今回より大きい標本か、英語混入がもっと起きやすい状況（英語混じりの
  観測など）でしか確かめられない。

## これが覆るとしたら何が起きたときか

- オーナーがデフォルト経路にも同じ指示を広げると判断し、カセット・Issue #704 録音の再録音を
  引き受けた場合。そのときは決定1・決定4を差し替える新しい ADR を書く（この ADR 本文は書き換えない）。
- より大きい標本・別のモデルでの再測定で、英語混入の指示に統計的に有意な効果が見えた場合、
  「主張できない」という上の実測結果に追記する（本文は書き換えず、追記する）。
