## 測ったこと【実測】

- 走らせたのは名指しのファイルだけ。Postgres は専用のもの（`C.UTF-8`）を立てた。全スイートは走らせていない。
- 足した歯は、変異を当てる前は緑。
- 変異ごとに `cp` で退避・`cp` で戻し・`cmp` で一致を確かめ、`git status` で src に変異が残っていないことを確かめた。

## 引き受けた負債

- 全スイートを走らせていないので、「名指しのファイルでは緑のままだが、別のファイルの歯が既に塞いでいる」変異を取りこぼしている可能性がある。#1511 の f10・#1526 の e8・#1544 の b10・b12・b13・b21 は、名指しを広げて当て直したら赤になった。その広げ方で見つけた分だけを歯の対象から外している。
- #1521 の R4・R5（recall と purge・reextract の並行の穴）は、PR が「直していない負債」として今の振る舞いを歯で縛っただけなので、実装に当てる変異が無く、確かめていない。
