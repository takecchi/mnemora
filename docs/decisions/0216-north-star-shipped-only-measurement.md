⟹ ⭐ **そしてこれは機械で測れる**——同じ入力を「何も渡さない呼び出し」と「明示的に渡した呼び出し」で2回走らせ、**差が出るか**を見ればよい。

⚠ **項目4 の ⚠ は正直に残す。**減衰そのものは出荷物だけで起きるが、`docs/north-star.md` の文面は「**使われない**記憶が」であり、**使われた記憶が在って初めて対比になる。**⟹ **機械は「減衰が既定で起きる」までしか言えない。**「対比が成立している」は言えない。

### 候補6 ⭐: 採用者が供給するものの種類 —— **配線か、データか、判定か**

**#400 の独立検算が到達した線を、そのまま物差しにする**【現物・逐語】:

> ⟹ ⭐ **(c) が耐えるには、線を1段絞る必要がある**: 「mnemora の出力を読んで作るか」ではなく、**「mnemora が原理的に持てない情報（発話・どれを実際に使ったか）か / mnemora が返すべき結論（どちらが誤りか）か」**。

| # | 採用者が供給するもの | 種類 | 判定 |
|---|---|---|---|
| 1 | 何も（`hashContent` と store の構築だけ） | **配線** | ⭕ |
| 2 | `association: { maxCount }` | **設定** ⚠ ただし**既定が文面と逆**（候補5 が拾う） | 🔴（候補5 による） |
| 3 | `getRecall(recallId)` を呼ぶこと | **配線** | ⭕ |
| 4 | `usedMemoryIds` ＝ **どれを実際に使ったか** | **mnemora が原理的に持てない情報** | ⭕ |
| 5 | `contestedPair` ＝ **どの2件が対向し、どちらが勝つか** | 🔴 **mnemora が返すべき結論** | 🔴 |
| 6 | 何も | **配線** | ⭕ |
| 7 | `budget` ＝ **どれだけ載せたいか** | **採用者にしか無い意思**（＝ 文面そのもの） | ⭕ |

⟹ ⭕ **落ちるのは項目5 だけ。**⭐ **§7.13 が「3つ目の弱点がいちばん重い」と書いたものと、同じ1点を名指ししている。**⛔ **広すぎない・狭すぎない。**

🔴 **だが、これは機械で測れない。**「原理的に持てない情報か」「返すべき結論か」は**意味の判定**であり、`grep` でも型検査でも出ない。
⟹ ⭐ **この候補は、歯にはしない。人手の監査の物差しとして文書に置く。**（決定4）

## 決めたこと

### 決定1: 🔴 物差しは1本にしない。**正典の文面の向き**で3類に割る

⛔ **7項目に同じ検査を当てない。**当てた瞬間に、証明しすぎるか何も証明しないかになる（上の候補1〜4）。

| 類 | 文面が要求しているもの | 該当 | 測り方 |
|---|---|---|---|
| **甲** | **既定で起きること** | 1・2・5・6 | 候補5（既定差分）を機械で当てる |
| **乙** | **使う側が渡せること**が充足 | 7 | 「渡すと効く」を機械で当てる。⛔ **既定の向きは当てない** |
| **丙** | **採用者が外の情報を渡す**ことを前提にする | 3・4 | ⛔ **機械に載せない。**供給物の種類（候補6）を人手で見る |

⚠ **どの項目がどの類かは、`docs/north-star.md` の文面が決める。**⛔ **実装が決めるのではない**（AGENTS.md「正典と実装が食い違ったら、バグなのは実装のほう」）。
🔴 **⟹ 類の割り当てを変えることは、正典の読みを変えることであり、オーナー専権である。**

> **⚠ 2026-09-24 追記（本文は書き換えていない。類の割り当ては動かしていない）: 項目3 を丙へ置く理由は、正典の文面「後から説明できる」の「後から」を [ADR 0161](./0161-runtime-get-recall.md) の `Runtime.getRecall`（読み戻す口）に割り当てる読みである**——候補5 の ⭕ は項目3 の書き半分（`explain` 必須欄）を、丙は読み半分（候補6 の項目3 欄）を見ている（「測ったこと」1 の項目3 行、[Issue #507](https://github.com/takecchi/mnemora/issues/507)）。⚠ この理由は当初の書き手の意図を再現したものではなく、オーナーの 2026-09-24 の指示（承認キュー経由・repo の外）で承認された推奨案として明記したものである。

### 決定2: 類甲は「**何も渡さない呼び出し**」と「**明示的に渡した呼び出し**」の**差**で測る

出荷物だけの環境で、同じ種を入れた同じ `recall()` を2回走らせ、差を印字する。

```
項目1: recall() → 記憶が返る。clock を +130日 進めて recall() → 返らない
       ⟹ 「既定で沈む」が観測できた
項目2: recall({}) と recall({ association: { maxCount: 10 } }) の差
       ⟹ 差が出る ＝ 既定 off ＝ 文面「自分から」を満たさない
項目5: observe(A) → observe(A') → recall() で A が返るか
       ⟹ 返る ＝ 既定では訂正が効かない
項目6: recall() の result.omitted が空でないか／Omission.kind の網羅は型で閉じるか
```

⭐ **項目1 の「約129.66日」は、`Clock` を注入して**その場で**測れる**（測定4）。⛔ **実時間を待つ形にしない。**

### 決定3: 類乙（項目7）には、**既定の向きを当てない**

**文面が「使う側が決められる」である以上、「既定で切り詰めない」ことが充足である。**
⟹ 測るのは **①`budget` 未指定で `budgetApplied: false` が返るか ②指定すると実際に落ちるか** の2点だけ。
⛔ **「既定で予算が入っていないから半分」とは**数えない**。**

### 決定4: ⛔ 類丙（項目3・4）と、候補6 は、**機械に載せない**

🔴 **「採用者が供給しているのは、配線か・データか・判定か」は意味の判定であり、機械で測れない。**
⟹ **人手の監査に残す。**

⭐ **代わりに置くもの**（⛔ **「置かない」と決めたときは、代わりに何を置いたかを書く**という規律に従う）:

1. **`docs/roadmap.md` §7.4 の表そのものが、その人手の監査の成果物である。**⟹ **この ADR は、その表を機械に置き換えようとしない。**
2. **probe が「出荷物の外から持ち込んだもの」を、コード上の印で明示する規律を置く。**probe の中で採用者役として書く定数に `// ADOPTER-SUPPLIED: 配線 | データ | 判定` を付け、**印の件数と種別だけを機械が集計して印字する。**⛔ **判定はしない。**⟹ 🔴 **`判定` の印が1つでも付いた項目は、その項目が「半分」である候補として人へ上がる。**
3. **この ADR の候補6 の表を、次に監査する人の物差しとして残す。**

### 決定5: 出荷物だけの環境は、**件数も一覧もハードコードしない**

- ⚠ **ただし tarball を作って install する段は、`build` ジョブに相乗りできる重さではない可能性がある。**⟹ ⭐ **2段に割る:**

⛔ **`publish.yml` と publish の経路には触らない。**段2 は別のワークフローか手動起動である。
