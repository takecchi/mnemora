# ADR 0590: 言語の事後検査の規則の境目（4字・20字・3語・直引用符の語）を、すぐ内側と外側の対で縛る（ADR 0554 の歯の穴）

- **状態**: 採用 (2026-10)
- **日付**: 2026-10-03

クローンのマネージャー（mgr-9a36f2f4）が書いた。決めたのはクローンで、オーナーではない（[ADR 0220](./0220-issue-comment-author-does-not-distinguish-owner-from-agent.md)）。
出所の区別: 【現物】は読んだコード・文書、【実測】は手元で走らせた結果、【判断】は担い手の判定。
これは試験だけの変更で、実装・CHANGELOG は触らない（[ADR 0580](./0580-adr-0568-nonexistent-id-and-event-get-controls.md) などの試験だけの PR と同じ）。

## 経緯【実測】

[ADR 0554](./0554-language-mismatch-false-positive-measured-by-replay-and-boundary-cases.md)（PR #1664）は、言語の事後検査（`packages/core/src/language-mismatch.ts`）の6条件を表にし、境目の入力を手で作って測った。ただし測定はスクリプトで、門ではない。確かめ直しで、規則の境目をずらす変異が vitest の歯をすり抜けていた（確かめ直しは前の担い手による）。

`packages/core/src/__tests__/language-mismatch.test.ts` の「閾値の定数」の歯は、定数を下限・上限で見るだけ（たとえば `LANGUAGE_MISMATCH_MIN_CONTENT_LATIN_LETTERS > 16`）で、ほかの歯の入力も境目から離れていた【現物】。そのため、定数を1つずらしても17本すべてが緑のままだった。下の変異試験で、新しい歯と既存の歯を一緒に走らせ、既存の17本が毎回緑だったことでも確かめた【実測】。

## 決定【判断】

1. 実装は変えない。
2. 歯を `packages/core/src/__tests__/language-mismatch-boundaries.test.ts`（新規、7本）に足す。**定数は import しない**——期待値は入力の文字数・語数の数字そのもので書く（定数を見ると、定数をずらした変異と一緒に動いてしまう）。どの対も、見たい条件のほかは余裕をもって満たす入力にした。
   - 条件1a（観測のかな・漢字は4字から）: `東京駅で`（4字）は印あり、`東京駅`（3字）は印なし。
   - 条件4（本文のラテン文字は20字から）: `we are going to the parks`（20字。`contentLatinLetters` が 20 であることも見る）は印あり、`we are going to the park`（19字）は印なし。
   - 条件6（小文字の語は3語から）: `Tokyo Station Meeting Room is very busy`（3語）は印あり、`… Is very busy`（2語）は印なし。
   - 条件6の `LOWERCASE_WORD` の直引用符の扱い: 語の中の ASCII の `'` は1語に数える（`Kenji Tanaka doesn't like it` は3語で印あり）。`’`（U+2019）の語（`doesn’t`）、`'` が2つある語（`rock'n'roll`）、`"` で囲んだ語（`"works fine"`）は数えない（どれも2語で印なし）。囲みを外した同じ文は印あり。

## 変異試験【実測】

`language-mismatch.ts` を `cp` で退避し、変異を Edit で1つずつ入れ、新しい歯と既存の `language-mismatch.test.ts` を名指しで走らせ、`cp` で戻して `cmp` で同一を確かめ、新しい歯を緑に戻した。

| # | 変異 | 赤になった歯（新しい7本中） | 既存の17本 | 戻して |
|---|---|---|---|---|
| M1 | 20字 → 21字 | 条件4 | 緑 | 7本緑 |
| M2 | 20字 → 19字 | 条件4 | 緑 | 7本緑 |
| M3 | 3語 → 4語 | 条件6・`doesn't` | 緑 | 7本緑 |
| M4 | 3語 → 2語 | 条件6・`’`・`rock'n'roll`・`"…"` | 緑 | 7本緑 |
| M5 | 4字 → 5字 | 条件1a | 緑 | 7本緑 |
| M6 | 4字 → 3字 | 条件1a | 緑 | 7本緑 |
| M7 | `LOWERCASE_WORD` から `(?:'[a-z]+)?` を外す | `doesn't` | 緑 | 7本緑 |
| M8 | `'` を `['’]` に広げる | `’` | 緑 | 7本緑 |
| M9 | `(?:'[a-z]+)?` を `*` にする | `rock'n'roll` | 緑 | 7本緑 |
| M10 | 語の前後の `"` を外してから `LOWERCASE_WORD` に当てる | `"…"` | 緑 | 7本緑 |

最後に戻した状態で、新旧あわせて24本が緑。

比較の演算子を変える形（`<` → `<=`）は走らせていない。定数を1つ上げる M1・M3・M5 と同じ境目の動きなので、同じ歯が赤くなるはずだが、確かめていない【判断・未確認】。

## 直さないもの

- 条件1b（観測の割合 0.3）と条件5（本文の割合 0.9）の境目は縛っていない。割合の境目は、文字数の組み合わせで「すぐ内側・外側」を作る必要があり、この ADR の依頼（4字・20字・3語・直引用符）の外である。
- 条件4の URL を除く処理、条件6の語末の記号（`[.,!?;:]?`）の境目も縛っていない。
- 閾値そのもの・規則の名前・検査の範囲は、ADR 0554 のとおりオーナーの判断待ちのまま（問24）。

## これが覆るとしたら

閾値（4字・20字・3語）を変えると決めたとき、または `LOWERCASE_WORD` を `’`・囲み語へ広げると決めたとき（ADR 0554 が材料を出している）。そのときは、この歯の対を新しい境目に合わせて作り直す。
