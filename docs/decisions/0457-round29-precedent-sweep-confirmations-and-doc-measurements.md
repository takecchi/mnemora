- **S15: 文書の「実測していない」を1つ測った——`packages/postgres/README.md` の `ANALYZE memories` が通常の読み書きをブロックしないこと**:

  【現物】README は「`ANALYZE` は PostgreSQL の公式文書によれば通常の読み書きをブロックしない……が、この副作用はこのリポジトリでは実測していない（作業環境に Postgres が無いため）」と書いていた。今は手元に PostgreSQL 17 がある（AGENTS.md の `initdb` の手順）。
  【実測】2026-10-01（PostgreSQL 17、`C.UTF-8`、`memories` に3000行を入れた。使い捨てのスクリプトで、commit していない）。2本の接続を張り、`lock_timeout` を付けて、待たされたら `55P03` になる形にした。

  | 手順                                                                                                            | 結果                                                                                         |
  | --------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
  | 接続Xで `BEGIN; ANALYZE memories;` を保持。`pg_locks` で X の `memories` のロックを見る                         | `ShareUpdateExclusiveLock` のみ（granted）                                                   |
  | X が保持している間、接続Wで `lock_timeout='1s'` のまま `INSERT`・`UPDATE`・`SELECT count(*)`                    | 3つとも成功（4ms・2ms・1ms）                                                                 |
  | 接続Yで `BEGIN; INSERT …; UPDATE …;`（未コミット）を保持。接続Zで `lock_timeout='1s'` のまま `ANALYZE memories` | 成功（36ms）                                                                                 |
  | **陽性対照**: Y が `SHARE UPDATE EXCLUSIVE` を保持している間の `ANALYZE`（`lock_timeout='500ms'`）              | `55P03 canceling statement due to lock timeout`（501ms）。探り棒は、待たされる場合を捕まえる |
  | **陽性対照**: Y が `ACCESS EXCLUSIVE` を保持している間の `INSERT`（`lock_timeout='500ms'`）                     | `55P03`（501ms）                                                                             |
  | `ANALYZE memories` の所要（3000行）                                                                             | 25ms                                                                                         |

  **直した**: README の該当の1文を、実測と「確かめていないこと」に置き換えた。確かめていないこと: 3000行より大きい表（所要時間は伸びる）、`autovacuum` との重なり、別の `ANALYZE`・`VACUUM` との重なり（`ShareUpdateExclusiveLock` どうしは待ち合うことは、対照の1本目で確かめた）。「安全側に倒れる設計」の主張は、通常の読み書きについては実測で裏づいた。
  ADR 0143 の本文は書き換えていない（README の1文が参照していた「実測していない」は、この ADR が置き換える）。
