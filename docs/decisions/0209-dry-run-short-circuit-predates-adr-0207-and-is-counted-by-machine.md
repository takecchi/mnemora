## 決定

### 1. ADR 0207 決定2 の「今回はじめて起きた」を訂正する

**短絡は 2026-09-08 の1件目の予行（`34248494960`）で、より極端な形（0/4）で既に起きていた。**
⟹ **これは「今回に固有の新しい劣化」ではなく、
「木の `version` と registry の関係で決まる、予行の構造的な性質」である。**

⛔ **崩れたのは根拠と位置づけだけであり、決定2 の運用上の結論は崩れていない。**
むしろ**強くなる**——「run の `conclusion` からは網羅率が見えない」ことの実例が、
1件ではなく**2件**在り、そのうち1件は**網羅率が 0** だった。

### 2. 「何本が経路を通ったか」を、人が読むのではなく機械に数えさせる

**ADR 0207 の「引き受けた負債」3番目が、この歯を名指しで残していた**
（**【現物】**同「引き受けた負債」3番目。逐語）:

> **⚠ 「段14 のログを1本ずつ読む」を機械が強制していない。**人が読むことに依拠している。
> ⟹ 次に予行を回す担い手が、`conclusion` だけ見て「確かめた」と書く余地は残っている。
> ⭐ **機械化するなら、段14 のログから「publish した」の件数を数えて
> `PUBLISH_TARGETS` の本数と突き合わせる歯が置ける**——この ADR では置いていない。

🔴 **その「余地」は、余地のままでは終わらなかった。**ADR 0207 自身が、
**人がログを読む経路（【受】）でこの数を取り違えている。**
⟹ ⭐ **この ADR は、0207 が設計まで書いて置かなかった歯を、そのまま置く。**

**`node scripts/check-publish-run-coverage.mjs <run id>`** が、
publish 段のログを引いて `PUBLISH_TARGETS` と突き合わせ、pass / fail を返す。

### 3. ⛔ `publish.yml` と publish 経路には一切触れない。ワークフローにも配線しない

**`v1.0.0` のリリース直前である。**出荷の経路そのものに手を入れるのは、いま取ってよい危険ではない。
⟹ **独立して走るスクリプトとして置き、`docs/release-v1.md` から「当日打つ手」として参照させる。**

### 4. この歯は、段を番号で見つけない

**同じ段が、文書によって違う番号で呼ばれていた**（**【現物】**）——
`npm publish` の段は ADR 0207 と §2.2 の追記では **段14**、`docs/release-v1.md` §1.2 の表では **12**。
前者は GitHub の step 番号（`Set up job` を1と数える）、後者は `publish.yml` に書かれた step だけを数えたものである。

⭐ **【現物】この2系統は、2026-09-17 に [PR #459](https://github.com/takecchi/mnemora/pull/459)（`d5e6e38`）が
「段N＝Actions の画面の番号（正典）／N番ステップ＝§1.2 の表の番号」という呼び分けで着地させた。**
⟹ **この ADR はその呼び分けに従う**——本文で段を指すときは名前を添える。

⛔ **だが呼び分けは、番号が腐ることそのものを止めない。**どちらの番号も、
`publish.yml` に step を1つ足した瞬間にずれる（§1.2 の表は2列とも書き直しになる）。

⟹ ⭐ **このスクリプトは段の番号を一切見ない。**job のログ全体から
`::group::npm publish <spec>` / `##[group]npm publish <spec>` を探すだけである
——**段がどこへ移動しても、番号が振り直されても、同じものを見つける。**

**⭐ 同じ理由で、この ADR は他の ADR を行番号で引かない。**測ったこと7 のとおり、
**行番号は「本文を書き換えず冒頭に追記する」というこの repo の作法そのものによって腐る。**
⟹ **節の見出しと逐語の引用で指す。**
⚠ **既に在る4箇所の行番号は、この ADR では直さない**——`docs/release-v1.md` の3箇所は
決定6 で触る節に含まれるが、**ADR 0207 決定2 の訂正とは別の欠陥である。**
⟹ **測ったこと7 に記録するにとどめ、直すのは別の PR に譲る**（`docs/autonomy.md` §2「ついでに直すをしない」）。

### 5. ADR 0207 の本文は書き換えない。前方参照だけを足す

**形**: **ADR 0207 の主張・判断・実測の記述は1行も変えない。**訂正の中身はすべてこの ADR に置き、
0207 へ足すのは冒頭の1ブロック——「後にこの ADR が決定2 の根拠を訂正した」ことを指す
**前方参照だけ**である。

**理由**: ⭐ **この形は既に規約として明文化されており、0207 自身が同じ形を 0067 に対して採っている。**
**【実測】**`git show b0e289d -- docs/decisions/0067-*.md` は **10行の追加だけ・削除0行**であり、
0067 の本文は1バイトも変わっていない。⟹ **同じ形に揃える。**
規約の出典は **【現物】**[ADR 0064](./0064-exact-path-cost-vs-scale.md) の「採らなかった案」（逐語）:

> **ADR 0063 の本文を書き換えて「約2.5倍」を直す**: 却下。**ADR は上書きせず追記して積む**
> のがこのリポジトリの作法であり（ADR 0059 → 0063 で同じ形を採った）、
> **上書きすると「当時そう判断した」という記録そのものが消える。**
> ⟹ **1行のポインタだけを足し、訂正の中身は本 ADR に置く。**
> **加えて、自分が書いた ADR を自分で書き換えるのは、いちばん歯止めが効かない形である。**

### 6. `docs/release-v1.md` §2.1 と §2.2 の両方を、追記で訂正する

**§2 はまるごと「予行で何が確かめられ、何が確かめられないか」を語る節である。**
そこに誤りを残したまま1つだけ直すと、**次に読む人が「どれが直った記述でどれが直っていないか」を
判定できない。**⟹ 同じ PR で両方に追記する（**既存の記述は消さない**）。

| 節 | 現物の記述 | なぜ誤りか |
|---|---|---|
| §2.1 | 「`workflow_dispatch` 契機の run は `34262743432`・`34248494960` の**2件だけ**」 | **【実測】**いまは3件である。⚠ **`3` へ書き直さない**——ADR 0207 の PR 自身が3件目を作って腐らせた。**その場で数える形にする** |
| §2.1 | 「**唯一の違い**は12番目のステップで `npm publish` に `--dry-run` が付くことだけ」 | ADR 0207 決定3 と矛盾する。**【実測】**段7・段8 も `skipped` であり、予行では走らない |
| §2.2 | 「6本のうち4本は、`npm publish` の経路を**1歩も通っていない**」 | 測ったこと6。**`npm publish` は6本とも起動されている** |
| §2.2 | 「2026-09-08 の予行2件では、**対象パッケージ全部が publish の経路を通っていた**」 | 測ったこと1。**1件目は 0/4 である** |
| §2.2 | 「**全14段 success**」 | 測ったこと5。**段7・段8 は `skipped`** |

## 採らなかった案

- **ADR 0207 の本文を書き換えて、誤った【受】と「今回はじめて」を直す。**⛔ 採らない——
  決定5 の理由がそのまま当たる。**当時そう判断した記録ごと消えてしまう。**
  ⚠ **そして 0207 の書き手はこの repo のオーナー本人であり、
  ADR 0064 が名指しした「自分が書いた ADR を自分で書き換える」形にいっそう近い。**
- **ADR 0207 を「棄却」に落とす。**⛔ 採らない——**決定1（予行は存在状態を読める）と
  決定3（版を決める経路は予行で走らない）は、この器で独立に裏が取れている**（下の「確かめたこと」）。
  崩れたのは決定2 の**根拠と位置づけ**であって、決定2 の運用上の結論でもない。
- **この歯を `publish.yml` の段として足し、予行が短絡したら run を赤くする。**
  ⛔ 採らない——**決定3。**`v1.0.0` の直前に出荷経路へ手を入れない。
  ⚠ **そして赤くするのは正しくない**——短絡そのものは故障ではなく、
  「その予行が何本について確かめたか」という**網羅率**の話である。
- **`docs/release-v1.md` §2.1 の「2件だけ」を「3件だけ」へ直す。**⛔ 採らない——
  **また腐る。**⟹ 数を焼き込まず、読む人がその場で `gh` に数えさせる形にする。
- **`::group::` ではなく段の番号（14）でログを切り出す。**⛔ 採らない——決定4。
- **歯を `docs/release-v1.md` の中のシェル片として置く**（§5.4 がその形）。⛔ 採らない——
  **文書の中のシェル片には歯が置けない。**このスクリプトは
  「ログの文言をどう読むか」という壊れやすい判定を持っており、そこを変異試験で測りたい。

## 引き受けた負債

- **🔴 このスクリプトは、ログの*文言*を読んでいるだけである。**
  `publish.yml` が `✔ … を publish した` / `✔ … は既に registry に在る（飛ばした）` という
  文字列を出すことに依拠している。⟹ **`publish.yml` 側の文言を変えると、
  このスクリプトは黙って「ログに無い」を返す**（`docs/autonomy.md` §4.1 の「静かに失敗する道具」の族に
  なりうる——ただし「ログに無い」は **fail** であり、pass へは倒れない）。
  ⚠ **文言の同一性を機械が検査していない。**`publish-yml-dry-run-wiring.test.mjs` と同じ形の
  「皮を入力に取る歯」を置く余地が残っている。
- **⚠ 「publish した」と出たことと、npm が実際に何をしたかは別である。**
  予行では `--dry-run` が付いているので、`+ @mnemora/x@0.1.1` は「上げた」ではなく
  「上げられるところまでは行った」である。**このスクリプトはその区別を判定しない**
  ——予行か本番かを出力に添えるだけである。
- **⚠ 短絡した本について、npm がどこまで進んだかは分からない。**
  OIDC のトークン交換を済ませてから存在検査に落ちたのか、その前に落ちたのかを
  **この器では観測していない。**⟹ **「短絡した4本は何も確かめていない」と

- **⚠ ログの保持期間を超えた run は判定できない。**GitHub は古い run のログを消す。
  ⟹ その場合スクリプトは **判定不能（exit 2）** を返す。**pass へ倒さないが、
  「昔の run を後から検算する」用途には使えない。**
