## 決定

### 決定1. 参照先を #605 へ付け替える

`README.md:264,271` / `docs/vision.md:78,85` / `docs/architecture.md:66,73` の6箇所すべてで、
`Issue #518` → `Issue #605`（Markdown リンクの表示テキストと URL の両方）を書き換えた。
⛔ 他の箇所（ADR 番号・別の Issue 参照）の `518` は一切触っていない——【実測】下記
「歯が噛むことを示した【実測】」節の diff がその証拠である。⛔ 3層の分類・文言・行構成・
段落構成は1バイトも変えていない。

### 決定2. 3文書の判断置き場ポインタの一致を、新しい歯で縛る

`scripts/__tests__/living-doc-judgment-pointer-consistency.test.mjs` を新設した。
`README.md` / `docs/vision.md` / `docs/architecture.md` の3文書が「判断の置き場」として
名指ししている Issue 番号を、2つの定型文脈（リンク形・素の形）から抽出し、3文書間で
一致していることだけを検査する。

### 決定3. 番号は literal で持たない

⭐ **理由**: 判断の置き場がどの Issue かは `main` が動けば変わる側である——現に本 PR 自体が
その番号を `#518` から `#605` へ動かしている。⟹ 歯は「518」「605」という文字列を期待値として
一度も持たず、3文書から抽出した値どうしを比較するだけである
（`AGENTS.md`「⚠ 数を、道具と生成物に焼き込まない」、[ADR 0234](./0234-bake-no-numbers-into-tools-and-artifacts.md)）。
これは [ADR 0244](./0244-runtime-method-doc-correspondence-tooth.md) 決定2・3（正典は
`packages/core/src/runtime.ts` から機械的に数え直し、テストへ写さない）と同じ規律を、
「メソッド名の集合」ではなく「判断の置き場の番号」に対して適用したものである。

### 決定4. 抽出は文書全体からの無差別な `#\d+` 走査ではなく、2つの定型文脈にだけ効かせる

現物の6箇所は、文書によらず同じ2つの定型文に載っている（【実測】
`grep -n "518" README.md docs/vision.md docs/architecture.md`）:

1. リンク形: `（[Issue #NNN](https://github.com/takecchi/mnemora/issues/NNN)）。⛔ **書き込まない口**なので、`
2. 素の形: `依然として意味の判定であり、この一覧はそれを決めていない（Issue #NNN）。`

歯はこの2つの逐語に一致する箇所からしか番号を拾わない。文書全体を無差別に検索すると、
他の ADR・Issue へのリンクに含まれる無関係な番号まで「判断の置き場」として誤って巻き込む
ためである。

## ⛔ この歯が捕まえないもの

⚠ **検査が存在することは、それが何を保証するかを何も言っていない。**⟹ **この節を消さないこと。**

1. 🔴 **3層への分類そのものは見ない。**意味の判定であり機械には決まらない
   （[ADR 0244](./0244-runtime-method-doc-correspondence-tooth.md) 決定5と同じ前提）。
2. 🔴 **番号が指す Issue が GitHub 上に実在するか・OPEN か CLOSED かは見ない。**この歯は
   ネットワークに繋がず、repo 内の3文書だけを読む。
3. 🔴 **6箇所以外の場所（他の文書・コードコメント）に同じ形のポインタが増えても、
   正規表現の文脈（2つの定型文）に一致しなければ拾わない。**定型文自体が書き換われば、
   歯は「番号が1つも取れない」側で空回り防止に引っかかって落ちる。
4. 🔴 **番号が一致してさえいれば、その番号が「正しい移管先」であるかは見ない。**
   3文書が3つとも間違った番号（例: 存在しない Issue）を同じ値で指していても、この歯は緑である。

⭐ **⟹ この歯が実際に止めるのは1つだけ**——**3文書のうち一部だけが付け替えられ、残りが
古い番号のまま `main` へ入ること。**⛔ **それ以上のことは主張しない。**

## 引き受けた負債

- **README.md / docs/vision.md / docs/architecture.md 以外の文書（各 package 配下の
  README.md 等）に同じ形の判断置き場ポインタがコピーされているかは掃いていない。**
- **この歯が縛る2つの定型文脈は、現物の6箇所の逐語に依存している。** 将来この段落の
  言い回しが変われば（例えば「⛔ **書き込まない口**なので、」という結び方をやめる）、
  正規表現は一致しなくなり、空回り防止（it 1）が先に落ちる——検出はされるが、その時点で
  歯自体の更新が必要になる。

## これが覆るとしたら何が起きたときか

- 3文書の「中核を守る3つの層」節が畳まれたとき、または上記2つの定型文脈の文言が
  変わったとき（⟹ 空回り防止（it 1）が先に落ちる）。
- 判断の置き場が Issue 以外の形（例えば ADR 番号）に変わったとき（⟹ 抽出対象の正規表現
  そのものを設計し直す必要がある）。

## 採らなかった案

### 1. Issue 番号を literal でテストへ焼き込む案

⛔ `AGENTS.md`「⚠ 数を、道具と生成物に焼き込まない」・[ADR 0234](./0234-bake-no-numbers-into-tools-and-artifacts.md) に反する。
判断の置き場は `main` が動けば変わる側であり、現に本 PR 自体がその値を動かしている。

### 2. #518 を閉じるときにコメントで書き残すだけで、文書は付け替えない案

⛔ Issue #518 最終コメントが逐語で「採らない」と決めている（「生きた文書が閉じた ISSUE を
指す状態を、一度でも作らないため」）。

### 3. 歯を3層への分類まで広げる案

⛔ [Issue #605](https://github.com/takecchi/mnemora/issues/605) が、層の割り当ての判断は
本 Issue（#605）の射程であり「オーナーの判断が出てからにすること」と明記している。
本 ADR は参照先の付け替えだけを扱い、層の分類には触れない——広げるなら別の ADR が要る。
