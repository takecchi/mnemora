# ADR 0224: 品質評価の証明範囲と合格基準の変更を、自律作業の条件にする

- **状態**: 採用 (2026-09)
- **日付**: 2026-09-17

## 文脈

オーナーは対話で、レビュー後の継続ルールを `docs/autonomy.md` に反映し、その文書を基に
AI が是正する作業を Issue 経由で指示する進め方を提案した。さらに専用ブランチと PR を指定した。
以下の具体的なルールは、その依頼に対する設計側の判断である。

現物確認（`30cce91`）では `examples/chat/src/provenance-trace.ts` は出典 ID の一致を判定し、
`compare.ts` はそれを `factStatementSurvived` として表示する。要約内容や最終回答の正誤はこの判定に含まれない。
`scripts/retrieval-quality-summary.mjs` は基準との差があっても正常終了する設計である。
出典追跡や測定の存在を、回答品質の保証へ読み替えてはいけない。

## 決定

継続して適用する正文を `docs/autonomy.md` §2.2 に置き、§2 の完了条件から参照する。
証明の範囲、振る舞いに基づく検査、独立した評価ケース、合格基準変更の別担当レビューを定める。
具体的な評価基盤と既存表示の是正は Issue で追い、この文書 PR で実装済みとは扱わない。
訂正機能は既存の #197 / #369〜#372 / PR #366 の判断と作業を再利用し、重複実装を指示しない。

## 採らなかった案

- 注意書きだけ増やす: 評価不足の修正が進まない。実装・検証の完了条件を Issue に持たせる。
- 全ベンチを直ちに厳密な閾値で落とす: ADR 0088 の揺れに関する理由を解消していない。固定可能な検査を別に用意する。
- 全変更に実 API 評価を課す: 文言修正まで外部サービスと費用に依存する。影響範囲に応じて適用する。
- すべての基準変更をオーナー承認にする: 日常の正解修正まで集中する。根拠を示した別担当レビューとし、既存のオーナー専権は維持する。

## 引き受けた負債・確かめていないこと

この変更は文書だけであり、新しい品質ゲート、未使用の評価セット、回答品質の実測はまだない。
別担当レビューを要求する規則は、この PR では branch protection によって強制していない。
レビュー前に参照した core の870テスト成功は、回答品質や実 DB の検証を意味しない。

## これが覆るとしたら

評価の実行費用や不安定性で有用な変更が止まる場合は、失敗の記録と守れなくなる保証を示して
適用範囲を見直す。出典追跡だけで回答品質まで保証できるという解釈には戻さない。
