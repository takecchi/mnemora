# ADR 0345: 文書のコード片は、印（` ```ts check `）を付けたものだけを今の公開 API で型検査し、必須の門にする

- **状態**: 採用 (2026-09)
- **日付**: 2026-09-27

> **⚠ 本文はクローン miku の委譲先が書いた。オーナー本人の執筆ではない。**
> 常設の歯として入れること・opt-in の形にすること・門（必須）にすることは、クローン miku
> （オーナーではない）が決めた。

---

## 文脈

[Issue #1053](https://github.com/takecchi/mnemora/issues/1053) で、README・`docs/*.md` の TypeScript のコード片を
今の `main` の公開 API（各パッケージの `exports` が指す `dist/*.d.ts`）に当てた。
型検査で落ちた片のうち、**本当に壊れていたのは3片**だった（素の `observe()`/`recall()` を呼ぶ README の2片、
`spec` が暗黙の any の `packages/local-embedding/README.md` の1片。PR #1054 で直した）。
**残りの赤は、どれも壊れていなかった**——動詞の一覧のような記法、`// ...省略` を含む片、
わざと空けた箇所、シグネチャの断片（`docs/migration-v1.md` の移行例の多く）、未実装の Phase の形だけの interface。

それまで、文書のコード片を公開 API に当てる歯は無かった。在ったのは
`docs/architecture.md` §5 の interface を実体と突き合わせる歯（[ADR 0269](./0269-port-interface-doc-correspondence-sweep.md)）と、
runtime のメソッド名と文書の対応を見る歯だけである。

## 決定

1. **フェンスの info string を `ts check`（または `typescript check`）にした片だけを検査する（opt-in）。**
   GitHub の描画は info string の最初の語で言語を決めるので、描画は変わらない。**印の無い片は1つも見ない。**
2. **門（必須）にする。** 理由は下の「門にしてよい理由」。
3. **片が前提にしている変数（`runtime`・`ctx` など）を補う宣言は、`scripts/check-doc-snippets-lib.mjs` の
   `DOC_SNIPPET_GLOBALS` の1か所にだけ置く。** 大域の宣言として置き、片はモジュールとして検査するので、
   片が同じ名前を自分で宣言・import すれば片の側が勝つ。**`any` では補わない**（補った変数の上では何でも通ってしまう）。
4. **全部の片を1つの Program にまとめて1回で型検査する。** 設定は `tsconfig.base.json`（strict・`noUncheckedIndexedAccess`・NodeNext）。
   片はディスクに書かず仮想ファイル（`.mts`）として渡す。解決の起点は、`packages/<name>/` の下の文書はそのパッケージ、
   それ以外（ルートの README・`docs/`）は `examples/chat`（利用者の立場で公開パッケージに依存している package）。
5. **CI の `build` ジョブ（`typecheck / lint / test / build`）の Build の後に `pnpm run check:doc-snippets` を置く。**
   別ジョブにしない（ジョブ名が required status check の文脈名そのものであるため。[ADR 0178](./0178-public-api-surface-gate.md) と同じ論拠）。
   配線は `scripts/__tests__/ci-yml-doc-snippets-wiring.test.mjs` が固定する。
6. **印の付いた片が1つも見つからなければ赤にする。** 抜き出しが壊れて何も見ていないのに緑になる形を作らない。
7. **最初に印を付けたのは、PR #1054 で型検査に通ることを確かめた片のうち、利用者が最初に読むもの**:
   ルートの README の骨格・`compareWithFullLog`・`ctx` の節・訂正の流れ (a)(b)、`packages/core`・`packages/testkit`・
   `packages/local-embedding` の README の例（`createRuntime({ // ...省略 })` を含む片を除く）、
   `docs/migration-v1.md` の移行例のうち単独で成り立つもの（4 の網羅 `switch`、6 の適合テストの呼び出し）。
   印を付けるにあたって、片を2か所直した: README の訂正の流れ (b) のわざと空けた箇所
   （`const correctedId = /* … */;`、構文として成り立たない）を、同じ README の冒頭と同じ `declare const` の形にした。
   `docs/migration-v1.md` 6 の片に、欠けていた `import` を足した。

### 重ねないもの

- `docs/architecture.md` §5 の interface には印を付けない。ADR 0269 の歯が実体との対応を見ている。
- `docs/migration-v1.md` のシグネチャの断片（1・2・3・5 の片、diff の片）には印を付けない。単独では構文として成り立たない。
  #1053 で実物の型の文脈に埋めて当て、一致していることは確かめてある（常設にはしていない）。

## 門にしてよい理由（`AGENTS.md`「⚠ 偽陽性率に上限を置けない検査は門にしない」に当てる）

`AGENTS.md` の文面は「門にしてよいのは、偽陽性率に上限を置けると実測できたものだけである」。

- **母集団が閉じている。** 見るのは印を付けた片だけであり、印は人が「この片はそのまま型検査に通るはずだ」と
  宣言して付ける。わざと省略している片は印を付けないだけで検査の外に出るので、#1053 で出た偽陽性（記法・省略・断片）は
  この門には入ってこない。
- **上限を実測した。** 【実測 2026-09-27、この枝】印を付けた片はすべて緑（偽陽性0）。
- **赤になるのは、印を付けた片が公開 API に合わなくなったときか、前提の宣言（決定3）が公開 API に合わなくなったときである。**
  どちらも文書か宣言を直すべき事象であり、偽陽性ではない。前提の宣言自体が型検査に通らなければ、
  片の結果を出す前に例外で止める（どの片のせいでもないことを、片の赤として見せない）。

⟹ **当たらないと判断した。** [ADR 0254](./0254-no-gate-without-a-false-positive-ceiling.md) が「線は引けない」とした論点
（偽陽性を承知で門にするか）には踏み込まない——この門は偽陽性を承知していない。

## 採らなかった案

- **全部の片を見て、省略している片を印で外す（opt-out）。** 外す印の書き忘れがそのまま偽陽性になり、上限が文書を書く側の注意力に依存する。
- **片ごとに Program を作り直す。** 【実測】#1053 の素朴な形では61片で約53秒かかった。1つにまとめると約2秒。
- **観測口（警告だけ）にする。** 母集団が閉じていて偽陽性の上限を置けるので、門にしない理由が無い。警告は読まれずに腐る。
- **前提の変数を片の側に書き足す。** 文書が読みにくくなり、同じ宣言が何か所にも散る。

## 引き受けた負債

- **型検査だけで、実行はしない。** 型が通っても、振る舞いが文書の説明どおりとは限らない。
- **`@mnemora/anthropic` を import する片は、ルート・`docs/` の文書に置くと解決できない**（解決の起点の `examples/chat` が依存していない）。
  `packages/anthropic/README.md` の片なら解決できる。
- **印を付けていない片は、これまでどおり誰も見ていない。** 印を付けるかどうかは文書を書く側の判断である。
- **前提の宣言（決定3）は、片が使う名前を1つの型に固定する。** 同じ名前を文書ごとに別の型で使いたくなったら、片の側で宣言すること。

## これが覆るとしたら

- 印を付けた片で、公開 API も前提の宣言も合っているのに赤になる事例が出たとき（TypeScript の版上げで診断が変わる等）。
  そのときは、偽陽性の上限が実測どおりか当て直す。
- 型検査では拾えない壊れ方（振る舞いの食い違い）が文書で繰り返し見つかり、片を実行する歯が要るとなったとき。

## 測ったこと

【実測 2026-09-27、この枝、32 コアの器】

- `pnpm run check:doc-snippets`: 印の付いた片 21件（5文書）、落ちた片 0件、約1秒。`dist` の build（約8秒）は CI の Build ステップが既に行っている。
- 陽性対照:
  - `packages/core/README.md` の片の `association: null` を `associations: null` にすると赤（`TS2561`、行番号は Markdown の中の行）、戻すと緑。
  - README の訂正の流れ (a) の `runtime.observe` を `runtime.observeX` にすると赤（`TS2551`、前提の宣言 `runtime` の型で検査されている）、戻すと緑。
  - 印の無い片（`packages/anthropic/README.md`）を壊しても、緑のまま（見ていない）。
- `scripts/__tests__/check-doc-snippets-lib.test.mjs` の変異試験: 意味の診断を捨てると4項目が赤、印の判定を緩めると1項目が赤。戻すと緑。

## 確かめていないこと

- Windows のパス区切りでの動作（CI は Linux だけ）。
